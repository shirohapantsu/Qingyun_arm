# P2 语音与云模型接入技术文档

状态：已按 2026-09-22 初审/复审修正收敛（D15、R05 涉及项）。可作为编码规格派发；前置 P0 已合入、P1 的模块桩与 AppConfig 已交付。

## 1. 目标、范围与依赖

为本期草莓 demo 提供真实语音输入和方案识别。依赖 P0 的英文 task 契约（strawberry/invalid）、P1 的 `AppConfig`、`runlog`、`terminate` 与本模块桩（异常类名与签名不可改）。录音、ASR、LLM 均在主调用线程顺序执行；PLAN 运行期间不接收或排队新任务。

供应商（D12）：ASR = **Qwen-Audio-3.1-ASR-Flash（阿里云 DashScope）**；LLM = **DeepSeek v4.1 flash**（OpenAI 兼容接口）。模型名以实际开通为准写入 app.json；JSON mode 支持、总时限可控、SDK 自动重试可关闭三项在目标机接入时实测核对，不符合即回报，不得静默降级。

非目标：语音对话、流式播报、唤醒词、语音急停、多供应商路由、蓝莓抓取。D07：用户说"分拣蓝莓"属合法语音输入，模型应输出 `invalid`（P0 已改 prompt）；模型若输出 `blueberry` 属输出违约。

- `qingyun/cloud_model.py`：替换 P1 桩。启动时加载 prompt、DeepSeek 请求组装、严格 JSON 解析、一次违约重问。
- `configs/app.example.json`：asr/llm 段 schema 见 P1 §3.1（本阶段核对注释）。
- `configs/secrets.local.json`（gitignore）：`{"dashscope_api_key": "...", "deepseek_api_key": "..."}`。
- `tests/test_asr_flow.py`、`tests/test_cloud_model.py`：假时钟、音频 fixture、HTTP 替身。
- `requirements.txt`：新增依赖（sounddevice、silero VAD 运行时、dashscope、LLM HTTP 客户端），版本在目标机验证后锁定并注释状态。

业务签名（P1 冻结，不可改）：

```python
class ASRHardError(RuntimeError): ...
class LLMHardError(RuntimeError): ...

def init(cfg: AppConfig) -> None            # 加载 VAD/设备/云配置；只允许调用一次
def listen_and_transcribe() -> str
def select_plan(text: str) -> str
```

- 不在 import 时加载模型、请求网络或打开麦克风；一切重活在 `init()`。
- `init()` 重复调用、或业务函数在 `init()` 前调用 → 抛对应 HardError（内部不变量，main 接 terminate）。
- 密钥从 `configs/secrets.local.json` 读取（P1 `load_secrets`）；日志与异常不得输出认证头或完整 key。
- **mock 说明（D15）**：独立 mock 入口**不调用** `asr.init` / `cloud_model.init`，业务函数由替身直接接管；因此 mock 场景不要求密钥、VAD 权重或麦克风存在。本模块的 init 语义无需为 mock 分支修改。

## 3. 录音状态机（asr.py）

| 状态/事件 | 行为 | 输出/下一状态 |
|---|---|---|
| WAITING，无语音 | 阻塞式按块读取音频，送 VAD，无总等待超时 | WAITING |
| WAITING，触发语音 | 记录触发时刻、建段 buffer（含约 200ms 前置缓冲） | TRIGGERED（起表 30s） |
| TRIGGERED，语音或静音 <1s | 积累；语音再现时重置连续静音计数 | TRIGGERED |
| TRIGGERED，连续静音 ≥1000ms | 结束本段，构造 WAV | ASR |
| TRIGGERED，30s 到点未形成结束 | 丢弃整段，打一行终端日志，复位 VAD/buffer | 返回空串 |
| ASR 返回空/纯空白 | 清理资源 | 返回空串 |
| 设备/重采样/VAD/云请求硬故障 | 保留来源与原因 | 抛 ASRHardError |

- 边界优先级：同一处理步同时满足"静音终点"与"30s 到点"时，先判静音终点（完整语音优先），用边界测试锁定（T02/T04 变体）。
- 每段结束/丢弃后清空音频缓冲并复位 VAD 时序状态；返回 WAITING 前排空设备输入（丢弃 PLAN 期间积压），避免旧口令误执行。
- 输入采样率/声道来自设备能力（多数免驱麦克风 44.1k/48k 立体声）；连续降混 + 带状态重采样到 **16 kHz 单声道**，禁止逐帧独立重采样。输出上传 **16 kHz mono PCM16 WAV**。
- 音频库：`sounddevice`（PortAudio）阻塞读块为建议实现；目标机不可用时换等价库，封装在私有函数，不改公开签名。
- VAD 运行时：silero，**onnxruntime 优先、torch 备选**（与视觉栈依赖解耦；目标机安装验证后锁定并回填 requirements）。帧长用模型官方推荐（16 kHz 下 512 采样），阈值按官方示例默认，不臆调。
- 30s 仅限录音；云转写受 `asr.cloud_total_timeout_s` 约束（独立时限）。

### 3.1 DashScope 适配（私有）

```python
def _transcribe(wav_bytes: bytes) -> str: ...
```

- 上传 16k mono PCM16 WAV；同步转写；模型名取 `cfg.asr.model`。
- SDK（`dashscope`）优先，arm64 wheel 不可用则走 REST；两者都封装在本函数内。
- **关闭 SDK 自动重试**（重试次数显式为 0）；连接+请求总时限 `cloud_total_timeout_s`，超时即 ASRHardError。
- **端到端 deadline（R05）**：HTTP 客户端的分项超时（如 HTTPX 的 connect/read/write/pool）不构成整次调用的墙钟上限——read 超时只约束等待下一块数据。实现必须对"连接 + 完整响应接收"施加可中止同步请求的端到端 deadline（总时长 = `cloud_total_timeout_s`），并用持续缓慢返回数据的服务替身验证（P2-T17），只用"立即返回超时异常"的 stub 不算证明。
- 网络/鉴权/限流/服务错误分类记录日志（请求标识、耗时、错误类别，脱敏），统一抛 ASRHardError。

## 4. LLM 解析与重问（cloud_model.py）

- `init()`：读 prompt.md 一次（运行期不重读）；读 key 与 `cfg.llm`；构造一次 HTTP 客户端（超时=total_timeout_s，重试 0）。
- 每次调用**新上下文**：messages = [system: prompt.md 全文, user: 转写文本]；开启 JSON mode（`response_format={"type":"json_object"}`，以 DeepSeek 实测为准）。prompt.md 已含"JSON"字样与 `{"task": ...}` 示例，满足 JSON mode 前提。
- 严格解析，合法当且仅当：响应为单个 JSON 对象、键集合恰为 `{"task"}`、task ∈ `{"strawberry", "invalid"}`。数字、旧数字字符串、布尔、`blueberry`、未知 ID、缺失/额外/重复键、代码块包装、截断输出均属**违约**（区别于网络等硬失败）。
- 第一次违约：新上下文、同一 prompt 与同一转写文本原样重发一次（不携带上次输出或纠错对话）；第二次仍违约 → 返回 `"invalid"`。
- 网络/鉴权/限流/服务异常 → 立即抛 LLMHardError，不消耗"再问一次"。
- 两次"语义请求"为上限；任何一次请求的耗时入日志。
- **计时口径（R05）**：两次语义请求**各自独立计时**（每次端到端 deadline = `total_timeout_s`，违约重问不共享首次剩余预算）；端到端 deadline 的实现要求同 §3.1。

## 5. 测试场景（无网络、无麦克风、无真实账号）

| 编号 | 场景 | 预期 |
|---|---|---|
| P2-T01 | 假时钟连续推进，输入始终静音 | 永远 WAITING，不调用 ASR |
| P2-T02 | 语音后 999ms 静音再语音 | 不结束该段 |
| P2-T03 | 语音后连续静音 1000ms | 一次完整 WAV 交转写 |
| P2-T04 | 触发后持续语音至 30s | 丢弃、空串、终端日志；零上传 |
| P2-T04b | 静音终点与 30s 同步到达 | 先按静音终点结束并上传 |
| P2-T05 | 44.1kHz 双声道 fixture | WAV 头/声道/采样率/位宽/时长正确 |
| P2-T06 | 第一响应即合法英文 task | 仅一次请求 |
| P2-T07 | 第一响应违约、第二合法 | 两次请求上下文一致；返回第二值 |
| P2-T08 | 两次均违约 | 返回 invalid，无第三次请求 |
| P2-T09 | 任一请求网络/鉴权/限流失败 | 立即 LLMHardError；无隐式重试 |
| P2-T10 | blueberry 输出、数字、重复键、额外字段、未知 ID、代码块包装 | 均按违约处理；对"分拣蓝莓"输入的正确输出是合法 invalid（prompt 行为，用替身固定） |
| P2-T11 | 模块 import | 不开设备、不请求网络、不加载权重 |
| P2-T12 | init 前调业务函数 / init 重复调用 | 抛对应 HardError |
| P2-T13 | key 缺失或全空白 | init 抛 HardError（P1 预检之外的兜底） |
| P2-T14 | ASR 返回空文本 | listen_and_transcribe 返回空串 |
| P2-T15 | 段结束后再次 WAITING | 缓冲与 VAD 状态已复位；PLAN 期间积压输入被排空 |
| P2-T16 | 云转写超时（假时钟推满 cloud_total_timeout_s） | ASRHardError；单次请求 |
| P2-T17 | 服务替身持续缓慢返回数据（每块间隔小于 read 超时、总时长超过总时限，R05） | 端到端 deadline 触发 ASRHardError/LLMHardError；证明总时限不依赖"立即超时" |

替身：HTTP 层用本地 stub 对象注入（不 monkeypatch socket）；音频用 WAV fixture + 假时钟；VAD 用固定概率序列替身。真实麦克风与真实云服务的烟雾测试独立于 pytest（P5 部署验收），普通测试不消耗账号。

## 6. 实施步骤

1. asr.py：设备枚举/阻塞读块封装（可注入音频源与时钟）→ 重采样/降混（带状态）→ VAD 状态机 → WAV 编码；单测先行（T01–T05、T12、T14–T15）。

4. requirements.txt 增补依赖并标注"目标机验证状态"；app.example.json 注释核对。
5. 全量回归：`python -m pytest tests/test_asr_flow.py tests/test_cloud_model.py -q && python -m pytest tests -q`。
