# P4 标定工具与参数发布技术文档

状态：2026-09-23 第三轮实施规格。工具可按冻结格式编码；真实数值、样本及设备证据由实测产生。前置 P0；相机工具与 P3 同步开发；抓放工具另依赖 P1 的启动握手。生产仍仅接受 verified profile。

## 1. 目标、范围与两类交付的边界

补齐草莓 demo 缺失的全部实测参数与发布流程：相机标定（内参/D2C/T_base_camera）、视觉精度验收（CAL-040/041）、分级阈值 K、A/B/C 落点、profile verified 发布。本期仅草莓（D06）。

**边界原则（强制）**：本阶段交付分为两类，文档、代码与报告不得混淆——

- **A 类：智能体可编码并离线验证的工具**——采集引导、拟合求解、验收分析、报告生成脚本，及其合成数据单元测试。
- **B 类：必须由真实设备/实测产生的证据**——标定采样、精度测量、人工定级、抓取统计。工具只负责引导与计算，不生成或替代证据；未测得的数值不得写为生产默认值（加载时拒绝未测值的原则由 P0/P3 的校验承担）。

## 2. 工具清单（A 类，全部新增于 `scripts/`）

除下列脚本外，本阶段允许修改 `configs/motion_params.py`（专用完整标定加载器）、`qingyun/grabbing/arm_control.py`/`executor.py`（只读阶段证据）、`scripts/calibrate.py`（实物记录完整性校验），以及对应测试。不得为采集降低运行阈值或放宽生产 loader。运动事件不改变 VisionInterface/GraspResult 的字段或原有失败保持行为。

### 2.1 `scripts/calibrate_camera_intrinsics.py`

- 输入：棋盘格规格（内角数×格边长 m）、采集帧目录（或 live 引导采集）。
- 功能：RGB内参及5项畸变拟合；深度内参、畸变和 depth_to_rgb 优先读取SDK并记录固件/流分辨率/是否已去畸变。无法读取时必须由对应设备的标定资料或双相机实测取得，禁止填单位矩阵/网上同型号名义值后当作实测。depth_unit_m 用已知距离物体验证，必须确认是轴向Z。
- 输出：`configs/vision/camera_intrinsics.json`（P3 §4 格式）+ 采集/拟合报告（重投影误差）。
- 输出拟合/独立验证每帧重投影误差和D2C已知目标对齐误差，1px仅为诊断提示，不自动授予生产使用资格；最终几何门槛是 CAL-040/041。每个报告含输入/输出资源哈希、分辨率、坐标系、软件版本、采样ID与 measured/simulation 来源。

### 2.2 `scripts/calibrate_camera_extrinsic.py`（R10 重写方法规格）

- 工具提供显式 `--method planar|spatial`，无自动猜测；本期两种方法均可采集，不把单块平板描述为非共面。planar 至少4个分布良好的共面点，使用 solvePnPGeneric/IPPE 枚举解，以全部点正深度和独立验证点误差选择唯一解；若两解不可区分则拒绝发布并补跨高度验证点。spatial 至少6个非共面点，solvePnP ITERATIVE；点集退化拒绝，不用4点调用默认迭代初始化。
- 输入：逐点采集记录（机械臂读反馈的 TCP 位姿 + 原始RGB图像中标记点像素）。TCP 位姿在 base 系；若观测的是指尖标记而非 TCP 本身，标记与 TCP 必须同点或给出明确刚性偏移变换。去畸变只在工具内部执行一次。
- 求解：求解器与最少点数匹配（如 OpenCV ITERATIVE 的非共面初始化要求至少 6 点；4 点须用相应 PnP 方法）；**PnP 输出通常是 world/base→camera 的变换，保存 `T_base_camera` 时必须取逆**。
- 输出：`configs/vision/T_base_camera.json` + 残差报告。
- 采样 CSV：`sample_id,split,x_base_m,y_base_m,z_base_m,u_rgb_px,v_rgb_px`，split为fit/validation；图像像素统一原始RGB，与P3保持一致。解算前用内参去畸变到像素坐标，再以同一K和零dist求解，不能重复去畸变。若有指尖标记偏移，在形成CSV时转到真实被观测点，保存刚性偏移来源。
- CLI必须提供有限正数 `--max-reprojection-error-px`，验证集各点超限或无验证集不发布输出。阈值由采样方案声明，不把默认值当物理保证；拟合误差、验证误差和所有候选解写报告，后续仍须CAL-040/041。输出方向与P3 T_base_camera对象格式一致；平面法的世界坐标如果是board，须先合成T_base_board，不能把T_camera_board直接当T_camera_base。
- 合成测试（P4-T01）覆盖：非零旋转+非零平移的真值恢复、输出矩阵忘记取逆的错误形态。

### 2.3 `scripts/validate_vision_accuracy.py`（CAL-040/041 执行器）

- 输入：样本清单（每条：物体真值中心 base 系坐标与真值 yaw，来源=TCP 示教或量具，记录测量方法）；连接已配置好的视觉模块。
- 纯视觉标定不构造motor/ArmController，也不调用生产real loader。可从draft JSON只读提取P0六个VisionThresholds字段与grasp.target_position_error_bound_m/target_yaw_error_bound_deg，逐项校验形状、有限性和bounds顺序；envelope/approach/error_bound须正，clearance/flatness非负，table_z允许有限负值，再构造；这些字段未测则拒绝，但无关运动字段未完成不阻止相机工具开发/采样。完整抓放另用§2.8.1加载器。
- 功能：精度集**每次场景只放一个已编号样本**，get_target(0) 的唯一有效检出与该编号关联；返回 valid_count!=1 或NoTarget均记样本失败，不另选更有利目标重测覆盖旧行。输出CSV含真值/测量中心、yaw、长宽、误差、拒绝原因、frame_id；每次扫描保存原始帧。混物体场景另做过滤/邻距验收，不能用get_target(0)假装已测整场全部样本。
- 判据（D09 + R10）：位置误差用**三维欧氏距离、逐样本** ≤ `min(5mm, grasp.target_position_error_bound_m)`（当前 4mm）；yaw 用**模 180° 最小角差、逐样本** ≤ 5°——两者作为运行期误差上界消费，**不验均值**。采样须覆盖 ROI 中部/边缘、多朝向、多尺寸；**验证集不得复用拟合数据**。几何中心"半高模型"（D11）随本验收一并独立验证。
- **分母口径（R10）**：验证样本与视觉检出一一对应；未检出/被过滤的样本计入分母并按失败处理，不能只统计成功返回的样本。
- **近圆样本（初审 L6 + R09）**：圆度剔除阈值在本阶段冻结（量纲建议 L/W 比值，数值由样本实测确定，不预设）；近圆样本不参与 CAL-041 的 5° 验收，且**近圆果整体不纳入本期 demo 样本集合**（R09，同步写入 P5 操作规范）。
- **真值偏差控制（R10）**：TCP 同时用于拟合与真值测量时记录参考测量不确定度，并用独立量具/已知尺寸目标交叉验证。
- 报告结论只有"通过/不通过 + 数据"，不允许"基本达到"。

新增同批足迹验证：真值矩形由独立量具/已知几何工件记录，求每个真值顶点到测量矩形的外部距离最大值，再加参考位置不确定度，作为本样本所需padding；拟合集最大需求形成建议 `footprint_padding_m`，独立验证集必须被膨胀足迹全部包含。padding只用于P3邻距，不写回运动包络、不修饰分级面积。depth_neighbor_jump_m 用原始深度点的同物体相邻距离与异物间距验证选取；无法同时保持本体连通并分离邻物时，相关场景不得宣称通过。min_points/inner_scale 和各参数、允许安装位置随报告固定，不能运行中自动调参追求通过。

`camera.max_pair_delta_s/acquire_timeout_s` 由设备采样记录回填：记录原时间戳、映射时基、偏移/不确定度、曝光新鲜度、配对差和丢帧；必须验证P3的“home后新扫描”约束。未填时live init拒绝；工具和replay可使用明确标注simulation的名义值。

### 2.4 `scripts/fit_grade_threshold.py`（K 标定，D05）

- 输入：样本 CSV（人工定级标签 A/B + 视觉实测 length_m×width_m，来自 validate 工具或专用采集模式）；每果品独立（本期草莓）。
- 功能：给出建议 K（取人工 A 组面积下界与 B 组上界之间的保守分界，边界样本归 A 验证 `area==K` → A）；输出建议值与依据报告。
- 输出：报告 + 提示回填 `qingyun/plans/strawberry.py::AREA_THRESHOLD_M2`。K 单位 m²；不成熟判 C 不受面积影响（P1 公式固定，本工具只定 K）。
- 人工定级责任在用户/视觉负责人；工具不做自动标签。

### 2.5 `scripts/calibrate_place_poses.py`（落点标定）

- 输入：示教记录（复用既有 `read_workcell_waypoint.py` 模式读反馈），或 TCP 示教 + 人工换算。
- 功能：把 TCP 释放位姿换算为物体中心 `PlacePose`（position=释放时物体中心，yaw=物体长轴角；换算用 profile 的 tool 变换与持物关系，方向与运动文档 §3.4 一致），写入 profile.json `places`：`strawberry_A_01..N`（有序，数量由托盘定）、`strawberry_B_bin`、`strawberry_C_bin`（箱口上方释放式堆放点）。
- 判据（先生成draft候选，再验证；通过前不覆盖已发布profile）：
  - 所有落点在 `target_bounds_m` **之外**（现有 `bin` 中心在 ROI 内，必须重标）；
  - A 槽位按各自yaw构造envelope水平矩形，逐对矩形净距≥collision.clearance_m，不能用未定义的“水平维+余量”标量代替二维检查；
  - B/C 箱口开度、释放高度、撤回竖直路线不碰箱壁与已堆物（损伤控制）；
  - 逐点实测一次释放验证（B/C 允许堆放重复，A 槽位独立）。
- `default`/`bin` 旧条目保留与否由实测决定，不得自动充当新 ID。

### 2.6 `scripts/record_ripe_confusion.py`

- 输入：混绿果场景样本（人工 ripe/unripe 标签 + `vision.get_target` 输出的 ripe 与图像存档）。
- 功能：输出混淆矩阵与误判率报告；**可接受比例的数值口径由用户在验收前确认**，工具只忠实统计。

### 2.7 profile 发布（复用既有 `scripts/calibrate.py promote`）

- places 增补、K 回填、相机标定包就绪、CAL-040/041 通过后，按既有 8 阶段标定与 promote 关卡把 REAL profile 从 draft 升 verified：全部运行期字段非 null、资源哈希与验收报告匹配。
- `acceptance.min_grasp_trials`（当前 30）等抓取统计字段须有真实试验记录（成功/掉落/损伤计数），依据标定记录复核，不得为赶 demo 跳过或改小。

### 2.8 `scripts/record_pick_place_trials.py`（R08 新增：抓放验收入口）

既有 `capture --hardware` 只支持 motor/joints/tool/workcell，明确拒绝 timing/motion/grasp/pick_place（要求"运行期日志导出"）；而生产 main 只加载 verified——首次 verified 所需的 pick_place 真实证据此前没有产生路径。本工具补该缺口：

- 基于 **draft 候选 profile** 驱动 ArmController 执行经审查的抓取—放置试验（动作范围由操作者确认），逐次记录：真实 profile 路径与 `parameter_sha256`、资源哈希、运行状态、软件返回（status/stage/holding/recovery_required）、独立观察的实际成功/掉落/损伤与操作者标识。
- 导出为既有 `calibrate.py validate --stage pick_place` 接受的 JSONL 格式（字段口径与标定指南 §11 一致，含 `began_descend`、`place_error_*`、`trial_summary`）；`source` 如实登记 `hardware`，**不得标成 simulation**。
- 生产加载器仍拒绝 draft——本工具是标定链的一部分，不绕过生产门槛（与"标定期间允许在 draft 上采集"的既有规则一致）。
- 先验收本工具与数据链（合成日志走通 validate），再进行真实样本试验。

#### 2.8.1 完整 draft 参数加载

新增 `configs.motion_params.load_calibration_motion_params(profile_path: Path) -> MotionParams`：仅允许draft/verified；所有运行期字段、表覆盖、限位交集、资源存在性及profile中URDF/电机校准哈希均须通过与real相同的检查。唯一豁免是“必须verified及其已完成验收报告绑定”，不豁免null/未测物理字段。保留原始status（draft仍为draft）及原始profile_dir，不改写文件或临时伪装simulation。

实现抽取现有loader的内部解析/校验共用函数，三个公开入口各自规定状态/报告门槛；不通过新增 `mode="calibration"` 暴露给生产main。既有只读 `load_calibration_profile` 保留，不能拿它的最小总线参数替代完整MotionParams。新入口是工具代码的一部分，未实现时禁止以修改status或删除生产校验替代。

抓放工具使用P1默认安全启动、cold_start_recover；不运行生产Plan的无限任务循环。一次只执行清单中一个target/place_id，操作者明确开始下一次；失败不自动恢复或直接接下一次。现场处置和恢复满足P1矩阵后才允许继续；终止不自动卸力。启动仍要求六轴原本卸力（D17）。

#### 2.8.2 下降证据：记录真实发送边界，保留原阶段

新增公开 `ArmController.get_last_motion_trace() -> tuple[MotionTraceEvent, ...]`；事件类型定义在arm_control.py，字段 `sequence:int, time_ns:int, stage:str, kind:str, outcome:str|None`。每次grasp_and_place开始清空，返回后保留到下一次调用；immutable快照；事件仅内存追加且有界（每阶段首次进入/首次下降发送/结果），不逐tick写盘、不增加线程/舵机调用。

- 在状态变更时记录 stage_enter；故障保持改写stage之前记录 failure，最终结果仍沿用原GraspResult契约。
- executor在DESCEND段首个非零下降节点的submit边界记录 descent_submit：调用驱动成功为submitted，驱动明确写前拒绝为rejected，通信异常/中断不能证明是否写入为unknown。钩子仅供运动内部维护trace，标定工具不访问 `_stage` 或替换规划器。预规划、APPROACH及下降首个非零节点前失败不会产生submitted下降事件。
- `began_descend` 来源是submitted事件（已开始下发下降指令，不冒充独立观察的物理成功）；rejected/无事件为False。unknown先记 `began_descend=null, descent_evidence="unknown"`，保留整条试验；需操作者结合现场/视频补充观察证据后定值并记录修订，不得将未知直接算False或丢弃。
- trace记录失败不得伪造下降事件；导出完整性验证拒绝无法确定分母的试验。对原运动测试增加trace开关前后运动指令/返回值不变的断言，验证模拟时钟不额外推进。

工具在调用返回后一次性导出trace，与sample通过trial_id关联。原始阶段、最终FAULT_HOLD阶段、实际成功三者分别存储。

#### 2.8.3 JSONL与发布校验

复用 `scripts.calibrate.Record/append_records` 包装；一个run第一行为metadata，之后每试验一条sample，`trial_summary`不是pick_place统计分母。以下示例是**合成格式样例**，写文件时哈希用实际64位hex，真实记录不能用占位值：

```jsonl
{"stage":"pick_place","run_id":"demo-run","sample_id":"meta-1","captured_at_ns":1,"payload":{"record_type":"metadata","source":"hardware","operator":"operator-id","profile_parameter_sha256":"<原始候选参数哈希>","profile_path":"<真实profile路径>","resource_sha256":{"urdf":"<实算哈希>","motor_calibration":"<实算哈希>"},"code_commit":"<版本>"}}
{"stage":"pick_place","run_id":"demo-run","sample_id":"sample-1","captured_at_ns":2,"payload":{"record_type":"sample","trial_id":"trial-1","profile_parameter_sha256":"<与metadata一致>","target_position_m":[0.35,0.0,0.024],"target_yaw_deg":0.0,"grade":"B","place_id":"strawberry_B_bin","start_ns":1,"end_ns":2,"software_status":"SUCCESS","software_stage":"DONE","holding":"EMPTY","recovery_required":false,"began_descend":true,"descent_evidence":"submitted","actual_success":true,"actual_drop":false,"actual_place_position_m":[0.32,0.055,0.024],"actual_place_yaw_deg":0.0,"place_error_center_m":0.0,"place_error_yaw_deg":0.0,"damage_label":"none","damage_observe_minutes":30.0,"image_refs":["trial-1.jpg"],"trace_ref":"trial-1.trace.json"}}
```

真实输入须额外由完整性校验验证，不能因为旧validate容忍缺键就省略：source精确hardware、operator非空、trial_id/sample_id唯一、全部sample参数哈希与当前candidate相同、资源哈希匹配、began_descend为bool、观察字段完整。实际成功的试验必须有实际位置/yaw与可复算误差；损伤观察时长≥acceptance.damage_observe_minutes，缺失/未到观察期记录pending，报告不能通过。began_descend未知也令报告不通过，不从分母删除。合成测试source=simulated，不能被作为physical证据。

P4须在 `calibrate.py` 的hardware pick_place分支补上述输入校验，并补实际放置yaw的P95≤acceptance.max_yaw_error_deg检查（中心误差既有P95门槛保持）。扩展仅落实指南已有字段/验收约束，不改成功率、掉落、损伤的阈值。导出器和validate都检查，避免手工JSONL绕过。标定中的位姿/损伤来自观察，不能从软件SUCCESS推定；feedback_span/stop_latency无实测时记null并引用相应timing证据，不伪填0。

CLI固定为 `record_pick_place_trials.py --profile PATH --trials CSV --output JSONL --operator NAME --vision-config PATH`；CSV至少含trial_id、sample_id、place_id、样本真值/身份及场景说明；目标从本次vision.get_target(0)取得，按单目标场景验证valid_count=1。每试验保存视觉输出、资源哈希、运动trace和人工观察。输入缺字段/未知place/未测完整参数在连接驱动前失败。

完成数据采集后顺序：完整性检查 → `calibrate.py validate --stage pick_place` → 最终候选全部八阶段报告复核/验证 → `promote` → **用load_motion_params(mode="real")实际读回验证**。promote命令返回成功不替代real loader的physical证据门槛。

## 3. 人工实测流程（B 类，执行顺序与责任）

1. 相机安装固定（眼在手外、home 不遮挡抓取 ROI）→ 内参/D2C → T_base_camera（2.1/2.2 工具引导）。
2. CAL-040/041 采样与验收（2.3）；不通过则回到 1。

### 3.1 未测值的交付规则（可编码，不伪造测量）

新增提交模板 `configs/demo_acceptance.json`，实测结果写 `configs/demo_acceptance.local.json`（gitignore）。严格schema：`{"schema_version":1,"near_round_min_ratio":null,"max_ripe_error_rate":null,"reference_position_uncertainty_m":null,"reference_yaw_uncertainty_deg":null}`。数值合法性：ratio>1，rate在[0,1]，不确定度有限非负，bool非法。`near_round_min_ratio` 定义真值L/W低于该值不属于demo集合，不增加视觉运行期圆度过滤；ratio在独立样本标定后确定。成熟度容许错误率由用户在实物验收前填写；模板null允许工具生成“不完整、不可验收”的报告，但不允许结论通过。独立模拟配置可给名义值，明确source=simulated。

样本清单与报告、vision配置、权重、K、motion profile必须在P5部署清单中绑定哈希。改相机安装/几何算法或权重须重验CAL-040/041、足迹及K，改motion yaw_offset按既有规则重新派生preopen并验证。

其他脚本最小CLI统一提供 `--input PATH --output PATH --report PATH`（纯输入输出工具）；相机采集可另加显式 `--live`，默认只读已有帧。validate_vision_accuracy额外要求 `--profile --vision-config --acceptance`；外参额外 `--intrinsics --method --max-reprojection-error-px`。报告保留输入schema、每条失败与全部样本分母。脚本import零设备副作用；所有运动脚本连接前打印本次候选/动作清单并要求操作者开始，不借生产main绕draft门槛。
