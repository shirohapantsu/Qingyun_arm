### D02 问题原文

连续抓取失败预算 N 取多少？原文同时写了 3 和 10。ignore 封顶仍优先，失败计数仅在成功抓取放置后清零。例如有 5 个合法候选，N=3 时第三次连续失败即终止，不会继续尝试剩余候选。

- 3 次：采用视觉契约中的值，连续三次失败即停止排查。
- 10 次：允许尝试更多候选；候选先跳尽时仍按原封顶规则结束。

用户决定（2026-09-22）：`选10个，希望能跳过非法项目把合法目标尽可能的抓完`。

已冻结数值为 `MAX_CONSECUTIVE_FAILURES = 10`。合法性过滤不通过的候选不送入运动；单个目标不可达、抓空等可恢复失败允许跳过，配置/通信/碰撞等原直死错误不因本决定改为忽略。预算是连续运动失败次数，不是视觉被过滤候选数量；成功抓取放置清零，NoTarget 不清零。**2026-09-22 注：本段语境中"候选先跳尽时仍按原封顶规则结束"已被 D14 修订——封顶不再是正常完成出口，而是 terminate("NO_GRASPABLE_TARGET")。**

### D03 问题原文

某个目标发生可跳过的抓取失败后，是否在本次任务内持续跳过它？当前 ignore 在其他目标成功后会归零，可能反复选中之前失败的目标。

- 本任务持续跳过：记录失败目标，其他目标成功后仍跳过；新任务清空。仍把被跳过物体纳入邻距检查。
- 保留临时跳选：其他目标成功后可重新尝试失败目标，连续失败达到 10 次终止。

本问题决定是否需要改变 `get_target(ignore)` 及相关公共契约。在回答前，不把新增目标身份、跨帧关联、排除集合或缓存机制写成已冻结实现。

用户决定（2026-09-22）：保留临时跳选，因为抓取其他目标可能改变原失败目标的状态，使其重新变得合法。因此保持 `get_target(ignore)` 与六字段目标，不增加持久目标 ID、跟踪器或永久排除列表。每次调用重新采集和过滤，成功或 NoTarget 后 ignore 归零；连续失败计数仍只在成功抓取放置后清零。

### D04 问题原文

优品抓取失败后，是否允许复用这次预留的放置槽位？原规则在分配时即消耗，即使抓空也不回退。

- 确认未放置才复用：抓空或运动前失败不消耗；已经放下或放置状态不明时仍占用，运动结果须提供明确依据。
- 保持分配即消耗：任何一次优品抓取尝试都占用一个槽位，失败也不回退；槽位耗尽终止。

仅凭 SUCCESS/失败无法判断是否已释放：放下后撤回失败也可能返回失败。因此若采用复用方案，需定义可证明的放置阶段结果，不能简单在所有失败时 a_count -= 1。

用户决定（2026-09-22）：保持分配即消耗，任何一次优品尝试均占用一个槽位，失败不回退；槽位耗尽终止。本项不增加 GraspResult 字段，也不实施放置槽位预留/提交/回滚机制。

### D05 问题原文

### D10 问题原文

用户决定（2026-09-22）：仅闭合轴上限。维持视觉契约原文：只检查闭合轴向两维 ≤ object_envelope_m 对应维，不设下限，不做高度维过滤。第三维上界由摆桌规范（单层摆放、不叠放）保证；超高目标若引发 COLLISION 按直死 terminate，该风险显式写入 P3/P5 已知风险与现场操作规范，不由视觉增加过滤维度。

**2026-09-22 复审修正（R06）**：经代码核实，运动侧碰撞模型按固定 `object_envelope_m` 建模（`safety.py::object_box`、`arm_control._target_obb/_held_obb`），且视觉不输出高度——实物超过固定包络时运动侧**未必能发现**，不能保证返回 COLLISION；位置过滤也不约束高度（中心 Z = table_z + h/2 可落在 bounds 内）。因此"运动碰撞检查兜底"的表述降级为：本期由**样本准入**承担——demo 样本实际高度 ≤ envelope[2]（当前 45mm）须经量具抽检并记录（写入 P5 操作规范），不宣称运动会为超高物体兜底。
