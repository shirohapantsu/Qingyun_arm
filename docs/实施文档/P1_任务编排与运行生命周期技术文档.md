# P1 任务编排与运行生命周期技术文档

状态：2026-09-22 第三轮实施规格修订。开始本阶段的条件是 P0 合入且运动回归通过；这不是对当前代码已完成 P0 的声明。启动准入按 D17（六轴全部卸力）执行。

范围（D06/D07）：本期只实例化草莓 Plan，使用草莓单套 motion profile。不实现 blueberry.py 或运动参数切换；蓝莓口令在 P2 按 invalid 处理。

## 1. 阶段目标与依赖

依赖 P0 的公共接口（六字段 VisionInterface + VisionThresholds）与运动回归基线。实现同线程同步的 main、plans、shutdown、runlog 和上层配置；借助不连接真实设备的替身打通任务循环。真实录音/云请求由 P2 实现，真实视觉由 P3 实现——本阶段为两者创建**契约桩**（异常类 + 函数签名，调用即抛对应硬错误），P2/P3 在原文件上替换实现，桩文件不得被重命名或移位。

已有运动控制负责单次抓取—放置及失败后的保持。P1 不在运动公开原语外拼装舵机指令，不另建线程或实时控制循环，不接 `should_stop` 回调（Ctrl-C 走 KeyboardInterrupt 现成路径）。

非目标：不实现录音/VAD/云调用（P2）、相机/检测/几何（P3）、落点与 K 的实测标定（P4）、端到端集成场景（P5）。

### 3.4 runlog.py（D13）

```python
def init(log_dir: Path) -> str     # 建 logs/run-<UTC时间戳>-<pid>.jsonl，返回 session_id
def event(kind: str, **fields) -> None   # 追加一行 JSON（自动附 ts/session_id），立即 flush
def console(msg: str) -> None            # 终端简洁输出
def context(**fields) -> ContextManager[None]  # 同步日志上下文，嵌套退出时恢复旧值
```

单线程同步，无需锁；ndarray 字段先 `tolist()`，JSON 禁止 NaN/Infinity。主循环为每个有效任务分配 session 内递增的 `task_instance_id`（不是固定字符串 strawberry）。Plan 的 `scan_id`/`attempt_id` 每任务从 0 起；每次 get_target 前递增 scan_id 并用 `runlog.context(scan_id=...)` 包住扫描、分配、抓取和恢复，P3 通过 runlog.event 自动取得 task_instance_id/scan_id。扫描 ID 不增加到 VisionInterface 或 get_target 参数。独立 P3 工具为每次扫描建立自己的上下文；单测可注入内存日志接收器。任务结束上下文在 finally 中恢复，日志关联键为 `(session_id, task_instance_id, scan_id, attempt_id)`。

日志失败抛异常并交顶层 terminate；terminate 的日志再次失败时仅向 stderr 输出，仍退出，不能递归调用自己。资源关闭只释放 HTTP/音频/相机/串口句柄，不发送运动命令。

## 4. 冷启动段（main，顺序固定）

```
1. cfg = load_app_config(项目根 / "configs/app.local.json", entry="production")
   ——失败时尚无正式日志，仅 stderr + terminate("APP_CONFIG_INVALID", detail)
2. session_id = runlog.init(cfg.log_dir)
3. params = load_motion_params(cfg.profile_path, mode="real") # real 要求 verified

     fb = motor.get_feedback()

                     <= params.motion.settle_position_tol_deg)

### 4.1 驱动启动握手（P1 必须实现，D17）

沿用公开 `initialize(*, verify_identity=True, enable_torque=True, timeout_s=...) -> None` 签名；默认构造调用它一次。`enable_torque=False` 只读身份/应答配置，不写目标或力矩；这条只读路径供已有标定工具继续使用。生产不使用 verify_identity=False。新增公开只读 `startup_report` 快照（dict 副本）与 `MotorStartupError(MotorStateError)`，错误携带相同报告，供构造失败时记录；main 不访问驱动私有协议对象。

默认上力路径按以下顺序执行，全部事务受本次绝对 deadline 约束：

1. 读取应答配置、核验身份、读取六轴 Torque_Enable。任一不为0，或任一读失败：失败退出，**零目标/力矩写入**；已上力的轴不能由本次启动自动卸力。
2. 在六轴均为0后，读完整新反馈和旧 Goal_Position；检查反馈有限、在已标定范围、五关节速度在 `motion.settle_velocity_tol_deg_s` 内、夹爪速度在 `gripper.settle_speed_pct_s` 内。旧目标与当前位置不一致只登记，后续以当前反馈预置，绝不先写 Torque_Enable=1。位置转换和限位沿用现有驱动编码器。
3. 广播当前位置目标前标记六轴均为 `torque_may_be_enabled`，因为 CAL-052 证明该写入可能隐式上力；写完核对全部 Goal_Position 等于编码目标，再读全部力矩。全1时不重复写力矩；存在0时只对0轴显式使能，随后再次完整读回；非0/1值拒绝。
4. 分隔写/读阶段的等待与排空输入沿用已验证脚本步骤（0.10s/0.20s 是当前实验值，计入 deadline，真机回归后锁定），完整读回反馈，五关节位置变化不超过 `motion.start_position_tol_deg`；夹爪开度变化不超过 `gripper.settle_tol_pct`。六轴已上力且位置检查通过才置 READY，返回构造调用方。禁止在此回 home/写 EEPROM。
5. 从步骤3首次可能上力起任一异常或 KeyboardInterrupt：驱动在独立有界 cleanup deadline 内逐轴尝试失能本次可能上力的六轴，即使某轴失败仍尝试其余轴；再逐轴读回。该清理只属于启动事务，不用于运行期 terminate。报告每轴 `off/on/unknown`，未成功读回0不得登记 off。清理不发 Goal_Position，不执行 hold/reset/home。

deadline 默认值沿用驱动常量作为待实测值；清理预算独立常量 `STARTUP_CLEANUP_TIMEOUT_S=5.0`，不是每轴重新起表，必须在目标机验证。报告含各阶段时间、旧/预置目标、前后位置、六轴读回、失败阶段、清理结果；异常后关闭传输句柄且不得泄漏。初始化成功之后，所有退出保持 §3.3 的零追加命令规则。

假总线用例见 T28–T30；真机验收使用实际 profile，记录参数和固件版本。不得把通过假总线测试写成物理启动安全已验证。

        continue
    task = cloud_model.select_plan(text)        # LLMHardError → terminate("LLM_HARD_ERROR")
    if task == "invalid":
        continue
    if task not in registry:
        terminate("LLM_CONTRACT_VIOLATION", repr(task))
    task_instance_id += 1                       # session内单调编号
    with runlog.context(task_id=task, task_instance_id=task_instance_id):
        plan = registry[task](arm)              # 每任务新实例，计数器归零
        plan.run()                             # 正常返回 = 仅 NoTarget×3
    # 不在此重复打印"任务完成"：统一由 _finish 输出（初审 L9）
```

| 异常来源 | 处置 |
|---|---|
| ASRHardError / LLMHardError | terminate（臂在 home） |
| VisionHardError（含 init/get_target） | terminate（臂在 home 或恢复后位） |
| PLAN 内 KeyboardInterrupt | WAITING/ASR 阶段 → terminate；抓取中由 arm_control 转 ABORTED → 分发表 → terminate；恢复 input() 中 → terminate |
| `SystemExit` | terminate 自己发的 exit(1) 直通，不包装 |
| 其余未预期异常 | terminate("UNEXPECTED", repr) |

PLAN 运行期间不录音、不提交云请求、不缓存下一任务。任务完成不退出程序，回 WAITING。生产入口无"跑完即退"分支。

## 6. plans 循环：计数器、分发顺序与恢复矩阵

### 6.1 计数器（D02/D03/D04）

| 事件 | no_target_streak | ignore | consecutive_failures | a_count |
|---|---:|---:|---:|---:|
| 新建 Plan | 0 | 0 | 0 | 0 |
| 视觉成功返回 | 0 | 不变 | 不变 | 分级为 A 并分配时 +1 |
| NoTarget | +1 | 0 | 不变 | 不变 |
| SUCCESS | 0 | 0 | 0 | 不变（不回滚） |
| 重试类失败 | 不变 | +1 | +1 | 不变（不回滚） |

### 6.2 run() 分发顺序（固定，不可重排）

下方为分发伪代码，省略日志context的缩进：每轮先递增scan_id，再按§3.4把本轮扫描至恢复放入同一context；在继续下一轮、return及异常退出时必须释放该context。函数签名/异常映射以§3、§5为准，不能把省略号当实际错误详情。

```python
while True:
    try:
        target = vision.get_target(self.ignore)
    except NoTarget:
        self.ignore = 0; self.no_target_streak += 1
        if self.no_target_streak >= 3:
            self._finish("NO_TARGET_STREAK"); return
        continue
    except VisionHardError:
        terminate("VISION_HARD_ERROR", "视觉管线故障")
    self.no_target_streak = 0
    self._validate_target_contract(target)        # §6.4

    grade = self.classify(target)
    place_id = self.next_place_id(grade)          # A 越界 → terminate（§6.3）
    self.attempt_id += 1
    runlog.event("assign", grade=grade, place_id=place_id, a_count=self.a_count,
                 valid_count=target.valid_count, ignore_used=self.ignore, ...)

    result = self.arm.grasp_and_place(target, place_id)
    # 先记录完整grasp_result；非SUCCESS累计failure_counts[result.status.value]
    # 任何直死/封顶分支之前都必须完成该次结果审计

    if result.stage == "FAULT_UNCONTROLLED":      # 1. 失控阶段最先
        terminate("FAULT_UNCONTROLLED", result.reason)
    if result.status == GraspStatus.SUCCESS:      # 2. 成功
        self.ignore = 0; self.consecutive_failures = 0; self.success_count += 1
        continue
    if result.status not in RETRYABLE_STATUSES:   # 3. 直死类
        terminate(result.status.value, result.reason)

    # 4. 重试类
    self.ignore += 1; self.consecutive_failures += 1
    exhausted = self.ignore >= target.valid_count
    if exhausted:                                 # 5. D14：判定无可抓取目标
        terminate("NO_GRASPABLE_TARGET",
                  f"ignore={self.ignore} ≥ valid_count={target.valid_count}，"
                  f"末次 {result.status.value}/{result.stage}")
        # 不恢复、不人工确认、不回 home、臂冻结于当次失败位（D14）
    if self.consecutive_failures >= MAX_CONSECUTIVE_FAILURES:   # 6. 预算
        terminate("FAILURE_BUDGET_EXHAUSTED", ...)              #    不恢复、臂冻结
    self._recover(result)                         # 7. 恢复后下一轮视觉
```

- 每次 NoTarget 之间不加 sleep；三连调每次都是真实新扫描。
- 连续三次 NoTarget 正常返回（**唯一正常完成出口**，D14）；每次视觉成功必须 `valid_count > requested_ignore`，不满足走 §6.4 契约违约。
- D14 精确触发条件：**本次重试类失败使 ignore 递增后，`ignore ≥ 本次返回该目标的 valid_count`**。视觉另因新扫描候选数变化抛出的 `NoTarget(skip_exhausted)` 不属于本封顶，仍走 NoTarget 分支（ignore=0、no_target_streak+1）；该分支不证明每个物理目标都已尝试。
- 封顶 terminate 不发任何新运动命令、不 reset、不 input()；"臂冻结"是沿用既有保持状态的业务描述，不代表软件在失控情况下仍能保证物理静止。

### 6.3 next_place_id（D04）

```python
def next_place_id(self, grade: str) -> str:
    if grade == "A":
        if self.a_count >= len(self.A_PLACE_IDS):
            terminate("A_SLOTS_EXHAUSTED", "优品槽位耗尽（GRASP_MISS 空耗捅穿摆桌保证）")
        pid = self.A_PLACE_IDS[self.a_count]; self.a_count += 1
        return pid
    if grade == "B": return self.B_PLACE_ID
    if grade == "C": return self.C_PLACE_ID
    terminate("PLAN_CONFIG_INVALID", f"未知 grade {grade!r}")
```

不回滚、不降级（A 耗尽不降 B、不循环覆盖 A_01）；任何运动结果（含运动前拒绝）都不回调 a_count。

### 6.4 视觉返回值契约复核（plans 侧）

`_validate_target_contract(target)`：`length_m >= width_m > 0` 且为有限 float；`ripe` 严格 bool；`valid_count` 正整数且 `> self.ignore`（当前请求值）；`yaw_deg ∈ [-90,90)`。违约 → terminate("VISION_CONTRACT_VIOLATION")，不触发抓取、不计 NoTarget。position/yaw 的深层校验归运动（INVALID_INPUT 直死），不重复实现。

### 6.5 恢复矩阵（D08 后定稿；D14 后仅服务"继续下一轮"路径）

> 注意：ignore 封顶（D14）在 §6.2 第 5 步直接 terminate，**不再进入本矩阵**。

| 返回情形 | 处置 |
|---|---|
| IK_FAILED / PLAN_INVALID，`recovery_required=False` | 运动前失败（臂未动、在 home、空爪）：不 reset、不搬臂，直接进入下一轮视觉（ignore 已 +1） |
| IK_FAILED / PLAN_INVALID，`recovery_required=True` | **terminate**（D08：一律终止，不区分 holding，臂冻结于失败位） |
| GRASP_MISS，`recovery_required=True` 且 `holding=EMPTY` | 空爪确定：自动 `reset_fault()` → 依次 `move_joints(safe_waypoints)` → `move_joints(home)` → 下一轮视觉 |
| GRASP_UNCERTAIN / GRIP_SLIP，`recovery_required=True` | 打印现场状态（status/stage/holding/reason）→ `input("确认物体已处置、可继续后回车...")` 阻塞等待；**回车即确认**（D13：不要求特定文本，空回车同样算确认）；EOFError/KeyboardInterrupt → terminate("MANUAL_CONFIRM_ABORTED")。确认后 `reset_fault()` → 中转 → home → 下一轮视觉 |
| GRASP_MISS/GRASP_UNCERTAIN/GRIP_SLIP 带 `recovery_required=False`，或 MISS 报 `holding≠EMPTY` 等状态与标志组合违约 | terminate("RESULT_CONTRACT_VIOLATION")，保留原 result 供定位 |
| reset_fault / 任一回程原语异常 / move 未到位 | 立即 terminate("RECOVERY_FAILED")，不追加 ignore 后再试恢复 |

回程路线冻结为 profile `safe_waypoints_deg` 列表顺序 + home，与冷启动复位一致；正常 SUCCESS 已由运动 RETURN 保证 home，不额外回零。确认期间不后台请求视觉或发送指令（同步阻塞天然保证）。

### 6.6 _finish（任务完成出口）

`runlog.event("task_done", reason="NO_TARGET_STREAK", success=..., failure_counts=..., a_slots_used=...)` + 终端一行：`任务完成：结束原因=NO_TARGET_STREAK，成功=N，失败码计数=...，已分配优品槽位=M`。终端必须含"任务完成"字样，同时不掩盖未抓走目标。D14 封顶仅记录 terminate，不调用 _finish。
