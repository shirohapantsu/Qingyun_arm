## 1. 目标与范围

1. **离线全链闭环**：`python3 scripts/run_mock.py`（独立 mock 入口，D15）不打开真实串口、不联网、不用真麦克风/相机，跑通语音→方案→视觉→抓取→完成→回 WAITING 的完整业务链（含失败分支）。
2. **真机集成**：目标机（香橙派）上同一套业务逻辑接真实设备完成草莓 demo；现场观察与日志一致。
3. **部署包与验收报告**：固定版本、依赖锁定、资源清单、现场记录与完成判据。

非目标：性能压测、多用户、蓝莓（D06）、修改各模块内部实现（发现缺陷回报对应阶段文档修订，不在本阶段私改契约）。

## 2. mock 全链装配（独立入口，D15/R04 重写）

新增 `scripts/run_mock.py`（独立 mock 入口；scripts 非生产运行链，**豁免"生产模块禁止导入 tests"**，可导入 `tests/mock_motor.py`）：

```python
# 装配契约（顺序固定）
cfg = load_app_config(固定路径 configs/app.mock.json)      # 含 mock 段
params = load_motion_params(cfg.profile_path, mode="mock") # simulation profile 副本
preflight_mock(cfg, params, MOCK_REGISTRY)                 # P1 §3.2 第 8 条

sim_time = SimTime()                                       # tests/mock_motor.py
motor = MockMotorController(params, sim_time)              # 含 P1 补的 initialize() 桩
arm = ArmController(motor, params,
                    clock=sim_time.monotonic,
                    sleep=sim_time.sleep,
                    clock_ns=sim_time.monotonic_ns)        # R04：必须统一模拟时钟，
                                                           # 默认真实时钟会判反馈过期

install_stubs(cfg)      # 替换 qingyun.asr / qingyun.cloud_model 的业务函数
                        # （不调用真实 init——D15：跳过 VAD/麦克风/密钥加载）：
                        #   listen_and_transcribe：按 cfg.mock.asr_script_path 的
                        #     转写序列逐次返回（耗尽后返回空串模拟静音）
                        #   select_plan：本地确定性映射（含"草莓"→"strawberry"，
                        #     其余→"invalid"），零网络
# vision 不替换：app.mock.json 的 vision_config_path 指向 replay 配置
# （P3 原生 source.mode=replay，帧目录=cfg.mock.vision_replay_dir）

run_session(cfg, arm)   # 复用生产 main 的会话函数与真实 Plan（R04：不复制业务循环）
```

- 替换方式为模块属性赋值，`install_stubs` 重复调用拒绝；生产 main 永不 import 本模块与 tests。
- **仿真 K 与 places**：`configs/app.mock.json` 的 profile_path 指向 simulation profile 的**副本**（需追加 strawberry_* places，按 tests/support.py 临时目录模式生成或提交一份专用仿真配置）；`MOCK_REGISTRY` 使用注入了名义 K 的 Plan 变体——坐标与 K 均为名义值并在配置与日志中注明**非实测**，不依赖 P4 回填（R04）。
- **replay 帧与业务一致性（R04）**：帧序列编排必须与脚本化的成功/失败序列一致（成功抓取后的后续帧不再含已被抓走的目标）；连续第二个任务必须能获得新的帧序列（目录分段或显式重置），不允许用"replay 耗尽 → NoTarget×3"来冒充连续任务通过。
- MockMotor 走 P1 补的 `initialize()` 桩；断言全链零真串口构造（注入探针 transport 验证）。

## 4. 真机集成（B 类，现场执行）

顺序固定，每步通过才进下一步：

1. **目标机依赖**：按锁定 requirements 安装（含 P2/P3 增补：音频/VAD/DashScope/DeepSeek 客户端/相机 SDK/YOLO 运行时）；记录版本清单。香橙派与开发机分别验证 import 与离线回放，不互相推断。
2. **设备验证**：相机（枚举、D2C、试采）、麦克风（44.1k 立体声输入正常）、串口（六舵机 PING）。
3. **云验证**：真实口令 → ASR 转写正确；→ LLM 返回 strawberry/invalid（各≥3 样本）；错误路径（断网）terminate。
4. **冷启动**：驱动启动握手（R07：旧 Goal_Position 不一致、部分使能失败、读回中断三种注入各验证一次）通过后，home 容差内外两分支各验证一次。
5. **单目标**：一个草莓完整抓放（A 或 B 落点）。
6. **多目标**：≥3 个含未成熟的草莓分拣，核对 grade→落点与日志一致。
7. **受控异常**：现场移走目标制造 NoTarget×3；空抓制造 GRASP_MISS 恢复。
8. **连续任务**：完成一次后直接下第二条口令。
9. **demo 判定**：一次完整任务（语音→分拣→回 WAITING）即达标（上层文档 §9）。

操作前提（每轮核对）：空爪、冷启动恢复通道已清、相机固定、ROI 单层且仅草莓、A 槽位已清空、箱内余量充足、语音与桌面果品一致、任务间清空/更换放置区（新实例从 A_01 重新分配）。**样本准入（R06/R09）**：demo 样本实际高度 ≤ `object_envelope_m[2]`（当前 45mm，量具抽检并留记录）；近圆果（圆度阈值按 P4 冻结口径）不纳入本期样本集合——运动碰撞模型按固定包络建模、物体膨胀按 5° yaw 界构造，超高/近圆样本没有运行期防线。
