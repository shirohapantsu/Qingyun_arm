## 1. 目标与范围

1. **离线全链闭环**：`python3 scripts/run_mock.py`（独立 mock 入口，D15）不打开真实串口、不联网、不用真麦克风/相机，跑通语音→方案→视觉→抓取→完成→回 WAITING 的完整业务链（含失败分支）。
2. **真机集成**：目标机（香橙派）上同一套业务逻辑接真实设备完成草莓 demo；现场观察与日志一致。
3. **部署包与验收报告**：固定版本、依赖锁定、资源清单、现场记录与完成判据。

非目标：性能压测、多用户、蓝莓（D06）、修改各模块内部实现（发现缺陷回报对应阶段文档修订，不在本阶段私改契约）。

## 2. mock 全链装配（独立入口，D15/R04 重写）

新增 `scripts/run_mock.py`（独立 mock 入口；scripts 非生产运行链，**豁免"生产模块禁止导入 tests"**，可导入 `tests/mock_motor.py`）：

```python
# 装配契约（顺序固定）
cfg = load_app_config(ROOT / "configs/app.mock.json", entry="mock")
runlog.init(cfg.log_dir)
params = load_motion_params(cfg.profile_path, mode="mock") # simulation profile 副本
preflight(cfg, params, MOCK_REGISTRY)                      # 与生产同一预检函数

sim_time = SimTime()                                       # tests/mock_motor.py
motor = MockMotorController(params, sim_time)              # 含 P1 补的 initialize() 桩
motor.initialize()                                       # mock构造不自动初始化，只显式调用一次
arm = ArmController(motor, params,
                    clock=sim_time.monotonic,
                    sleep=sim_time.sleep,
                    clock_ns=sim_time.monotonic_ns)        # R04：必须统一模拟时钟，
                                                           # 默认真实时钟会判反馈过期

install_stubs(cfg)      # 替换 qingyun.asr / qingyun.cloud_model 的业务函数
                        # （不调用真实 init——D15：跳过 VAD/麦克风/密钥加载）：
                        #   listen_and_transcribe：按 cfg.mock.asr_script_path 的
                        #     转写序列逐次返回（耗尽后返回空串模拟静音）
                        #   select_plan：本地确定性映射（含"草莓"→"strawberry"，
                        #     其余→"invalid"），零网络
# vision 不替换：app.mock.json 的 vision_config_path 指向 replay 配置
# （P3 原生 source.mode=replay，帧目录=cfg.mock.vision_replay_dir）

cold_start_recover(arm)
vision.configure(thresholds_from_params(params), cfg.vision_config_path)
vision.init()         # replay源；init验证首帧但不消耗扫描序号
runlog.event("ready")
run_session(cfg, arm, registry=MOCK_REGISTRY)  # 与preflight相同注册表
```

- 替换方式为模块属性赋值，`install_stubs` 重复调用拒绝；生产 main 永不 import 本模块与 tests。
- **仿真 K 与 places**：`configs/app.mock.json` 的 profile_path 指向 simulation profile 的**副本**（需追加 strawberry_* places，按 tests/support.py 临时目录模式生成或提交一份专用仿真配置）；`MOCK_REGISTRY` 使用注入了名义 K 的 Plan 变体——坐标与 K 均为名义值并在配置与日志中注明**非实测**，不依赖 P4 回填（R04）。
- **replay 帧与业务一致性（R04）**：帧序列编排必须与脚本化的成功/失败序列一致（成功抓取后的后续帧不再含已被抓走的目标）；连续第二个任务必须能获得新的帧序列（目录分段或显式重置），不允许用"replay 耗尽 → NoTarget×3"来冒充连续任务通过。
- MockMotor 走 P1 补的 `initialize()` 桩；断言全链零真串口构造（注入探针 transport 验证）。

`thresholds_from_params(params)` 是入口层的纯构造辅助函数，按 P0 六个来源逐一复制；不让 vision 导入 motion_params。P1 阶段使用 FakeVision 验证上述装配；P3 交付后同一入口切换原生 replay，P5 补场景资产。不得要求 P1 在 P3 尚未实现时已经运行真实视觉几何。

提交完整 `configs/app.mock.json`，独立于生产模板：

```json
{
  "profile_path": "../tests/fixtures/mock/profile.json",
  "vision_config_path": "../tests/fixtures/mock/vision.json",
  "prompt_path": "../prompt.md",
  "log_dir": "../logs/mock",
  "asr": {"model": "mock", "endpoint": "https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation", "cloud_total_timeout_s": 30.0},
  "llm": {"model": "mock", "base_url": "https://api.deepseek.com", "total_timeout_s": 30.0},
  "mock": {"asr_script_path": "../tests/fixtures/mock/scenario.json",
           "vision_replay_dir": "../tests/fixtures/mock/frames"}
}
```

场景资产由 P5 编写并提交，不能依赖个人机器上的权重、密钥或 P4 实测值：

- profile 是 simulation 副本，URDF/电机标定文件引用可解析，追加全部 strawberry_* places。K 用 mock Plan 子类覆盖，生产类不改。由现有 IK 和真实 ArmController 离线验证目标/落点组合可达，不随意填坐标后把 IK_FAILED 当 E2E 成功。
- vision.json 使用 P3 的 `model.backend="fixture"` 和 `source.mode="replay"`；固定检出 OBB 从逐帧 JSON 读取，RGB-D/测量/过滤/排序仍走真实管线。另设 yolo replay 烟雾验收，使用真实权重但不作为无权重 pytest 的前提。
- `scenario.json` 为对象：`{"utterances":["分拣草莓","分拣草莓"],"attempts":[{"contact":"present"},{"contact":"absent"}]}`。utterances 每次取一条；耗尽后替身按真实墙钟阻塞等 Ctrl-C（可用小段 sleep），不持续空串忙循环。单测注入可结束的输入源，捕获预期 SystemExit；生产会话不增加“跑完即退”。
- attempts 按每次真实 grasp_and_place 调用顺序消费。入口用仅负责设置 MockMotor 故障开关的 ArmController 子类包装调用，再原样调用 super；不替换返回结果。present 对应 `object_gap_m=float(mean(contact_gap_range_m))`，absent 对应 `object_gap_m=None`；沿用现有 MockMotor 的真实字段，不增加虚构的 object_present 开关。其他异常用 tests/mock_motor.py 的真实故障开关注入，场景清单登记开关值和触发时刻；不得伪造 SUCCESS。attempts 耗尽时拒绝场景，不默认为成功。
- 帧按 manifest 一条条消费，不以文件名的操作系统顺序决定。两个任务共用一条连续序列：第一任务目标及抓后帧→三张真实空桌帧→第二任务目标及抓后帧→三张空桌帧。init 不消费首帧，不重复 configure，不靠私有重置游标切换任务。成功后后续帧删除已抓物，失败后帧保留目标；测试断言实际成功数和消费帧数。
- P5 入口检查 cfg.mock.vision_replay_dir 与 vision.json 解析后的 replay_dir 一致，避免两个路径各读一套帧。每个 fixture/场景应标明 simulation，禁止进入实测证据目录。

## 4. 真机集成（B 类，现场执行）

顺序固定，每步通过才进下一步：

1. **目标机依赖**：按锁定 requirements 安装（含 P2/P3 增补：音频/VAD/DashScope/DeepSeek 客户端/相机 SDK/YOLO 运行时）；记录版本清单。香橙派与开发机分别验证 import 与离线回放，不互相推断。
2. **设备验证**：相机（枚举、D2C、试采）、麦克风（44.1k 立体声输入正常）、串口（六舵机 PING）。
3. **云验证**：真实口令 → ASR 转写正确；→ LLM 返回 strawberry/invalid（各≥3 样本）；错误路径（断网）terminate。
4. **冷启动**：驱动启动握手（R07：旧 Goal_Position 不一致、部分使能失败、读回中断三种注入各验证一次）通过后，home 容差内外两分支各验证一次。
5. **单目标**：一个草莓完整抓放（A 或 B 落点）。
6. **多目标**：≥3 个含未成熟的草莓分拣，核对 grade→落点与日志一致。
7. **受控异常**：现场移走目标制造 NoTarget×3；空抓制造 GRASP_MISS 恢复。
8. **连续任务**：完成一次后直接下第二条口令。
9. **demo 判定**：一次完整任务（语音→分拣→回 WAITING）即达标（上层文档 §9）。

操作前提（每轮核对）：生产进程启动前六轴全部卸力（D17）、空爪、冷启动恢复通道已清、相机固定、ROI单层且仅草莓、A槽位已清空、箱内余量充足、语音与桌面果品一致、任务间清空/更换放置区。D18：用户保证demo样本实物长宽高不超过object_envelope_m，当前为70×45×45mm；不额外要求逐个量具登记。近圆果按P4的已填写判据排除。进程终止后不盲目重启，先现场处置并恢复启动前提；程序不替操作者对已上力设备执行自动卸力。

## 5. 部署包

固定内容：代码版本（git commit）、锁定 requirements 与 Python/Conda 环境、YOLO 权重与类别映射、相机标定包（P4）、verified motion profile（P4 promote 产物）、configs/（app.local.json、vision.local.json、secrets 模板——密钥现场填）、prompt.md、mock 配置（回归用）。资源哈希在启动日志记录（由P1实现）。

部署包同时包含demo_acceptance.local.json、实际K值及所在代码commit、样本集合说明、视觉配置与算法版本、CAL-040/041/足迹验证报告。生成 `deployment_manifest.json`，逐项记录资源相对路径、SHA256、对应报告；密钥不入哈希清单。发布验收工具检查文件存在、哈希匹配、报告通过、未测字段非null，并以real loader重新加载profile。首次生产main真机动作前缺任一强制报告/条件不得用“演示过一次”替代。

近圆阈值与成熟度错误率在P4实物验收前确定；这些是显式待实测/验收输入，工具的schema、缺值拒绝行为和模拟值来源已冻结，不由编码者猜测默认值。

现场记录表（每轮）：成功分拣数、残留果、掉落、错分、损伤、软件完成原因（NO_TARGET_STREAK 或各类 terminate，D14 后 IGNORE_EXHAUSTED 不再是完成原因）、terminate 事件；与 JSONL 核对签名归档。

## 6. 完成标准

- **软件闭环完成**：§3 全部场景通过 + 全量回归通过 + 独立 mock 入口（`scripts/run_mock.py`）可重复演示。
- **真机 demo 完成**：§4 步骤 1–9 通过，验收报告（含 CAL-040/041、K、落点、抓取统计、混淆矩阵，P4 产物）归档。
- 两种完成标准不互相替代；"演示成功一次"不豁免 verified profile 的发布要求（落地方案 §9.2）。
