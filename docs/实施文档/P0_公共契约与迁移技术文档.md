## 3. 目标接口

保留当前 `configs.common_interface.VisionInterface`，不另外创建同名类型或双版本兼容构造器：

```python
@dataclass(frozen=True)
class VisionInterface:
    position: FloatArray  # np.float64，shape (3,)，base_link，m，几何中心
    yaw_deg: float        # 物体水平长轴，模180°，[-90,90)
    length_m: float       # 长轴长度，m
    width_m: float        # 短轴长度，m
    ripe: bool            # 成熟度
    valid_count: int      # 当前扫描过滤后合法候选总数，非剩余数
```

运动仅消费 position/yaw；分级字段与候选总数由视觉和 plans 保证及使用。不要为了通过旧测试给新数据类重新加上 grade、默认 grade 或动态属性。

**新增纯数据类型** `VisionThresholds`（D13，P1 组装注入、P3 消费的共享边界契约，必须在本阶段落地以解耦 P1/P3 并行）：

```python
@dataclass(frozen=True)
class VisionThresholds:
    """从已加载 motion profile 提取的视觉可抓性阈值快照。

    P1 的 main 在加载并校验 profile 后组装，经 vision.configure() 注入；
    视觉模块只导入本类型，不导入 motion_params/plans/main。
    """
    target_bounds_m: FloatArray   # (2,3) [min,max]，合法候选中心判定域
    object_envelope_m: FloatArray # (3,)   闭合轴向按 R_top_down 夹持约定对应
    clearance_m: float            # 邻物最小净距，m
    approach_height_m: float      # 接近高度，m（头顶净空检查推导用）
    table_z_m: float              # 桌面平面高度，base_link，m（几何中心估计用）
    table_flatness_m: float       # 桌面平整度容差，m
```

字段来源（构造时逐一从 `MotionParams` 复制，不做单位换算；已按 motion_params.py 实际字段核对）：`workspace.target_bounds_m`、`grasp.object_envelope_m`、`collision.clearance_m`、`grasp.approach_height_m`、`workspace.table_z_m`、`workspace.table_flatness_m`。数组字段构造时 `np.asarray(..., dtype=np.float64)` 并复制。

英文任务标识（D01，按 D06/D07 收窄）：`strawberry`、`invalid`。后者代表不启动方案，不注册 InvalidPlan 或 BlueberryPlan。`blueberry` 和 `"1"/"2"/"0"` 均不属于模型输出的合法 task 值；用户输入蓝莓任务应由模型返回 invalid。

## 6. 必测与通过标准

- 六字段合法对象可以进入正常抓取流程，不再因缺 grade 返回 INVALID_INPUT。
- 非法 position 的 shape/dtype/NaN 以及非法 yaw 仍在发送运动命令前拒绝。

- 改变新元数据不改变运动放置选择；运动不开始读取 length/width/ripe/valid_count。

- `VisionThresholds` 可从当前 simulation profile 的 MotionParams 组装，字段形状/dtype 正确，冻结且数组为副本。
