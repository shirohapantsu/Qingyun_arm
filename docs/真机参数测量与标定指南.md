## 1. 配置与标定工具

### 1.1 标定包

```text
calibration/<robot_id>/<profile_id>/
  profile.json                 # 运行期参数与 places 放置位姿
  motor_calibration.json       # 官方电机校准数据
  raw/*.jsonl                  # 原始读数、参考测量与实验记录
  reports/validation.json      # 参数验收结果、输入哈希及人工实物评估
```

`raw/` 与 `reports/` 不由 `init` 创建，必须手工预建：`capture --output .../raw/x.jsonl` 会因父目录不存在而失败，`capture --hardware` 的前置检查在 `reports/<前置阶段>.json` 缺失时直接拒绝。本机首次标定即踩此坑（`dev_logs/真机标定问题记录.md` ISSUE-011）。

目录名 `<robot_id>/<profile_id>` 只是命名约定。`profile_id` 与 `robot_id` 一律从 JSON 字段读取（`configs/motion_params.py:1224-1225`），不由路径推导；报告比对只用 `profile_id`。因此字段值与目录名不一致时功能照常，只是容易混淆——`calibration/REAL_ARM/PC/` 里写的却是 `robot_id="REAL_ARM_PC"`、`profile_id="real_pc_v0"`。

**相对路径深度必须跟着标定包的目录层数走。** `model.urdf_path` 以 profile.json 所在目录为基准，从仿真包（`calibration/SIM_ROBOT/simulation/`，3 层）复制到实机包时若层数变了，`"../../../libs/.../so101_new_calib.urdf"` 会解析到仓库之外，加载期报 `model.urdf_path: 文件不存在`（ISSUE-001）。

`MotionParams` 的嵌套属性与 profile.json 字段逐项同名，数组加载为 np.float64；`places` 映射的每个值加载为公共接口 PlacePose。另有 `profile_dir`、`urdf_limits_deg` 两个派生字段不出现在 JSON 中，键校验时被显式标记为"派生"。

```python
def load_motion_params(profile_path: Path, *, mode: Literal["real", "mock"]) -> MotionParams: ...
```

real 模式要求 status=verified、全部运行期字段非 null，模型和电机校准文件哈希与验收报告匹配，并且报告里**每个阶段至少有一条 `evidence_type="physical"` 证据**（`configs/motion_params.py:1288`）——纯 mock/offline 证据的配置永远上不了实机。mock 模式要求独立的 status=simulation 配置，跳过哈希与报告匹配，但结构、shape、单调性、限位交集全部照查。

**draft 状态在这两条链上都加载不了**：real 因 status 被拒，mock 因 status≠simulation 被拒。采集发生在 draft 期，因此另有第三条入口，见 1.2。

加载时拒绝未知键、缺失键、非有限值、错误 shape、非法旋转、空限位交集和不单调标定表。此外加载期还会拒绝：`home_joints_deg`/`safe_waypoints_deg` 越出有效限位、`contact_gap_range_m` 越出 `gap_table` 定义域、三张表无共同覆盖区间、`ignore_self_pairs` 引用不存在的 capsule id、重复 id、含 DTD/ENTITY 的 URDF。放置位姿的 `yaw_deg` 在加载时被 `wrap180` 归一化到 `[-90,90)`。

### 1.2 标定 CLI

```text
python scripts/calibrate.py init    --output <目录> --robot-id <ID> --profile-id <ID>
python scripts/calibrate.py capture --stage <阶段> --profile <文件> --output <数据.jsonl>
                                    [--hardware] [--reference <文件>] [--repeats <N>]
                                    [--operator <名>] [--power <名>] [--pad <名>] [--load <名>]
python scripts/calibrate.py fit     --stage <阶段> --profile <文件> --input <数据.jsonl> --output <候选配置.json>
python scripts/calibrate.py validate --stage <阶段|all> --profile <候选配置.json> --input <验证数据.jsonl>
                                    --report <报告.json> [--operator <名>] [--operator-reviewed]
python scripts/calibrate.py promote --profile <候选配置.json> --report <报告.json> --output <配置.json>
```

阶段固定为 `motor / joints / tool / workcell / timing / motion / grasp / pick_place`，前置关系是一条严格的顺序链。`fit` 与 `validate` 均为离线处理，`validate` 不启动运动（代码里只在采集路径导入只读的 `CalibrationReader`）。退出码：0 正常，`validate` 在本次受检阶段未通过时为 1，配置/数据错误为 2。

**`capture --hardware` 只支持 motor / joints / tool / workcell 四个阶段。** 其余四个阶段需要 `ArmController` 的完整动作路径，代码显式拒绝并要求"把运行期日志导出为同格式 JSONL"再喂给 `fit`/`validate`（`scripts/calibrate.py:533-537`）。timing / motion / grasp / pick_place 的实机数据全部走这条路，本文第 8~11 节的采集规程因此是**给运行期日志导出格式的说明**，不是给 capture 的说明。

实机采集本身只读总线，且**参考量必须来自操作者手工录入的 `--reference` 文件**：

| 阶段 | 总线自动读回 | `--reference` 必须人工提供 |
|---|---|---|
| motor | `raw_position/raw_velocity/raw_current/sample_*_ns` ×`--repeats`（默认 5） | `reference_angle_deg[6]`、`reference_current_ma[6]`（量角器/外部电流表） |
| joints | `q_bus_deg` | 每行 `q_reference_deg[5]`、`approach_direction`、`sweep_joint_index`，以及端点/应用限位/FK 验证各系列行——**但 joints 分支不会把这些键写进记录，见第 5 节警告** |
| tool | `q_urdf_deg`、`gripper_pct` | 每行 `tcp_reference_B_m`、`T_B_TCP_reference`、`gap_m`、`gripper_reference_angle_deg` |
| workcell | `q_urdf_deg`、`gripper_pct` | 每行 `entity_id` 及其对应几何量（见第 7 节） |

joints / tool / workcell 的 `--reference` 格式是 `{"samples": [ {...}, ... ] }`；motor 是单个对象。每行样本对应一次总线读回，操作者把机械臂摆到该姿态后逐行采集。

三个必须知道的实现事实：

1. **`init` 生成的 draft 不是"全 null 骨架"。** 它先整份复制 `calibration/SIM_ROBOT/simulation/profile.json` 作模板，再套用 `DRAFT_OPERATOR_VALUES`（约 60 项，含 `acceptance.*` 全部 9 项、motion/ik/gripper/timing 的一批待试值）与 `DRAFT_FIXED_VALUES`（`timing.fps=30`、`motor.ids=[1..6]`），最后把**第 1.4 节标为 A/B/C 类的待测物理量**置 null。"验收要求和待试参数由操作者先填入 draft"因此已由 `init` 代劳了一遍——操作者的责任是**逐个复核并显式确认这些预填值适用于本机**，而不是以为它们是自己定的。
2. **`fit` 总是把候选文件 `status` 强制写成 `draft`**，并另出一个 `<output>.audit.json` 边车（`updated_fields / residuals / notes / fit_sample_ids`）。以 `_calibration_note` 开头的键只进边车、不进配置。
3. **`validate --report` 是可读可写的状态文件**：已有报告会先载入再合并本阶段结果。`promote` 要求八个阶段全部存在且 `passed`，并写入 `status=verified` 与 `verification.{report_path,report_sha256}`。`promote` 对"某阶段全是 mock/offline 证据"**只打印告警、不失败**（`calibrate.py:2120`），真正的关卡在 1.1 的 real 模式加载器。`--operator-reviewed` 会让 CLI 自己置上人工复核标记，`operator` 缺省为 `"unknown"`——**这意味着"人工复核"在工具层面可以被绕过，它靠的是流程纪律，不是代码强制**。

### 1.3 数据与报告格式

JSONL 每行**恰好**五个顶层键：`stage、run_id、sample_id、captured_at_ns、payload`。`run_id` 12 位十六进制、`sample_id` 10 位十六进制，`captured_at_ns` 取当前进程 `time.monotonic_ns()`。记录以追加方式写入。每个新 `run_id` 的第一条 payload 必须是 `record_type="metadata"`，记录 `source`（`hardware`/`simulated`）、`models`、`firmware`、`port`、`power`、`pad_id`、`load_label`、`operator`；其余样本 `record_type="sample"`；grasp 阶段另有 `record_type="trial_summary"`（缺省视为 `sample`）。各阶段其余 payload 字段见对应测量章节，**必须与 1.4 节所述 fit 实际读取的键一致**。

拟合样本和独立验证样本的 `sample_id` 不重叠（重叠即硬失败），保存原始量和换算后物理量。报告包含 `profile_id、parameter_sha256、operator、operator_reviewed、stages、overall_pass`；`stages` 按八个阶段映射，每项含 `input_sha256、fit_sample_ids、validation_sample_ids、checks、passed`。每个 check 含 `name、field_path、measured、limit、comparison、passed、evidence_type、evidence_refs`。

`comparison` 代码只实现 `<=`（含 1e-12 容差）、`>=`（含 −1e-12）、`==`（1e-9 容差）；**`all` 未实现，写了会抛错**。`evidence_type` 取值只有 `physical / mock / offline`，且 `mock` 的判据是"该阶段 metadata 的 `source=="simulated"`"——**只要走 `--hardware`，哪怕只是一次静止读回，也会被登记为 physical**。配合 1.1 的加载关卡，这意味着"physical 证据"只证明数据来自真机总线，不证明该参数已被真正测量并核对；参数是否测对仍要靠本文各节的验收条款与人工判断。

`input_sha256` 是 `--input` 文件的普通 SHA256，同一次运行内八个阶段共用同一个值。许多阈值（1.0 计数、25.0 mA、10.0° 行程跨度、1.0° sign 拟合 RMS、10 个 FK 构型、1e-6 正交残差、3 个开度、0.005 m 平面度、9 个桌面点、1000 个 tick）**写死在 `calibrate.py` 里而不是配置中**，改配置不能放宽它们。

parameter_sha256 对 profile 除 status、verification 外全部字段做排序键、UTF-8、紧凑 JSON 序列化后求 SHA256。verification 保存报告路径与哈希；报告整体审核通过后才能 promote。记录实际测量值，不为通过验收而自动放宽 limit。

### 1.4 参数获取途径分级

本节回答一个实操问题：**每个参数到底谁负责测？** `fit` 会写一个字段，不等于该字段被测量过。分级如下：

- **A｜样本拟合**：`fit` 从 JSONL 里的实测样本解出该字段。操作者的责任是按本章节规程采够样本、并核对 audit 边车里的残差。
- **B｜伪拟合**：`fit` 会写这个字段，但写进去的是字面常数、draft 预值的原样回抄，或由别的字段乘固定系数推导。**跑完 fit 绝不等于测完；这类字段是最危险的"看起来已标定"。**
- **C｜无 fit 通路**：`fit` 从头到尾不碰，只能由操作者测量后手工写入配置，或在 draft 阶段显式规定。
- **D｜运行期无消费点**：没有任何 `qingyun/grabbing/` 代码读它（详见 2.6）。仍需人工确定，但**不要指望代码替你拦住错值**。

#### A｜样本拟合（责任：按规程采够样本）

`joints.sign`、`joints.zero_offset_deg`、`joints.measured_limits_deg`、`joints.application_limits_deg`、`tool.rotation_e_tcp`、`tool.translation_samples`、`gripper.gap_table`、`gripper.angle_table`、`workspace.table_z_m`、`workspace.table_flatness_m`、`workspace.obstacles`、`workspace.home_joints_deg`、`workspace.safe_waypoints_deg`、`workspace.target_bounds_m`(兼 D)、`places`、`collision.link_capsules`、`collision.ignore_self_pairs`、`motion.max_velocity_deg_s`、`motion.max_acceleration_deg_s2`、`motion.following_error_deg`、`motion.settle_position_tol_deg`、`grasp.center_offset_object_m`、`grasp.yaw_offset_deg`、`gripper.empty_closed_pct`、`gripper.empty_tol_pct`、`gripper.slip_opening_change_pct`、`gripper.preopen_pct`、`gripper.release_pct`、`model.urdf_sha256`、`model.motor_calibration_sha256`（哈希是资源绑定，不是测量）。

注意 A 类的参考量本身仍是人工测量：`joints` 的 `q_reference_deg` 必须来自几何夹具/量角，`tool` 的 `tcp_reference_B_m`/`T_B_TCP_reference`/`gap_m` 必须来自尖点、量块与卡尺。工具只负责把外部测量解成参数，不负责产生外部测量。

另注：joints 组四项（`sign`、`zero_offset_deg`、`measured_limits_deg`、`application_limits_deg`）虽然形式上都是 A，但它们所需的样本键在当前硬件采集分支里会被丢掉（第 5 节警告），所以在 calibrate.py 修好之前**实操上按 C 类对待**——样本必须人工追加进 JSONL。

`ik.seed_joints_deg` 额外注意：`init` 预填 `[]` 且没有任何 fitter 写过它，所以它在 fit 链路上恒为空；本机配置里的 4 组初值是操作者手加的。

#### 特别一档：`acceptance.*`

指南原要求"验收要求在调参前确定"。代码事实是：`acceptance.*` 由 `init` 从 `DRAFT_OPERATOR_VALUES` 预填，**任何 fitter 都不修改它**，`validate` 直接从配置读它当 limit（所以"不为通过验收而放宽 limit"在代码上成立）。但"预填"不等于"操作者已规定"——`promote` 之前必须逐个确认这 9 项适用于本机、且确已在任何调参之前定下。另见 2.6：`acceptance` 整组在运行期无消费点。

## 2. 配置字段字典

所有表中字段均为必需键。`[5]` 按 JOINT_NAMES，`[6]` 按 MOTOR_NAMES；`[5,2]` 每行为 [lower,upper]，`[2,3]` 的两行分别为 XYZ 最小/最大值。实机未知参数在 draft 中为 null，不能由代码补猜测值——**但 1.4 的 B 类字段正是这条禁令的现存例外，它们由 `fit` 写入常数，只能靠人工覆盖。**

```text

shoulder_lift  [-100.0000, +100.0000]     wrist_roll    [-157.2110, +162.7893]
elbow_flex      [ -96.8300,  +96.8300]
```

`wrist_roll` 限位本身不对称，进一步说明不该拿对称的猜测值凑 `application_limits_deg`（见 4.1 第 4 条与 ISSUE-007）。

官方校准文件里的 `homing_offset` 与 `drive_mode` **只登记、绝不参与换算**（`motor_control.py:314`、`:402`）。`drive_mode` 只校验取值 ∈ {0,1}。不要据此在配置里补 offset 去"对齐"读数——那会造出两份方向真值，正是 4.1 第 3 条禁止的重复补偿。

## 3. 测量顺序与采集条件

代码注释按 `指南 3.3` 引用本节第 3 条，因此下列条目顺序不可重排。

1. 顺序为 motor→joints→tool→workcell→timing→motion→grasp→pick_place。更换零位、指垫、框位置或关键运动参数后，重新验证受影响的后续阶段。
2. 标定前固定基座，确认独立断电急停可用。卸力时托住机械臂。motor 阶段允许单电机配置与卸力手动读数；joints/tool/workcell 阶段使用受限低速点动或手动夹具；timing 阶段先静止读写；motion 使用空场短路径；grasp/pick_place 使用已验证区域与测试物。
3. capture 的实机模式逐阶段检查前置条件，实际检查项是：前置阶段的 `reports/<阶段>.json` 存在且 `stages.<阶段>.passed` 为真，以及 `motor.port`/`motor.baudrate` 非 null。**不再要求 `timing.*`**——只读采集用的是 `CalibrationReader` 自己的采集预算，而 timing 组要到第 5 阶段才拟合，用它当前置会在 tool/workcell 采集时结构性死锁。`load_calibration_profile()` 接受 `status ∈ {draft, verified}`，所以把配置退回 draft **不影响采集**。
4. 全部采集、点动、规划和回放顺序执行；拟合与验证离线进行。每阶段仅允许规定动作范围，不自动搜索机械硬端点或运行未校验路径。
5. **先做电气冒烟，再谈配置字段。** `serial.Serial` 打开成功只代表 USB 侧适配器在线，不代表总线对端存在。半双工舵机在未供电时表现为**任何波特率都零字节**（波特率错会收到乱码而不是零字节）。本机曾因此把"配置字段错"当方向排查了一整轮（ISSUE-013）。采集脚本必须先逐 ID PING 一次，并顺带核对应答的是这台臂的六个 ID。
6. **哈希链条会放大重做的范围**：官方校准文件一旦重跑，`model.motor_calibration_sha256` 变化 → `parameter_sha256` 断裂 → real 模式加载失败，此后 joints 及以后各阶段的已拟合值全部作废，需从 joints 起重做后续验证。因此标定期间不要把官方校准文件当"只读资源"随便覆盖（本机该文件权限为 `-r--r--r--`，正是为此）。

## 4. motor：身份、物理量和夹爪百分比

### 4.1 原始记录与准备

payload：`raw_position[6]、raw_velocity[6]、raw_current[6]、reference_angle_deg[6]或null、reference_current_ma[6]或null、sample_start_ns、sample_end_ns、torque_enabled、motion_label`。寄存器读回的原始无符号值按 4.3 的符号位规则先解码，再进行数值换算。命令记录保存 request 和结果，不能只保留成功数据。

`capture --hardware` 会把 `torque_enabled` 恒写成 `1`、`motion_label` 恒写成 `"static"`，`reference_*` 两项整体取自 `--reference` 文件（对所有 repeat 相同）。`reference_angle_deg` 在 motor 阶段的 fit 中并不参与求解——真正用它的是 joints 阶段；motor 阶段的参考量是 `reference_current_ma`。

1. 对照 ID 1～6 与实体关节，必要时只连接一个舵机配置 ID；读取固件与型号。项目里**唯一**做身份比对的地方是运行期 `initialize()` 内的 `_verify_identity()`（读 `Model_Number` 与固件版本并与配置比对，不符即 `MotorStateError`），采集路径不做比对，且 `metadata` 里的 `models`/`firmware` 是从配置回抄的（1.4）。**这一步只能人工完成**：逐个 PING + 读寄存器，并把读回值手工写进 `motor.models`/`motor.firmware`。
2. 核对串口、供电、波特率；保留官方 LeRobot 校准原始文件和 SHA256。校准文件必须六个通道齐全且端点已填，否则 `fit --stage motor` 会拒绝它还是 init 骨架。
3. 按官方流程做 homing 与范围采集；手动缓慢经过可达范围，避免顶死。不要重复在本项目里再加一次官方 homing_offset（见 2.1）。
4. 特别记录 wrist_roll 的实际线缆安全范围。官方校准中把 wrist_roll 记为 0～4095 不代表应用可以绕满一圈——**本机 `range_min=0, range_max=4095` 正是这种"没测出实际端点"的典型形状**，而 URDF 限位本身不对称（2.1）。线缆会在某个角度被拧断，当前配置对此必须给出实测依据（ISSUE-007）。

### 4.2 关节读数的严格换算

本机 LeRobot 的 DEGREES 归一化使用官方 calibration 中 `mid=(range_min+range_max)/2` 和 `resolution-1`：

```python
q_bus_deg = (raw_position_after_homing - mid) * 360.0 / (resolution - 1)
q_urdf_deg = joints.sign * q_bus_deg + joints.zero_offset_deg
q_bus_command = (q_urdf_command - joints.zero_offset_deg) / joints.sign
raw_command = round(q_bus_command * (resolution - 1) / 360.0 + mid)
```

`raw_position_after_homing` 就是设备上报的 `Present_Position` 原值，**不加 `homing_offset`**（`motor_control.py:607`）。4.1 与 4.2 是同一个"不重复补偿"约定。

生产 C 可以调用已验证的 SDK DEGREES 转换，再做 sign/offset；也可使用上述原始公式，二选一，不重复归一化。本项目实际实现是后者：`MotorMapping.raw_to_bus_deg` / `degrees_to_raw` 用 `count_to_deg = 360/(resolution-1)` 与 `mid_raw`，取整固定 `round()`。整数取整策略必须固定并用往返测试证明误差不超过半个/一个编码步长的实际实现界限。量化误差也计入限位余量。

本机 sts3215 的编码步长是 `360/4095 = 0.087912°/计数`，即单关节取整误差量级 ±0.044°；夹爪百分比与计数的换算另按 4.4，其 1% 对应的计数由标定端点跨度决定，端点跨度小的机器上百分比取整误差会明显更大。

**换算后的目标还会撞一道官方行程硬闸**：`send_action` 在完成全部校验、换算之后，逐通道检查编码目标是否落在该通道官方 `[range_min, range_max]`（含取整余量）内，越出即整条 `MotorLimitError` 拒绝，理由是"说明方向/零位/限位三者之中有东西错了，写下去就是拿舵机去撞硬端点"。因此**限位数值自洽但零位/方向错，会以"命令被拒"的形式暴露，而不是以"位置不对"的形式暴露**——这是 joints 阶段之前不要试图靠放宽限位绕过的检查。

### 4.3 电流和速度单位

`current_ma=(decoded_raw_current-current_zero_raw)*current_ma_per_raw`；控制阈值比较其绝对值。current_ma_per_raw 先根据当前型号/固件的厂商资料确定，用可靠参考测量验证合理性。测板上整机供电电流不能直接当某个舵机的电枢电流来拟合"夹持力"；无法可靠验证时记录限制，不伪造 mA/力映射。

速度先按厂商比例转换，关节再乘 joints.sign。用多组低速正反向运动的连续位置差分中位数，与速度读数对照方向和量级（`fit` 的 `velocity_direction_check` 只做这个方向核对，不产生数值）。禁止把 Present_Load 当 Present_Current，或把寄存器整数原样填进带 mA/deg_s 名称的接口。

驱动按 56..70 的 15 字节连续块读回 Present_Position/Velocity/Current，块内中间字节（含 `Present_Load`）透传但一律不解码。**`Present_Current` 的方向位未登记在 vendor 编码表里，因此当前按无符号解码**——这是从表推出的、不是从固件手册确认的实现选择，注释本身要求"必须在 motor 标定阶段核对"。核对结果若与假设不符，只需改 `MotorMapping.sign_bit`，上层不变（`dev_logs/电机修改.md` §6.5 同样列为待验证）。

**换算比例的基准是实际固件版本。** 本机登记的固件曾是从仿真抄来的 `2.54`，实测读回 `3.10`；改固件字段后，原先按 2.54 资料取的 `current_ma_per_raw`、`velocity_deg_s_per_raw` 与符号位假设全部作废，需按 3.10 的寄存器/电气资料重新取。

### 4.4 夹爪开闭两端

托住手臂，移走物体，在低速受限条件下记录不持续挤压硬端点的安全闭合读数 closed_raw 和安全张开读数 open_raw。重复至少 5 次，检查迟滞和方向：

```python
g = 100 * (raw_position - closed_raw) / (open_raw - closed_raw)
raw = closed_raw + g / 100 * (open_raw - closed_raw)
```

open_raw 不必大于 closed_raw。分母为 0 禁止使用（加载期即拒）。超出范围的观测属于异常而不是先裁剪成 0/100 后掩盖故障——`CalibrationReader.read_snapshot()` 在读数越出标定端点时抛 `MotorLimitError`，不裁剪。夹爪速度用 `raw_count_speed * 100/(open_raw-closed_raw)` 转成 %/s，raw_count_speed 由已换算的轴角速度换回对应编码计数/秒。

**实操上这两端是人工测量项**：硬件采集不产出端点样本（1.4），`fit` 因此永远保持 draft 里的旧值。本机 draft 抄自仿真的 `500/3600` 与官方行程 `[1458, 2980]` 直接冲突：0%、3%（`empty_closed_pct`）和 100% 换算出的 raw 全部越出官方行程而被 4.2 的硬闸拒绝，**夹爪既无法完全闭合也无法完全张开，抓空判定位置本身就走不到**。连带后果是真机 gripper 可用行程只有 1522 计数（≈66.9° 总线角），仿真侧是 3125 计数，宽一倍多，因此 `gripper.gap_table` 的开度↔间距斜率**不能沿用仿真那份 0~100% 对应 5~55mm 的形状假设**。

验收：ID/方向逐项正确；度数/百分比指令往返正确；电流与速度单位有出处和验证数据；motor 校准文件与当前 EEPROM/homing 状态匹配。

## 5. joints：方向、零位、行程和外部 FK 验证

payload：`q_bus_deg[5]、q_reference_deg[5]、measured_tcp_position_m[3]或null、measured_tool_axes[3,3]或null、fixture_id、load_label、approach_direction`。fit 另外要求这些按 `approach_direction` 分流的行，键名必须完全一致：

| `approach_direction` | 额外必填键 | fit 用途 |
|---|---|---|
| `"joint_sweep"` | `sweep_joint_index`、`sweep_direction` | 试 sign=±1 拟合 `sign`/`zero_offset_deg`，每关节至少 3 行 |
| `"endpoints"` | `sweep_joint_index`、`endpoint_side`(`lower`/`upper`)、`endpoint_urdf_deg`、`endpoint_repeat_deg` | `measured_limits_deg` 取 `endpoint_repeat_deg` 的重复观测极值 |
| `"application_limit"` | `sweep_joint_index`、`application_limit_urdf_deg[2]`、`limit_reason` | `application_limits_deg`；缺任一节则 fit 报错而不是猜 |
| `"fk_validation"` | `fk_check: true`、`q_reference_deg`、`measured_tcp_position_m` | 计数校验，**至少 10 个**才通过 |

参考角必须来自几何夹具、量角/倾角测量或外部标记测量，不能把同一个 FK 输出当真值。

**⚠ joints 的硬件采集路径目前是断的，实测已确认。** 与 tool/workcell 分支不同，`_capture_hardware` 的 joints 分支只把 `--reference` 行里的 `q_reference_deg / measured_tcp_position_m / measured_tool_axes / fixture_id / load_label / approach_direction` 六个键取出来（`calibrate.py:515-521`），**不 `payload.update(row)`**，因此上表的 `sweep_joint_index`、`endpoint_urdf_deg`、`endpoint_repeat_deg`、`application_limit_urdf_deg`、`fk_check` 全部被丢掉。用硬件采集形状的 joints 数据直接调 `_fit_joints` 会抛 `KeyError: 'sweep_joint_index'`（本文档修订过程中已复现）。这是 calibrate.py 的实现缺陷，不是测量规程能绕开的：修好之前，joints 阶段的 JSONL **必须由操作者按上表键名手工追加**（总线侧的 `q_bus_deg` 与 `sample_*_ns` 可先用 `--hardware` 采出，再把外部测量键补写进对应行）。joints 是 tool/workcell 及以后所有阶段的基准，本项不通则整条链不通。

1. 按 URDF link/joint 的 origin 和 axis 确认每关节正方向。固定其他关节，手动或很小点动，至少取三个不同角度并覆盖正反方向。
2. 对每关节试 sign=+1/-1，拟合 `q_reference = sign*q_bus + offset`。选择残差较小且符合轴定义的方向，offset 取相应残差均值/稳健估计。fit 输出 `sign_fit_rms_deg`，validate 要求逐项 ≤1.0°。
3. 参考姿态若是连杆绝对倾角，要先按 URDF 固定变换和父关节姿态换算为该关节角，不能直接赋给 q_reference。
4. 在安全机械范围内缓慢记录下限、上限；转换到 URDF 坐标后，填 measured_limits_deg。线缆、支架、桌面限制填 application_limits_deg。
5. 从端点测量误差、编码量化和运行停止余量确定 margin_deg，再计算有效交集。B/C 共用同一计算结果。`fit` 的公式是 `margin = max(draft 值, 端点重复散布 + 0.5)`——**只会变大不会变小**，所以 draft 里的 `margin_deg` 仍然是一个需要人工判断的输入。
6. 用至少 10 个未参与拟合的不同构型，含工作区近/远、左/右和不同腕姿，检查外部测得末端/工具参考点与 FK。必要时先用可测的刚性工具标记点，随后在 tool 阶段验证真实 TCP。

**未拟合期间不要把 sign/zero_offset_deg 填成非 null 占位值。** `dev_logs/修复报告.md` §一（P1-5）的保护只在字段为 null 时生效：全 `+1`/全 `0` 的仿真占位值会让 `read_snapshot()` 照常输出 `q_urdf_deg`，而没有任何一处标记这些数是假的。本机实测证据：静置不动时按占位值换算出的角度里，`shoulder_lift=-102.68°` 越出配置有效限位下限 9.68°、`elbow_flex=99.47°` 越上限 9.47°——**说明零位基准本身就是错的，不是臂摆到了奇怪姿势**。因此 joints 拟合完成前，标定包里 `joints.sign`/`joints.zero_offset_deg` 应保持 `null`，让 `load_calibration_profile()` 的既有保护（joints 组含 null 时返回 `joints=None`，`q_urdf_deg` 随即为 `None`）真正生效；这也直接保护第 7 节示教 `home_joints_deg` 时不把错误零位固化进配置。

验收：方向一致，固定角度偏差和正反向迟滞在预算内，所有验证构型有效；误差随姿态变化明显时排查装配/连杆/模型，检查运动学模型与安装几何。仅用肉眼手摆一次顶抓不能完成本阶段。

## 6. tool：工具坐标轴、TCP 随开度变化与有效开口

### 6.1 器材和采样

使用尺寸已知、不会明显压缩的量块/圆柱、固定定位尖点或标记夹具、游标卡尺；测量精度须优于 acceptance.max_position_error_m 的预期分配。payload：`gripper_pct、q_urdf_deg[5]、tcp_reference_B_m[3]、T_B_TCP_reference[4,4]或null、gap_m、gripper_reference_angle_deg、fixture_id`。

**本阶段的前置是 joints 已拟合**：`capture --hardware --stage tool` 读的是 `q_urdf_deg`，若配置里 `sign`/`zero_offset_deg` 仍为 null，采集直接报错（这是 5 节保留 null 保护后的必然顺序）。

确定实际夹持深度和指垫接触带，在每个使用开度采样至少 3 个不同机械臂姿态；开度至少覆盖闭合附近、中间、预张开、释放范围，通常 5 个以上更便于检查非线性。fit 的硬性下限是**至少 3 个不同开度、至少 6 行样本**。不要把所有参考点都放在一条直线上或只绕单一轴转动。

### 6.2 固定开度的 TCP 平移

已知独立参考中心 p_B_ref 时，每个样本用 FK 得到 `T_B_E=[R_i,t_i]`，计算 `p_E_TCP_i=R_i.T@(p_B_ref-t_i)`，同一开度稳健平均（逐分量中位数）得到 xyz_m。

若使用未知但固定的 pivot 点，通过多个方向触及同一夹具中心，可解线性最小二乘：`R_i*p_E_TCP - p_B_pivot = -t_i`。需报告矩阵秩/条件数；姿态变化不足时拒绝拟合。夹持中心无法直接触及尖点时，用已知几何偏移的夹具把量块中心换算到接触中心，必须记录该偏移。

按开度得到 translation_samples；只分段线性插值平移，不外插。用未采样的中间开度做独立验证，把插值误差计入 tool.position_error_bound_m。**注意 `fit` 不解 `tool.position_error_bound_m` 与 `tool.orientation_error_bound_deg`**（1.4 的 C 类）——这两项是本阶段唯一必须由操作者根据独立验证结果亲手写进配置的误差界。

### 6.3 工具轴旋转

用已知方向的夹具/标记板测量 TCP +X（闭合代表方向）、+Z（接近方向），单位化并正交化，+Y=+Z×+X，得到 R_B_TCP_ref。每个姿态计算 `R_E_TCP_i=R_B_E_i.T@R_B_TCP_ref_i`；对矩阵和做 SVD 投影到 SO(3)，确保 det=+1，作为 rotation_e_tcp。audit 边车给出 `rotation_orthonormality_err`，validate 要求 ≤1e-6。

旋转定义固定在工具主体，不能把活动指转角作为 TCP 坐标轴整体旋转。用至少三个不同腕姿验证实际接近方向/闭合方向，不能只依赖"看起来朝下"。

### 6.4 gap_table 和 angle_table

每个样本开度用卡尺/量块测量预定接触带内表面间距 gap_m；同一开度正反方向各重复至少 3 次，拟合严格单调 gap_table。某段非单调、指垫有过大迟滞或接触带变化时，缩小使用范围或重设计指垫，不强行排序 gap 数据消除物理问题。

测量活动指相对固定夹爪 link 的实际转角，换算成 URDF gripper 关节角后写 angle_table；它服务于碰撞 FK，与五姿态关节 IK 分开。使用经过验证的单调分段线性插值。两张表都在 **tool 阶段**由 `fit` 一并产出，不在 grasp 阶段。

验收：独立 TCP 中点、轴向和开口测量通过；预张/接触/释放的全部开度在两张表与 TCP 表覆盖范围的交集中。不得把常数旋转、关节零位、相机 yaw 偏移合并成第二个隐含修正。

## 7. workcell：固定几何、抓取域与配置放置位姿

payload 的公共键是 `entity_id、point_B_m[3]、q_urdf_deg[5]或null、gripper_pct或null、measurement_method、reference_image、fixture_id、measurement_uncertainty_m`，但 fit 按 `entity_id` 分流并要求额外键：

| 记录角色 | 判别键 | 额外必填键 |
|---|---|---|
| 桌面网格点 | `entity_id=="table"` | ≥9 个 `point_B_m` |
| 固定障碍 | 其它 `entity_id` | 每物至少 2 个角点，fit 取 AABB |
| 待机/中转位 | `waypoint_role`(`home`/`wp*`) | `q_urdf_deg`、`order`（中转位按 order 排序，K≥1） |
| 抓取域扫描 | `entity_id=="grasp_scan"` | `point_B_m`、`yaw_deg`、`ik_ok`（只有 `ik_ok=true` 的点参与 bounds） |
| 连杆胶囊 | `entity_id=="capsule_<id>"` | `capsule_id`、`link`、`p0_m`、`p1_m`、`radius_m` |
| 接触豁免 | `entity_id=="ignore_pair"` | `pair:[idA,idB]` |
| 放置点 | `place_id` | `point_B_m`（释放时物体中心）、`yaw_deg`；必须含 `default` |

1. 按 URDF 定义在实体基座上标出 +X/+Y，确认 +Z 竖直向上。在桌面至少测 9 个网格点，填 table_z_m 与最大高度偏离 table_flatness_m（fit 取 z 中位数与最大偏离）。桌面倾斜造成竖直路径净距不足时先调整安装。
2. 测量框壁、支架和固定夹具的外边界，生成 workspace.obstacles。用多个 AABB 表示容器的壁和底，内部留作放置空间。
3. 依据网格和实物构造 link_capsules，覆盖舵机、打印件、螺丝、活动指和指垫。活动指的位置按 angle_table 更新。人工核对几何覆盖及 ignore_self_pairs 的每个接触豁免。**胶囊体不是测量得到的，是按图纸/CAD 构造的**，fit 只做 id 有效性检查；`clearance_m` 与 `max_joint_substep_deg` 完全由人工定（1.4 的 C 类）。
   本机代码把"允许接触"的豁免范围从"仅指垫—目标"放宽为**整个 URDF 夹爪子树**（`safety.py:53` `GRIPPER_CONTACT_LINKS` = `gripper_link`/`gripper_frame_link`/`moving_jaw_so101_v1_link`），腕及以上连杆与目标仍须保持净距。核对 `ignore_self_pairs` 时按这个实际集合判断，别按"只有指垫可以碰"来核。
4. 用已确定的 grasp.yaw_offset_deg，在目标位置、yaw 和接触开度范围上扫描完整接近—抓取—提起路径，确定 target_bounds_m 与 tcp_bounds_m。`fit` 对 target_bounds 取 `ik_ok` 点的 2%/98% 分位数，对 tcp_bounds 则在 target_bounds 上**加硬编码 pad**（见 1.4），不是独立测量。保存扫描原始结果供视觉定义可抓取条件。视觉下发时已经满足这些条件；扫描与配置更新在标定阶段完成。**当前 `target_bounds_m` 运行期无人消费（2.6）**，控制模块不会替你拦越界目标。
5. 示教 home_joints_deg 和有序 safe_waypoints_deg，空载低速验证段间路线，再带规定测试负载验证。每段检查连杆与持物包络，不只检查 TCP 高度。示教前必须已完成第 5 节的零位拟合，否则会把占位换算出的假角度固化进配置（ISSUE-017）。
6. 测各放置位置，填写 places[place_id].position 与 yaw_deg。position 是释放时物体中心，需要根据支承面高度、物体高度和允许释放落差确定；yaw 按基座 +X 测量长轴角度。
7. 对每个 place_id 验证完整到达、下降、松爪和撤离路线，包含实际接触开度变化。APPROACH/TRANSFER 的竖直偏移使用 approach_height_m；抓取提起用 lift_height_m；释放撤离用 retreat_height_m。这三项高度**没有 fit 通路**，是人工确定项。

### 7.1 误差预算

用已知中心与长轴的标定物，核对视觉下发位置/角度与独立基座测量，填写 grasp.target_position_error_bound_m 与 grasp.target_yaw_error_bound_deg。该结果用于定位预算，控制不进行每次视觉查询。

目标包络使用 grasp.object_envelope_m；再按目标中心误差、目标角度造成的外缘位移、工具误差、运动模型/负载误差和 object_shift_bound_m 做膨胀。collision.clearance_m 是膨胀后仍须保持的最小净距。

相邻轨迹节点按 max_joint_substep_deg 加密；用关节角增量与点到关节轴最大距离估计节点间扫掠误差，并加入余量。减小采样步长检查结果是否稳定。几何净距不足时调整布置或允许工作域。

**CHECK 阶段的接触开度包络是离散检查的**：只验 `contact_gap_range_m` 的两个端点对应的包络，不连续扫全区间（`dev_logs/复审报告.md` §2 P1-4 已接受这个残余风险）。因此接触区间内部的包络异常需要靠 6.4 的 gap_table 单调性来保证，不能指望运行期发现。

### 7.2 放置点录入与验证

优先用独立尺具/定位板测出物体中心和长轴方向，也可使用已验证 TCP 的夹具示教。示教记录的是 TCP 时，按姿态文档的 T_TCP_O 换算成物体中心后写配置。

为每个 place_id 至少选三个不同抓取位置和多个实际接触开度完成实物试放，测量释放后物体中心与长轴误差。误差若随抓取位置变化，排查运动学/TCP；误差若随闭合程度变化，检查 TCP 插值与闭合位移界。配置中的位置和角度以同一基座定义保存，读入后生成 PlacePose。

## 8. timing：单线程调用的读写与停止时限

payload：`tick_index、deadline_ns、read_start_ns、read_end_ns、write_start_ns、write_end_ns、feedback_sequence、checkpoint_ns、sample_span_ns、stop_condition_ns或null、last_trajectory_write_ns或null、hold_submitted_ns或null、mechanically_still_ns或null、fault_injection`。

**本阶段不能用 `capture --hardware`**（第 3 节）：timing 需要真实同步规划与回放路径，实机记录由运行期日志导出为上述同格式 JSONL 后再 `fit`/`validate`。fit 要求 **≥1000 条 tick**，否则报错。

1. 在静止姿态下完整读回并提交保持目标，至少记录 1000 个 tick，统计读写的最大值和 P50/P95/P99。随后运行实际同步规划和回放路径，测量计算与 I/O 用时。
2. 用 Mock 注入通信错误，并在可控静止状态测量设备超时行为。**超时预算是分段落实的**：`read_timeout_s` 约束整次读方法（六台各一次 15 字节块读，共用同一个绝对 deadline，总时限不随台数倍增），`write_timeout_s` 约束整次写（一条 SYNC WRITE 帧），最坏合计为两者之和。核对 SDK 内部是否重新设置超时。Python + USB 串口不是硬实时，实际超时误差是分片粒度 + 调度延迟。
3. max_feedback_span_s 依据整次读回跨度确定；max_feedback_age_s 从 sample_start_ns 计算，不能只看读取结束时间。本机三次静止块读的实测跨度为 **3.80 / 3.85 / 6.32 ms**——这只是起点数据，样本量远不足，不能拿来定阈值。
4. 设置 should_stop 为按当前 monotonic 时间判断的测试回调；在规划、节点等待、运动、闭爪、到位等待各阶段触发，测从条件成立到停止提交轨迹/完成保持提交的延迟。测试回调本身不阻塞，不引入执行任务。fit 从 `mechanically_still_ns − stop_condition_ns` 求中位数作为停止延迟统计。
5. 测量单次底层 IK 调用的最长耗时，计入 planning_poll_s 与接受的停止延迟。规划检查点不能中断正在执行的底层调用；超出要求时需减少每次计算量或调整求解器调用方式。
6. stop_poll_s 控制 sleep 分片，取值不大于一个 tick；max_tick_lateness_s 小于一个 tick。超出迟到阈值必须停止，不补发积压节点。
7. 以外部录像/位置记录区分软件停止与机械实际静止。通信失败时记录保持未提交，不能将返回错误视作已经物理静止。

**应答等级会改变"写成功"的含义，本阶段必须记录。** 驱动在任何 WRITE 之前逐台读回 `Response_Status_Level`（vendor 表地址 8，纯 READ，不写 EEPROM）并据此配置策略：等级 0 = 全应答（等状态帧并校验 ERROR）；等级 1 = 只回读指令应答，**WRITE 只承诺"整帧提交给串口"，拿不到设备确认**；等级 2 = 全静默，初始化直接以通信错误失败。本机六台实测**全为等级 1**，属 Feetech 常见出厂配置、不是故障，但意味着每条写（含 `Goal_Position`、`Torque_Enable`）是否真的落盘只能靠事后读回反馈发现。本项目不做隐藏的 EEPROM 写入去改成等级 0。

验收：读写时限有效，正常周期可满足预算，各检查点的停止延迟满足 acceptance.max_stop_latency_s，函数返回后没有继续执行的循环。

## 9. motion：速度、跟踪与到位

payload：`trajectory_id、segment、command_deg[5]、feedback_deg[5]、speed_deg_s[5]、current_ma[5]、tcp_reference_B_m[3]或null、time_ns、gripper_pct、load_label、stop_reason或null、passed、direction`。

**同样不能用 `capture --hardware`**：motion 数据来自真实执行的路径日志导出。`passed`（该组参数是否通过）与 `direction`（正反向）是 fit 的分流键，别漏。

1. 在已标定空场从低速单关节短路径开始，逐步验证多关节路径。首次测试值由实机操作者根据设备允许范围设置，不能把示例值作为安全结论。
2. 对同一路径测试逐步增加的速度与加速度组合，每组正反方向重复；记录跟踪误差、振动、电流和到位时间。超出测试边界即停止。
3. 在实际夹持方向下加规定测试负载，覆盖远伸和不同运动方向。max_velocity_deg_s/max_acceleration_deg_s2 取通过范围内留有余量的值；TCP 速度/加速度同时按 FK 和外部测量验证。**fit 只从样本推关节两项**（`max_velocity = min(peak_ok, first_bad×0.85)×0.85`；`max_acceleration = |Δ²command|×0.85 + 50.0`）；`tcp_max_velocity_m_s`/`tcp_max_acceleration_m_s2` 是 draft 值的原样透传，**这句"按 FK 和外部测量验证"目前只能由人工完成**。
4. 设置 max_command_step_deg 不大于 max_velocity_deg_s/FPS；执行器仍检查实际差分速度与加速度。低速不能替代碰撞校验。
5. 分关节测量正常位置滞后、噪声和负载误差，确定 following_error_deg 与 dwell；hard 阈值依据可接受几何偏差和机构限制确定。`fit` 给的是 `P99(err)×2+3`，hard 再乘 2.2；`following_error_dwell_s` 写死 0.10。持续阈值不能大到掩盖卡阻。
6. 用静止噪声和重复到位数据选 settle_position_tol_deg、settle_velocity_tol_deg_s、settle_dwell_s 与 settle_timeout_s。fit 只解 `settle_position_tol_deg = P99(err)+1.0`，其余三项写死。Mock 中验证"停住但未到目标"必须失败。
7. 实测段起点偏差对路径的影响，确定 start_position_tol_deg；fit 写死 `[3.0]*5`。超过它时重新规划到同一目标或返回错误。
8. 合法关节 q 经 FK 构造数值测试目标，另用实际抓取域进行 IK 扫描，记录残差/耗时/失败原因。选择 ik 的容差、权重、迭代与停滞参数；数值容差须严于真实总定位误差预算。**目前三项容差是从 acceptance 乘系数推导、七项求解器参数完全没有 fit 通路**（1.4），所以这一条整条落在人工职责上。

验收：空载与测试负载下的定位、跟踪、到位与节拍通过；独立工具位姿误差满足 acceptance。规划与运动期间的反馈检查均由同步调用执行。

## 10. grasp：固定抓取参数与草莓接触试验

### 10.1 数据记录

使用最终供电、装配和指垫，准备规则假果、量块，以及覆盖允许尺寸和成熟度的真实草莓。

payload：`trial_id、object_id、cycle_phase、dimensions_reference_m[3]、maturity_label、pad_id、target_center_B_m[3]、target_yaw_deg、yaw_offset_deg、gripper_pct、gripper_current_ma、command_pct、time_ns、contact_label、actual_gap_m、actual_lift_result、actual_release_result、damage_label、damage_observe_minutes、image_refs`。时序样本中尚未产生的结果为 null，试验结束后保存 trial_summary。

**本阶段也不能用 `capture --hardware`**，且 fit 依赖以下判别键，缺一项就报"缺少…记录"：

| 用途 | 判别 | fit 产出 |
|---|---|---|
| 空爪闭合循环 | `cycle_phase=="empty_close"` | `empty_closed_pct`(P95)、`empty_tol_pct`(std+1.0) |
| 首次接触 | `contact_label=="first_contact"` 且带 `actual_gap_m` | `contact_gap_range_m` = min/max ∓0.001 |
| 接触前后电流 | `contact_label=="before"/"after"` | `contact_current_ma`、`hard_current_ma`(×2) |
| 试验汇总 | `record_type=="trial_summary"`，带 `contact_center_offset_object_m`、`grasp_yaw_offset_deg`、`dimensions_reference_m` | `center_offset_object_m`、`yaw_offset_deg`、`preopen_pct`、`release_pct` |
| 闭合位移 | `center_shift_m`（录像/标记点直接测得的中心位移，**模拟源不产出，必须人工记录**）或退回 `slip_drift_pct` | `object_shift_bound_m` |
| 持物漂移 | `slip_drift_pct` | `slip_opening_change_pct` = P99×2+1 |

人工观察和影像用于标定验收，不成为运行期视觉通信步骤。

### 10.2 固定开度与接触阈值

1. 测量适用草莓最大长/宽/高，写 object_envelope_m；按固定 yaw_offset_deg 计算闭合轴宽度，并以量块与真果确认实际接触带。
2. 根据 gap_table 选择覆盖该宽度且有适当净余量的 preopen_pct；验证接近时指垫不触碰邻物或桌面。选择能稳定释放且不碰固定环境的 release_pct。`fit` 的净余量是 `max(0.10×宽度, 0.003)`，释放只用半个余量；预张超过 gap_table 覆盖上限会直接报错并要求换指垫或缩小适用尺寸。
3. 空爪在预定速度下开合至少 20 次，完整记录启动、摩擦、空闭合端的电流与开度，确定 empty_closed_pct、empty_tol_pct 及开合超时。**开合超时目前 fit 写死 6.0**，"按实测开合时间放大"要靠人工把实测值写回去。
4. 用量块/假果初测接触开口，再用草莓低速小步闭合。记录首次接触的实际 gap 与电流，将经过验证的接触 gap 最小/最大值及测量余量写入 contact_gap_range_m。该区间须与空闭合端可区分（加载期会硬检查，见 2.4）。
5. 根据数据选择 window_samples、contact_current_ma、contact_dwell_s。把滤波、连续确认、读写和一个 tick 的延迟乘 close_speed_pct_s，估算额外闭合量，再用 gap_table 换算压缩距离。超出允许压缩量时降低速度或检测延迟。`fit` 会把这个估算写成 `_calibration_note_extra_close_pct` / `_calibration_note_extra_compression_m`，**但它们只进 `.audit.json` 边车、不进配置**——也就是说这份"额外闭合量"是给你看的提示，不是被代码执行的约束；`window_samples`/`contact_dwell_s`/`open_speed_pct_s`/`close_speed_pct_s` 四项本身仍是纯人工参数，改它们来消解这份提示之后需要重跑本阶段。
6. hard_current_ma 比较未滤波电流，结合设备限制与真实草莓试验设置。`fit` 恒取 `contact_current_ma×2.0`。若正常运动和接触电流无法可靠区分，则改进指垫或缩小适用范围后重测。**本机六台 WRITE 无应答（第 8 节实测等级 1），闭爪是否真的写进去本来就只能靠电流+开度反馈推断，因此本条与第 4 条的实测质量直接决定抓取可靠性。**
7. 接触判据成立即保持实际开度；设置 hold_dwell_s 检查开度与电流稳定性。测量持物期间的正常开度漂移，确定 slip_opening_change_pct；其作用是异常提示。
8. 张开到 release_pct 后，根据果实脱离行为确定 release_dwell_s；采用独立观察验证，正常代码只检查开度/速度及等待时间。

接触、预张开和释放的全部开度须落在 TCP/gap/angle 表共同覆盖区间内；超出表范围则补测，不能外插。

### 10.3 抓取偏移与高度

1. 用目标几何中心作为基准选定指垫接触带，测量并试验 center_offset_object_m；偏移写在物体坐标系中。
2. 在标定实验中确定一个可用的 yaw_offset_deg，验证该方向下的空间、接触稳定性和允许目标域。运行期固定使用这个值。采用单动指夹爪时 theta 与 theta+180° 的实际接触几何可能不同，配置方向即执行方向。
3. 在多个尺寸、目标位置和物体 yaw 下，测闭合前后物体中心移动，最大值加测量余量写 object_shift_bound_m。**必须真的记 `center_shift_m`**，否则 fit 会退回用 `slip_drift_pct × gap_table 斜率` 的保守换算，两者都不记时它干脆不写这个字段。
4. 测 approach_height_m、lift_height_m 和 retreat_height_m，使完整连杆/工具/持物包络脱离桌面和固定障碍。高度沿基座 +Z 定义。三项全部是人工确定（1.4 的 C 类）。
5. 固定参数后测试不同目标位置到各配置放置点的搬运和松爪，记录掉落、位姿误差和损伤。需要改变指垫/偏移/速度时，重新验证受影响阶段。

## 11. pick_place：完整同步调用验收

payload：`trial_id、profile_parameter_sha256、target_position_m[3]、target_yaw_deg、grade、place_id、began_descend、start_ns、end_ns、software_status、software_stage、holding、recovery_required、actual_success、actual_drop、actual_place_position_m[3]或null、actual_place_yaw_deg或null、place_error_center_m、place_error_yaw_deg、feedback_span_s、stop_latency_s、damage_label、damage_observe_minutes、image_refs`。

`began_descend` 是分母来源，`place_error_center_m`/`place_error_yaw_deg` 是 validate 用来核对落位误差的键。模拟源会把 `profile_parameter_sha256` 写成 `"not-bound-here"` 且代码不校验试验与参数的绑定，**实机数据必须自己填当前配置的 parameter_sha256**，否则这一阶段记录无法证明是针对被验收的那份参数。

用未参与调参的样本完成不少于 acceptance.min_grasp_trials 的独立试验；覆盖允许抓取位置/方向、实际接触开度与全部 place_id。视觉下发一次目标后运行一次完整同步调用，记录软件返回结果并独立观察实物结果。

分别统计：

- 软件完成率：返回 SUCCESS 次数 / 开始 DESCEND 的次数。
- 实际成功率：物体实际抓起并放到配置位置的次数 / 开始 DESCEND 的次数。
- 掉落率：非预期掉落的次数 / 开始 DESCEND 的次数。
- 损伤率：按规定时间完成观察的果实中损伤数 / 已完整观察果实数；另列观察缺失数。
- 放置中心/长轴误差、单次耗时、反馈跨度、软件停止及机械静止耗时。

**`fit --stage pick_place` 不写任何字段，也不产生残差**（`calibrate.py:1742`）。上表全部统计由 `validate` 从 JSONL 直接算并与 acceptance 比较，所以这一阶段没有"先 fit 再 validate"的余地：只有 capture(日志导出) → validate。另需知道两个实现局限：损伤率的分母是"该行的 `damage_observe_minutes` 为真值"的行数，而配置里的 `acceptance.damage_observe_minutes` 从未被用来判观察是否达标（2.6）；模拟源的 pick_place 数据是按"能通过验收"造的，绿色 `--stage all` 报告在 mock 下是构造结果，不是测量结果。

软件返回与实际结果不一致时保留误差案例，不自动将电流正常等同于物体实际成功。acceptance.min_grasp_success_rate 针对实际成功率。

故障试验覆盖错误输入格式、缺失 place_id、IK 不收敛、轨迹越限、抓空、开合超时、反馈过期、通信失败和 should_stop。使用 Mock 的项目明确标注，真实夹持与损伤验收使用实物数据。

必要离线检查：

1. 字段、shape、非有限值、未测参数、资源哈希和配置模式校验；draft 在 real/mock 两条链上都必须被拒，采集链必须仍可用。
2. 正反方向的关节与夹爪映射往返；open_raw<closed_raw 正确处理；分母为零失败。
3. URDF rad→deg 只发生一次，有效限位空交集失败；示教位姿越限在加载期即失败。
4. TCP/gap/angle 表端点、中点、非单调数据、范围外开度与插值误差；三表共同覆盖区间的交为空时必须失败。
5. 配置 places 的位置/角度直接转换为 PlacePose，品级不改变所选 place_id。
6. 用同一原始日志通过生产换算函数重建 JointFeedback，与采集时保存的物理量在量化容差内一致。
7. 规划、回放、开合与等待均顺序执行；停止后不再提交动作节点，函数返回后不继续执行。
8. `scripts/calibrate.py init→capture→fit→validate→promote` 全链在无真机上可跑通；`fit` 的候选必须恒为 draft，`.audit.json` 边车的 `updated_fields` 应与 1.4 的分级表逐字段对得上——**这张对照表是发现"某字段悄悄被 fit 写了常数"的最快手段**。

### A.2 已证明与实机冲突（阻断级，必须优先处理）

1. **`status` 与 `verification` 矛盾**：现为 `verified` 但 `verification: null`，real 被哈希/报告关卡拒、mock 被 `status≠simulation` 拒，**两种模式当前都加载不了**。应退回 `draft`（不影响采集），走完八阶段后由 `promote` 写回（ISSUE-004）。
2. **`motor.gripper_closed_raw=500` / `gripper_open_raw=3600` 是仿真值**，真机官方行程是 `[1458, 2980]`：0%、3%、100% 换算出的 raw 全部越界被 4.2 硬闸拒绝，夹爪开不到也闭不到。连带 `gripper.gap_table` 的斜率假设失效（见 4.4）。无 fit 通路，**只能人工测**（ISSUE-003/017）。
3. **`joints.sign=[1]*5` / `zero_offset_deg=[0]*5` 是仿真值，已被实机证伪**：静置即有两关节越出配置有效限位（−102.68° / +99.47°）。拟合前应把这两项改回 `null`，让 5 节描述的既有保护生效（ISSUE-008/017）。
4. **`motor.current_ma_per_raw=[1.0]*6`、`motor.velocity_deg_s_per_raw=[3.0]*6` 的基准已失效**：原按固件 2.54 资料取，实机为 3.10，需按 3.10 手册重取（ISSUE-015 下游）。
5. **标定包缺 `raw/` 与 `reports/` 目录**，任何 `capture` 都会因目录不存在失败；`drive_mode` 全 0 与仿真原件模式不同，需与官方原始输出逐字段比对（ISSUE-006/011）。
6. **`Present_Current` 按无符号解码**尚未从 3.10 手册确认（4.3）。
7. **`workspace`/`collision`/`places`/`tool`/`motion`/`ik`/`gripper`/`timing`/`acceptance` 各组当前仍是仿真副本**：与仿真 profile 摊平后有 **110 个字段完全相同**，即所有物理量都还是占位值。第 3 节顺序推进时逐组替换，不要假定"fit 跑过就是测过"（1.4 的 B 类）。
