## 一、模块定位与边界

运动控制模块是"视觉感知"与"电机执行"之间的桥梁：

```
1号 视觉 (VisionInterface: 基座系 xyz + yaw + 品级)
        │
        ▼
┌─────────────────────────────────────────────┐
│  2号 运动控制 (qingyun/grabbing/arm_control) │
│                                             │
│  技能层   grasp_and_place                   │
│  规划层   Plan: 段序列 → 关节轨迹数组        │
│  校验层   Validate: 限位/步长/FK回放         │
│  回放层   Play: 30Hz 查表下发 + 监控         │
│  运动学   FK/IK (vendor: placo + URDF)       │
└─────────────────────────────────────────────┘
        │  MotorController Protocol（同进程函数调用）
        ▼
3号 电机驱动 (qingyun/grabbing/motor_control)
        │  Feetech 总线协议 (/dev/ttyACM0)
        ▼
     STS3215 × 6
```

**职责边界**：

| 归属 | 职责 |
| :--- | :--- |
| 本模块（B） | 运动学正逆解、工作空间与步长约束、轨迹规划与校验、抓取编排、回放监控、软件急停（freeze）、时钟节拍 |
| 上游（A） | 手眼标定外参的持有与维护，输出基座系坐标 |
| 下游（C） | 串口驱动、软限位最后一道钳位、反馈回读、硬件供电与物理急停 |
| 上层（方案库/状态机） | 品级→放置点映射、抓取失败后的重试策略 |

**设计原则**：语义决策与实时控制解耦；所有失败尽量发生在 t=0（臂静止时），而非半空中。

## 二、代码目录结构

在 readme.md 工程结构基础上，本模块涉及的部分完善如下（其余成员的文件保持原结构不动）：

**结构决策说明**：

1. **vendor 与自研分离**：`libs/so_arm_core/` 只放原样搬运的上游文件（kinematics.py、URDF），同步上游升级时整个目录可整体替换；本模块的重写逻辑全部放 `qingyun/` 下。lerobot 的 `robot_kinematic_processor.py` 中的 ProcessorStep 逻辑不照搬框架（其依赖 lerobot.processor 整套注册表/特征变换体系，服务于"数据集采集→策略训练"流水线，本项目无此流水线），只摘取数学内核重写为普通函数。
2. **测试独立成目录**：Mock 驱动 + pytest + 可视化脚本集中管理，开发机上运行，不依赖真机与串口。
3. **`kinematics_ext.py` 的存在理由**：把"对 vendor 运动学内核的薄封装"（delta 位姿计算、工作空间裁剪、软约束求解、限位读取）与"控制器"（时钟、状态、编排）解耦，前者可纯函数化单测，后者依赖注入电机。
4. **配置两分法**：结构真值（关节限位）由代码从 URDF 程序化读取，不进配置文件；真机特性参数（边界盒、阈值等）集中 `configs/motion_params.py`，每个数值附来源注释。

## 三、整体功能架构：Plan-Validate-Play

一次抓取运动分为三阶段。核心思想：**目标位姿在运动开始前即完全已知，因此把一切计算量与失败可能性前移到 t=0（臂静止时），回放阶段只做查表与监控**。

```
grasp_and_place(target, place_pose)
        │
        ▼
┌─ Plan（运动前，无实时约束）─────────────────────────┐
│ 抓取编排 → 段序列：                                  │
│   [关节空间] 移到目标上方预抓取点（S 曲线）           │
│   [笛卡尔]   垂直下潜到抓取点（直线插值）             │
│   [夹爪]     闭爪（电流闭环，运行时在线）             │
│   [关节空间] 提拉到安全高度                          │
│   [关节空间] 搬运到放置点上方                        │
│   [笛卡尔]   垂直下放置（yaw 对齐）                  │
│   [夹爪]     松爪                                    │
│   [关节空间] 撤回待机位                              │
│ 每段展开为 30fps 关节角数组，链式 warm-start IK；     │
│ 整条轨迹拼接为一个稠密数组 + 段边界索引               │
└──────────────────────────────────────────────┬──────┘
                                               ▼
┌─ Validate（仍在运动前，臂静止）─────────────────────┐
│ ① 关节限位：每帧 q ∈ URDF limits（程序化读取）       │
│ ② 单帧步长：|Δq| ≤ 0.5°/帧（@30Hz = 15°/s）         │
│ ③ FK 回放：对每个解出的 q 做 FK，与路点误差 < 容差   │
│ 任一不通过 → 拒绝整条轨迹，返回上层（臂未动）        │
└──────────────────────────────────────────────┬──────┘
                                               ▼
┌─ Play（30Hz 实时循环，单线程）──────────────────────┐
│ i = int((now - t0) * fps)      # 绝对时间索引        │
│ send_action(q[i])              # 非阻塞写串口        │
│ 读反馈 → |实测-指令| > 5° → freeze + abort          │
│ 段边界处 wait_settled(timeout, tol)                 │
│ 闭爪段：唯一真在线闭环（电流阈值柔抓，见下）          │
│ stop 标志位由 watchdog/主线程置位 → 循环退出         │
└──────────────────────────────────────────────┘
```

### 为什么不是逐帧在线 IK（30Hz 流式闭环）

该模式（lerobot 遥操作架构）适用于目标每帧不可预知的场景（人类 leader 随动）。本项目为自主抓取，视觉给出目标时整条轨迹已知，逐帧在线 IK 的实害：

1. 中途 IK 失败时臂处于半空中的未定义状态，除 freeze 外无体面退路。
2. RK3588S 上与 YOLO 推理共享 CPU，30Hz 截止期内塞 1–5ms 的 IK 迭代，deadline 命中率不可控。
3. 总线预算浪费：规划可离线做，实时循环内只需查表。

逐帧流式闭环保留为**遥操作模式**（创新点四主从协同）的预留路径，与自主模式共享同一运动学内核。V1 只实现自主模式。

### 闭爪段：唯一真在线闭环

闭爪无法离线规划——夹多紧取决于果实尺寸与软硬。实现：闭爪指令下发后，循环读夹爪电流与开合度反馈，电流达到阈值（实测定）立即锁定开合度停止加压（"轻柔抓取、零损伤"）；开合度提前到底且电流未升 = 抓空（GRASP_MISS）。

## 四、各文件功能与技术原理

### 4.1 `libs/so_arm_core/kinematics.py`（vendor，不改）

lerobot 0.5.1 的 `RobotKinematics` 类，placo 库的薄封装：

- **FK**：`forward_kinematics(joint_pos_deg) -> 4×4 T`。原理：关节角（度→弧度）写入 URDF 关节模型 → 更新运动学树 → 读末端系（`gripper_frame`）变换矩阵。
- **IK**：`inverse_kinematics(current_q_deg, T_desired, pos_w=1.0, ori_w=0.01) -> q_deg`。原理：加权软约束优化——把"末端到达 T_desired"表达为位置误差与姿态误差的加权平方和最小化（placo KinematicsSolver 的 frame task，"soft" 配置），以 current_q 为初值迭代。位置高权重、姿态低权重 = 优先保证到达性，姿态"尽力满足"。
- **依赖**：仅 `placo`（PyPI 有 aarch64 wheel，`pip install placo` 直接装香橙派）+ `numpy`。备胎方案：若 placo 不可用，换 `pin`（Pinocchio），wrapper 改动量小。

### 4.2 `libs/so_arm_core/so101_new_calib.urdf`（vendor，不改）

SO-ARM100 官方 SO-101 新标定版 URDF。选型依据：真机为按开源文件标准打印组装的 SO-101；该版含 `base_link` 与 `gripper_frame_joint`（末端参考系，老版 calib 无此关节）；关节限位真值（shoulder_pan ±110°、shoulder_lift ±100°、elbow_flex ±96.83°、wrist_flex ±95°、wrist_roll −157.21°~+162.79°、gripper −10°~100°）由校验器程序化读取。前提：3 号舵机零位标定走 lerobot/SO-ARM100 官方校准流程，URDF 标定值与真机对齐。

### 4.3 `configs/motion_params.py`

真机特性参数集中地，每个数值附来源注释。初始值（全部待真机标定覆盖）：

| 参数 | 初始值 | 来源/依据 |
| :--- | :--- | :--- |
| `WORKSPACE_BOUNDS` | 待真机测绘（以标定顶抓位为中心的边界盒） | 视觉目标必须在盒内才接受规划 |
| `MAX_JOINT_STEP_DEG` | 0.5°/帧 @30Hz（=15°/s） | 慢而稳；肩关节满行程 0.75s，够分拣用且温柔 |
| `REPLAY_DEVIATION_DEG` | 5° | 超过舵机正常滞后+柔性变形范围 = 卡阻 |
| `GRASP_CURRENT_MA` | 实测（空闭/闭合/夹梨三条电流曲线取中） | 无理论值，必须实测 |
| `SETTLE_TOL_DEG / SETTLE_TIMEOUT_S` | 1° / 0.5s | 段间静止判据 |
| `FPS` | 30 | 控制流节拍 |
| `R_TOP_DOWN / YAW_OFFSET_DEG` | 标定脚本产出 | 见《顶抓姿态构造与R_top_down标定.md》 |

关节限位**不在此文件**——由 `ArmController.__init__` 从 URDF 程序化读取（结构真值跟 URDF 走）。

### 4.4 `configs/common_interface.py`（增量）

现有 `VisionInterface` 保持冻结。本模块新增两块契约：

- `MotorController` Protocol（B→C 接口，见第五节；3 号的 `motor_control.py` 与 `tests/mock_motor.py` 都实现它）。
- `JointFeedback` / `GraspResult` / `PlacePose` 等数据类（见第五节）。
- 给 `VisionInterface.position` 补注释：`# in base_link frame (m)`；`yaw_deg`：水平面内相对目标摆放姿态的偏航角（deg）。

### 4.5 `qingyun/grabbing/kinematics_ext.py`（重写自 lerobot ProcessorStep）

lerobot `robot_kinematic_processor.py` 的数学内核，剥掉 ProcessorStep 注册表/特征变换框架，重写为纯函数。三组函数：

**`apply_delta_pose(ref_T, dx, dy, dz, wx, wy, wz, step_sizes) -> T`**（源自 `EEReferenceAndDelta`）
增量位姿计算：参考位姿上叠加末端增量。平移按步长缩放 `p_d = p_ref + Δ·s`；姿态用旋转向量映射 `R_d = R_ref · exp([ω]∧)`（`Rotation.from_rotvec`）。服务于遥操作模式（V2 预留）。

**`clip_workspace(p_desired, bounds, last_p, max_step_m) -> p_clipped or None`**（源自 `EEBoundsAndSafety`）
两级安全约束：工作空间边界盒裁剪 + 单步位移限幅（相邻时刻位移超阈值按比例缩放）。返回 None 表示完全越界。抑制视觉识别跳变、上层指令异常导致的末端跳变。

**`solve_ik(kinematics, q_init, T_desired, pos_w, ori_w) -> q or None`**（源自 `InverseKinematicsEEToJoints`）
软约束 IK 求解薄封装：构造 4×4 目标 → 调 vendor `inverse_kinematics` → FK 复核误差 < 容差才算成功，否则 None（防"求解器声称收敛但实际偏了"）。初值策略（闭环：实测角；开环：上一解）由此函数的调用方（规划器）决定。

另含 **`top_down_pose(xyz, yaw_deg, R_top_down, yaw_offset_deg) -> T`**：构造 `R = Rz(yaw + offset) · R_top_down` 的目标位姿（顶抓+偏航恰定策略，详见配套文档）。

### 4.6 `qingyun/grabbing/arm_control.py`（核心）

`ArmController` 类，依赖注入 `MotorController`（真驱动或 Mock，可切换）。内部四个子组件 + 一个技能入口：

**① 段规划器（Plan）**
- 关节空间段：`plan_joint_segment(q_start, q_end, duration)` —— 五次多项式 S 曲线 `s(t) = 10t³ − 15t⁴ + 6t⁵`，s(0)=0、s(1)=1、首末端速度与加速度为零（缓起步→匀速→缓停，jerk 受限，防甩飞果实）。逐帧 `q(t) = q_start + (q_end−q_start)·s(t)`。
- 笛卡尔段：`plan_cartesian_segment(p_start, p_end, duration)` —— 位置直线插值（同一 s(t) 时间律）+ 顶抓姿态（R_top_down 常数）+ yaw 对齐；每个空间路点链式 warm-start IK（第 k 个路点用第 k−1 个解作初值，保持在同一 IK 分支，避免奇异点空中翻转）；任一路点解算失败 → 规划失败，前移到 t=0。
- 夹爪段：`plan_gripper_segment(action)` —— 闭爪段不展开为位置数组（电流闭环在线执行），松爪段直接展开。

**② 校验器（Validate）**
纯函数检查整条拼接后的关节轨迹数组：URDF 限位（每帧）、单帧步长（相邻帧差）、FK 回放（对笛卡尔段的每个解做 FK，与空间路点误差 < 容差）。返回 `ValidationResult(ok, reason)`——拒绝时臂尚未动。

**③ 回放器（Play）**
单线程 30Hz 循环，绝对时间驱动：`t0 = time.monotonic()`，帧号 `i = int((now − t0) · fps)`（掉帧时直接跳到正确帧，不排队重放，不累积漂移）；每帧 `sleep(max(0, t0 + i/fps − now))` 对齐绝对节拍。帧内动作：`send_action(q[i])`（非阻塞）→ 读反馈比对偏差（>5° → freeze + abort）→ 检查 stop 标志位。段边界处 `wait_settled`（循环读反馈直到角度变化率 < 阈值或超时，消除惯性余振）。闭爪段走专用电流闭环子循环。

**④ 技能层：`grasp_and_place(target: VisionInterface, place_pose: PlacePose) -> GraspResult`**
编排"接近→下潜→闭爪→提拉→搬运→放置→松爪→撤回"全流程为段序列，交给 ①②③ 执行。一次抓取 = 一次 Plan-Validate-Play，原子操作。
- 抓空检测归本层：闭爪后开合度到位但电流未升 = GRASP_MISS。
- 重试决策归上层：本层不重试，返回 `GraspResult` 枚举（SUCCESS / GRASP_MISS / GRIP_SLIP / PLACE_FAIL / ABORTED），上层（V1 为 main.py 循环）决定重试或换目标。
- V1 放置位置：place_pose 由方案（上层）硬编码给出，本层不持有品级→放置点映射。

**⑤ 急停：`emergency_freeze()`**
软件急停 = freeze：停止接受新轨迹，把当前实测角度作为目标持续下发，臂僵在原地（保护现场与机械，不切力矩——避免举着梨时失力砸落）。物理急停按钮由 3 号接入舵机供电回路直接断电，不经任何软件。恢复需人工确认 + 显式调用，禁止自动恢复。

**原语层 API**（技能层之下，同样导出，供调试与上层组合）：

```python
move_cartesian_top_down(xyz: np.ndarray, yaw_deg: float, duration: float)  # 笛卡尔垂直直线（顶抓+yaw）
move_joints(q_target_deg: np.ndarray, duration: float)                      # 关节空间 S 曲线
open_gripper() / close_gripper()                                            # 后者含电流闭环柔抓
wait_settled(timeout_s: float, tol_deg: float) -> bool
emergency_freeze()
```

### 4.7 `tests/mock_motor.py`

Mock 电机驱动，实现 `MotorController` Protocol。**关键设计：仿真一阶位置滞后**——`get_feedback()` 返回"上次下发角度按时间常数 τ≈100–300ms 一阶趋近"的值（模拟 STS3215 响应速度），而非 `feedback == command` 的假 Mock。理由：`wait_settled` 逻辑、回放偏差阈值、闭爪电流上升沿检测都依赖"反馈落后于指令"的事实，假 Mock 会让全部阈值调参作废。闭爪电流仿真：开合度随位置趋近目标而电流按剩余行程比例上升，夹住目标（行程提前受阻）时电流持续上升——让抓空/夹稳两种情形可测。

### 4.8 `tests/test_kinematics.py` / `tests/test_trajectory.py` / `tests/plot_trajectory.py`

五项测试套件（pytest，开发机运行，不碰真机）：

1. **FK/IK 往返性质**：工作空间内随机采样位姿 → IK → FK → 位置误差 < 0.5cm、姿态误差 < 1°。
2. **S 曲线性质**：s(0)=0、s(1)=1、首末端速度与加速度为零（数值差分验证）。
3. **校验器测试**：构造越限位轨迹、跳变轨迹 → 必须在 t=0 拒绝；合法轨迹必须通过。
4. **回放器测试**：注入 Mock 时间跳变（模拟 CPU 被抢占）→ 绝对时间索引不丢帧、不累积漂移。
5. **末端轨迹可视化**（plot_trajectory.py，matplotlib）：FK 回放全程末端 xyz 曲线，下潜段必须为直线——答辩展示用。

### 4.9 `main.py`（V1 形态）

装配：实例化 MotorController（真驱动/Mock 开关）→ 注入 ArmController → V1 任务循环 = while 循环取视觉目标 → `grasp_and_place(target, place_pose)` → 按 GraspResult 决定重试/换目标/终止。品级→放置点映射的硬编码表放这里（上层领地，不放 arm_control）。

## 五、接口设计

### 5.1 三层接口总览

| 边界 | 契约位置 | 内容 |
| :--- | :--- | :--- |
| A → B | `VisionInterface`（冻结） | 基座系 xyz（m）+ 水平面 yaw（deg）+ 品级字符串 |
| B → C | `MotorController` Protocol（冻结） | 同进程函数调用，四个方法 |
| B → 上层 | `ArmController` 公有方法 | 原语层 + 技能层 |

### 5.2 B → C：`MotorController` Protocol（`common_interface.py`）

```python
from typing import Protocol, runtime_checkable
import numpy as np

@dataclass
class JointFeedback:
    angles_deg: np.ndarray      # shape (6,)，关节角，含 gripper
    speeds_deg_s: np.ndarray    # shape (6,)
    currents_ma: np.ndarray     # shape (6,)

@runtime_checkable
class MotorController(Protocol):
    def send_action(self, joints_deg: np.ndarray, gripper_pct: float) -> None:
        """非阻塞：写入串口缓冲立即返回。内部先做关节行程软限位钳位（最后一道闸，源自
        lerobot motors_bus 标定范围钳位），禁止内部 sleep。joints_deg 为 5 个姿态关节角(deg)。"""

    def get_feedback(self) -> JointFeedback:
        """同步读 6 舵机角度/速度/电流。总线耗时约 10ms（1M 波特率同步读写），30Hz 节拍内富余。"""

    def wait_until_settled(self, timeout_s: float, tol_deg: float) -> bool:
        """阻塞等待所有关节静止（角度变化率 < tol），超时返回 False。"""

    def emergency_stop(self) -> None:
        """freeze：以当前实测角度持续下发，锁定输出。"""
```

约定：**时钟节拍（30Hz 循环、绝对时间对齐）归 B**；软限位最后一道钳位与急停原语归 C；串口 I/O 在 C 内部同步完成（一个 tick 内 send+read ≈ 10ms，无性能瓶颈，不引入线程/进程）。B 对 Protocol 编程，`motor_control.py`（真）与 `mock_motor.py`（测）可互换，`main.py` 一个开关切换。

### 5.3 A → B：`VisionInterface`（沿用冻结契约，补语义注释）

```python
@dataclass
class VisionInterface:
    position: np.typing.NDArray[np.float64]   # 基座系(base_link)坐标，单位 m
    yaw_deg: float                            # 水平面内相对目标摆放姿态的偏航角，deg
    grade: str                                # "A+" / "A" / "B" / "C"(不合格)
```

手眼标定外参由 1 号持有维护，本模块只收基座系坐标。品级→放置点映射归上层，本模块不解释品级语义。

### 5.4 B → 上层：`ArmController`

```python
class ArmController:
    def __init__(self, motor: MotorController, urdf_path: str, params: MotionParams): ...

    # ---- 技能层（V1 上层主入口）----
    def grasp_and_place(self, target: VisionInterface, place_pose: PlacePose) -> GraspResult: ...

    # ---- 原语层 ----
    def move_cartesian_top_down(self, xyz, yaw_deg, duration) -> None: ...
    def move_joints(self, q_target_deg, duration) -> None: ...
    def open_gripper(self) -> None: ...
    def close_gripper(self) -> GraspResult: ...    # 电流闭环柔抓，含抓空检测
    def wait_settled(self, timeout_s, tol_deg) -> bool: ...
    def emergency_freeze(self) -> None: ...
```

`PlacePose`：放置目标（xyz + yaw，顶抓语义）。`GraspResult`：`SUCCESS / GRASP_MISS / GRIP_SLIP / PLACE_FAIL / ABORTED`。检测归 B（有反馈数据），重试归上层（任务级决策）。

### 5.5 时序图：一次抓取的 B/C 协作

```
B: Plan   ── 纯计算，无 C 参与 ──────────────────────
B: Validate ── 纯计算，无 C 参与 ────────────────────
B: Play   ┌────────── 30Hz 循环（绝对时间）──────────┐
          │ send_action(q[i])  →  C: 软限位钳位→串口写 │
          │ get_feedback()     ←  C: 同步读 6 舵机     │
          │ 偏差>5° → C.emergency_stop() + abort      │
          │ 段边界 → wait_until_settled()             │
          │ 闭爪段：循环读电流，达阈值锁定开合度        │
          └───────────────────────────────────────────┘
```

## 六、关键技术决策索引（本次讨论共识）

| # | 决策 | 要点 |
| :--- | :--- | :--- |
| 1 | IK 引擎 | vendor lerobot `RobotKinematics`（placo），不引入 lerobot 全家桶 |

| 7 | 测试策略 | 一阶滞后 Mock + pytest 五件套；真机是最贵资源，Mock 先行 |
| 8 | 技能封装 | grasp_and_place 整体封装；检测归 B，重试归上层 |
| 9 | 运动学模型 | so101_new_calib.urdf；零位标定走官方流程（URDF 与真机对齐前提） |
