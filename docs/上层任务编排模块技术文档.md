## 一、总体流程与状态机

单线程、同步、阻塞。无任何并发；与运动模块的同步执行哲学一致。

```
冷启动（§8）
  → WAITING        silero VAD 无限等待语音触发
  → TRIGGERED      起表 30s；≥1s 连续静音→ENDED / 超时→丢弃回 WAITING
  → ASR            云端转写；空串→回 WAITING；硬失败→terminate
  → LLM            选方案 {"task": "strawberry"|"invalid"}；"invalid"或两次违约→回 WAITING；硬失败→terminate
  → PLAN           实例化 qingyun/plans/ 对应方案模块，run() 拥有完整视觉-抓取循环
  → 完成           仅 3×NoTarget（D14）→ 打印"任务完成" → 回 WAITING（新任务重新实例化，计数器重置）
```

任务完成不退出程序。程序唯一的正常出口不存在：所有终止路径都走 `terminate()`（§7）。

## 二、模块职责与签名

```python
# asr.py —— silero VAD 状态机 + 16k mono 重采样 + 云 ASR
def listen_and_transcribe() -> str
#   返回空串 = 无有效语音（含 30s 超时丢弃），统一不区分，区分只进日志
#   抛 ASRHardError → 云 API 硬失败 → terminate

# cloud_model.py —— prompt.md 组装 + LLM 调用（JSON mode）+ 解析 + 违约重问
def select_plan(text: str) -> str
#   返回 "strawberry"|"blueberry"|"invalid"，按字符串比对（与 prompt.md 示例一致）
#   "invalid"（无意义文本）→ main 回 WAITING
#   违约（非法输出）：新开上下文原样重发一次；再违约 → 回 WAITING
#   抛 LLMHardError → terminate
#   prompt.md 启动时加载一次，运行期不重读

# qingyun/grabbing/vision.py —— 视觉单体（YOLO+RGB-D 眼在手外；import 同进程，不 import 上层/运动）
class NoTarget(Exception): ...        # ROI 无物体 / 全部候选被过滤 / ignore 跳尽
class VisionHardError(Exception): ... # 相机断开/帧读取失败/检测管线崩溃 → terminate
def init() -> None
#   main 冷启动段调用；YOLO 模型一次性加载（不懒加载、不放 import 时）
def get_target(ignore: int = 0) -> VisionInterface
#   前置条件：机械臂在 home 位姿（运动 RETURN 阶段天然维持）
#   一次调用 = 一次完整采集-检测管线，无跨调用缓存（本体内部多帧融合不受限）
#   返回可抓候选按确定性排名（邻距最大→ROI 中心→position 字典序）的第 ignore+1 个
#   返回值携带 valid_count（当次合法候选总数）；ignore ≥ valid_count 的调用必跳尽，plan 以此封顶（§6）
#   无目标一律抛 NoTarget（不返 None）；每次调用日志：候选数 + 逐项拒绝原因（伪"任务完成"的唯一审计手段）

# shutdown.py（原 watchdog.py，按功能改名）—— 所有退出的唯一出口
def terminate(status: str, detail: str) -> NoReturn
#   打印状态/阶段/原因 + 现场指引 + sys.exit(1)；注册 atexit 兜底

# qingyun/plans/ —— 方案模块（每方案一个实现，共享基类）
class Plan:
    def __init__(self, arm: ArmController) -> None
    #   arm 实例由 main 创建并传入；落点映射在构造时从自身逻辑加载
    def run(self) -> None
    #   完整循环：get_target() → grade 判定（plans 内部）→ next_place_id(grade)
    #     → grasp_and_place(target, place_id) → 失败分发（§6）
    #   仅 3×NoTarget 正常返回 = 任务完成；ignore 封顶（§6，D14）与其余不可恢复失败一律 terminate
    #   每轮打一行 grade→place_id 日志（grade 不出 plans，place_id 是唯一放置可观测）
    def next_place_id(self, grade: str) -> str      # 内部方法；grade ∈ {"A","B","C"}，常量在 plan 文件
    #   A（优品）：顺序分配下一个优品 place_id；a_count 为实例状态，新任务重新实例化归零；
    #     越界（GRASP_MISS 空耗槽位捅穿摆桌保证）→ terminate
    #   B（次品）/C（不良品）：各自返回一个固定 place_id（落点须为箱口上方释放式堆放点）

# main.py —— 冷启动复位段（§8，含 vision.init()）+ 顶层状态机（§1）+ Ctrl-C 接到 terminate
```

## 三、录音与 ASR 契约

- silero VAD，输入重采样/降混至 **16kHz 单声道**（多数免驱麦克风默认 44.1kHz 立体声）。
- 起止判定逻辑自实现（silero 只输出逐帧语音概率）：
  - `WAITING`：无限等待语音触发；
  - `TRIGGERED`：起表 30s；检测到 ≥ `min_silence_duration_ms = 1000` 的连续静音 → 录音结束交 ASR；
  - 30s 到点未结束 → 丢弃整段 buffer → **打一行终端日志**（避免现场看似挂死）→ 回 `WAITING`。
- 无人说话永不超时、永不退出。
- 云 ASR：厂商未定（实现级选型，§10）；上传格式与 16k mono WAV 对齐。
- ASR 返回空串 → 回 `WAITING`；无意义文本交 LLM 判定（`"invalid"`）；ASR 调用硬失败 → `terminate`。

## 四、LLM 方案选择契约

- prompt 见 [prompt.md](../prompt.md)；输出 `{"task": "strawberry"|"invalid"}`，字符串比对。
- 合法输出两类：方案标识（strawberry/blueberry）或 `"invalid"`（无意义标识）；旧数字字符串不再合法。
- 违约处理：新开上下文原样重发一次（API 支持 JSON mode，重发即原样）；再违约 → 回 `WAITING`。
- 硬失败（网络/限流）→ `terminate`。
- API key 存 `configs/` 下新建文件（**加入 .gitignore**）。
- 当前 prompt 已包含 `{"task": "invalid"}` 反例示例；原“缺少无效输入反例”的记录已失效，实际拒识效果仍由语音/LLM 验收确认。

## 五、方案模块与抓取循环

- 方案间差异 = 各自标定的面积分级阈值 K + 落点映射（D05）；方案号**不下发视觉**，grade 同样不出 plans。运动抓取参数是否切换等待 D06。
- 循环体：`get_target()` → `grade 判定` → `next_place_id(grade)` → `grasp_and_place(target, place_id)` → 失败分发（§6）。
- grade 判定（plans 内部，各方案的阈值常量在对应 plan 文件，单位 m²）：`not target.ripe → "C"`；`length_m*width_m ≥ K → "A"`，否则 `"B"`。两方案公式相同，K 分别标定。
- 终止（**唯一任务完成出口**，D14）：
  - 连续 3 次 `NoTarget`（视野真空/全被过滤）→ 任务完成；任一次成功检测清零计数。
    - 三连调**无间隔**，防的是检测抖动，不防场景变化（后者由 §9 目标静止假设承担）。
    - 一次调用 = 一次完整采集-检测管线，无跨调用缓存（见 §2）。
  - ~~ignore 封顶穷尽 → 任务完成~~ **D14 已废止**：ignore 封顶改为判定无可抓取目标、terminate 任务失败（见 §6）。

## 六、抓取失败分发表（plan.run 内部）

| 状态码 | 行为 |
|---|---|
| IK_FAILED / PLAN_INVALID / GRASP_MISS / GRASP_UNCERTAIN / GRIP_SLIP | **重试类**，见下 |
| 其余全部（INVALID_INPUT / CONFIG_INVALID / COLLISION / PLACE_FAIL / TRACKING_ERROR / TIMEOUT / COMM_ERROR / ABORTED） | **直死类**：`terminate` |

重试类流程（连续失败预算 N=10 兜底；D08/D14 已修订判定顺序）：

```
失败返回（运动已开始，recovery_required=True，实例锁定；本条同时 ignore+1、连续失败计数+1）
1. 判定（D08/D14 修订后）：
   IK_FAILED/PLAN_INVALID 且 recovery_required=True → terminate（D08：一律终止，不分 holding）
   ignore ≥ 当次 target.valid_count → terminate("NO_GRASPABLE_TARGET")
     （D14：判定无可抓取目标；不恢复、不人工确认、臂冻结于当次失败位）
   连续失败计数 ≥ N → terminate（不再解锁复位，臂冻结于最后失败位）
2. 解锁：GRASP_MISS（空闭合区无接触，空爪确定）→ 自动 reset_fault()
   GRASP_UNCERTAIN / GRIP_SLIP（物体去向不明）→ 打印 + input() 等人工确认后 reset_fault()
3. reset_fault 不自动回零（技术文档 §6.4）：
   move_joints(safe_waypoint) → move_joints(home)
4. 重新请求视觉：get_target(ignore) → 正常循环
```

- D14 精确触发条件：本次重试类失败使 ignore 递增后 `ignore ≥ 本次返回该目标的 valid_count`。视觉因新扫描候选数变化抛出的 `NoTarget(skip_exhausted)` 不属本封顶，仍走 NoTarget 分支（ignore=0、streak+1）；该分支不证明每个物理目标都已尝试。"臂冻结"是沿用既有保持状态的业务描述，不代表软件在失控情况下仍能保证物理静止。
- 失败预算：连续失败计数**仅成功抓取清零**（NoTarget 不清零），连续 N 次且未先触发穷尽 → `terminate`。N 为 plan 常量，D02 已确认 **10**；计数为实例状态、新任务归零。预算既限制候选较多时的连续失败，也覆盖 NoTarget 归零绕路，不能宣称只在后者触发。
- ignore 生命周期：每次重试类失败 +1，任一次成功抓取或 NoTarget → 归零。skip 是 episode 级弃权非拉黑——被跳过物体仍在 ROI 时，归零后按当次排名重新入选；每次调用重新扫描，ignore 跳的是当次排名（失败可能已碰歪物体）。
- 重试期间 `NoTarget×3` 照常生效（任务完成语义一致）。
- 依据：技术文档 §4.3——运动开始后失败锁存实例，`reset_fault` 前一切调用被拒。

## 七、退出与冻结

- 冻结 = `terminate()`：打印 status/stage/reason + 现场指引 + `sys.exit(1)`。**进程不存活**。
- 依据（技术文档 §6.4）：位置保持依赖已提交的舵机位置目标，与进程存亡无关。
- 底线（CAL-052 批注）：**任何出口不主动断扭矩、不发任何新舵机指令**；卸力清理是异常路径的责任，上层不碰。
- 出口清单：
  - ASR / LLM 硬失败 → `terminate`（臂在 home）；
  - `VisionHardError`（相机断开/检测管线崩溃）→ `terminate`（臂在 home）；
  - WAITING 阶段 Ctrl-C → `terminate`（臂在 home）；
  - 抓取中 Ctrl-C → arm_control 捕获 KeyboardInterrupt → `ABORTED` → 分发表 → `terminate`；
  - `FAULT_UNCONTROLLED` → 串口不重试（I/O 重试为 0）→ `terminate`；
  - 连续重试失败预算耗尽（§6 兜底）→ `terminate`（臂冻结于最后失败位）。
- `should_stop` 回调不接：Ctrl-C 走 KeyboardInterrupt 现成路径。

## 十、已知风险（已接受）

3. 30s 超时丢弃可能有效的录音：嘈杂环境每轮白等 30s（有日志）。

6. 放置物不进碰撞障碍模型：落点设计必须自行保证放置空间。
7. 过小目标不设尺寸下限（夹爪可完全闭合）→ 逐个 GRASP_MISS → ignore 封顶穷尽（§6）→ 任务完成（每次失败留状态码日志，可审计；摆桌不混入过小果规避）。
8. GRASP_MISS 重试空耗已分配的优品落点槽位 → 可能捅穿 §9 摆桌保证 → `next_place_id` 查界 → `terminate` 兜底。
9. YOLO ripe/unripe 误判 → 放错堆，无任何一层拦截（混绿果场景人工验收）。
10. 冷启动容差外复位无人工确认：开爪可能掉落夹持物、复位路径依赖现场已清（操作规范承担）。
