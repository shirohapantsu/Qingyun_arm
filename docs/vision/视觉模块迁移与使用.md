## 公共接口与异常

继续使用 `configure(thresholds, config_path)` → `init()` → `get_target(ignore=0)`。调用方仍是生产 main/plans，不需修改。

输出 `VisionInterface(position, yaw_deg, length_m, width_m, ripe, valid_count)`：位置为基座系米制 `float64 (3,)` 几何中心，yaw 为基座系无向长轴角度，范围 `[-90,90)`。旧 `grade` 字段退役，成熟度由配置映射生成 `ripe`，品级由本地 Plan 根据尺寸判断。

相对模型/标定/回放路径都相对 vision JSON 所在目录解析。重复 configure/init、非法 ignore（含 bool）、坏配置、整帧无有效深度、推理失败抛 `VisionHardError`。无检出、全被过滤、ignore 跳尽、回放耗尽抛 `NoTarget`，原因分别为 `no_detection`、`all_filtered`、`skip_exhausted`、`replay_exhausted`。每次扫描通过 `runlog` 发一条结论，沿用 task/scan 上下文。

几何采用原始轴向 Z、深度去畸变、米制 D2C、RGB 原图带畸变投影与最近 Z 配准；不填补配准空洞。OBB 仅定义采样区域；剔除桌面，在深度连续分量的 base XY 点上测长宽/yaw，中心 Z 用桌面与顶面半高。低置信度/非候选物体仍参与邻距；无法测量的邻物触发保守拒绝。过滤检查 XYZ 工作域、两维尺寸、邻距和可见头顶点，排名键为 `(-clearance, distance_to_roi_center, x, y, z)`。

## 离线使用

在项目根目录，安装根 `requirements.txt` 后：

```bash
python scripts/vision_api.py --mode mock
python scripts/preview_vision_pipeline.py --mode mock --frames 4
python scripts/run_mock.py
python -m pytest tests -q
```

诊断入口只测视觉，不发送运动指令。预览默认保存 `logs/vision_preview.jpg`；`--display` 可显示 GUI。mock 使用连续八帧：目标、三张显式空桌、另一个任务目标、三张显式空桌；相机参数与深度均为 simulation 名义值。默认场景第一任务接触成功；第二任务按原有 `scenario.json` 的 `absent` 故障演练，达到 ignore 封顶时按本地契约终止。它不代表两任务成功验收；原生两任务帧消费与成功抓放分别有自动测试。

## 真机配置

1. 复制 `configs/vision.json` 为 `configs/vision.local.json`，app.local.json 指向它。
2. 手动部署 `models/vision/11l_berry_best-rk3588.rknn`，核实导出输入尺寸、输出 `[1,4+classes+angle,N]`、角度为 rad、类别序。默认模型输入/crop 均为 640；另一原型使用 736，不能据文件名判断导出参数。
3. 填写实际 `camera.rgb_device`、`rgb_size`、配对与采集超时，使用 **640×480 深度流对应的内参**；深度单位 0.001m。D2C 平移单位为 m；SDK 关闭配准，软件仅执行一次 D2C。
4. 将实测内参和 RGB 光学系到 base 的外参放到 local 配置引用位置。`configs/vision/` 的 null 模板不能运行；原分支恒等外参也不是有效手眼标定。
5. 安装对应 ARM64/Python 的厂商 RKNNLite wheel 和 OpenNI Python 绑定（附加依赖说明在 `configs/requirements.vision.txt`）。vendor SDK 的来源见 `libs/OpenNI2_arm64/SOURCE.md`。如需 USB 权限，可手动运行安装脚本；本次未运行 sudo 或修改 udev。
6. 用 `vision_api.py --mode real` / `preview_vision_pipeline.py --mode real` 做视觉诊断，并完成本地 P3/P4 独立验收及 verified profile 发布流程。

`model.backend` 支持 `fixture`（仅 replay）、`rknn`、`yolo`。旧 `yolo` + `.rknn` 配置兼容；`.pt` 使用 ultralytics OBB，模型类别必须与成熟度映射一致。新增可选模型键为 `input_size`、`crop_size`、`iou_threshold`、`class_names`，camera 可选 `openni_path`；其余未知键拒绝。

YOLO 四角/类别/置信度适配依据 [Ultralytics 官方 OBB 输出说明](https://docs.ultralytics.com/tasks/obb/#results-output)。OpenNI 绑定包使用 `openni==2.3.0`（`from openni import openni2`），其导入方式见 [包维护者说明](https://pypi.org/project/openni/)；`primesense` 使用另一包名，不能替代当前导入。

## 手眼标定

```bash
python scripts/generate_vision_markers.py
python scripts/calibrate_vision_touch.py --image calibration/vision/reference/calibration_snapshot.jpg \
  --intrinsics path/to/measured_intrinsics.json
```

默认输出 `calibration/vision/candidates/T_base_camera.json`，可用 `--output` 指定。拟合点过少、共线/重合、非有限坐标或最大拟合残差超过 4mm 时拒绝保存。PnP 与刚体拟合测试仅验证软件；训练点残差不等于 CAL-040 独立验收。位置 ≤4mm、yaw ≤5°、足迹 padding、成熟度混淆与半高中心模型须按本地规范另行实测。
