## 2. 实现说明（文件 + 关键符号）

### 2.1 `qingyun/asr.py`

**新增 §3.1 协议常量**（模型名/endpoint **不**硬编码，取 init 校验后的配置值）：
`AUDIO_DATA_URI_PREFIX = "data:audio/wav;base64,"`、`AUDIO_FORMAT = "wav"`、
`AUDIO_SAMPLE_RATE = str(TARGET_SAMPLE_RATE)`（= `"16000"` 字符串）、
`SSE_HEADER_NAME/VALUE = "X-DashScope-SSE"/"disable"`、`CONTENT_TYPE_HEADER_VALUE`、
`_DISARM_GRACE_TICKS = 8`、`_DETAIL_MAX_CHARS = 200`。

**端到端 deadline（§3.2，asr.py:444–604）**：
- `_AsrDeadlineExceeded(BaseException)`（asr.py:444）：专用异常，**不继承 OSError 也不
  继承 Exception**；两条实现性理由写在类 docstring 里（PEP 475 EINTR 自动重试风险 +
  httpx 内部 `except Exception` 会把到期改写成"传输错误"）。只在模块内部产生，
  永不外泄（`_transcribe` 统一转 `ASRHardError`）。
- 时钟/让出原语 `_monotonic()`（asr.py:473，**注入点**，T16 假时钟）与
  `_yield_to_signals()`（asr.py:478，`time.sleep(0)`）。
- `_deadline_handler`（asr.py:483）：SIGALRM 到点即抛 `_AsrDeadlineExceeded`。
- `_drain_handler`（asr.py:490）：取消计时器后吸收"已送达未派发"的在途 SIGALRM。
- `_reject_unsupported_call_environment()`（asr.py:500）：非主线程
  （`threading.current_thread() is not threading.main_thread()`）或
  `signal.getitimer(ITIMER_REAL)` 任一字段 > 0 → 抛 `ASRHardError("…不支持的调用环境…")`，
  **一次 HTTP 都不发**（见 DEC-P2-02-A）。
- `_CloudDeadline`（asr.py:529）：
  `__enter__` 顺序 = 环境检查 → `deadline_at = _monotonic() + total_s`（绝对截止）→
  预算 ≤ 0 直接判到期（不把负数喂给 setitimer）→ 安装处理器 →
  `setitimer(ITIMER_REAL, budget)` 并**用其返回值二次确认**旧表确为零（非零即撤销并拒绝）；
  装表异常回滚处理器。`item_timeout_s()` 返回剩余预算，≤ 0 抛到期。
  `__exit__` **总是** `_disarm()`（取消 → 换吸收处理器 → 8×让出 → 恢复旧处理器），
  随后若正常返回却已越过绝对截止点，仍判到期（最后一道校验，非中断机制，见 DEC-D）。
  每次 `_transcribe` 新建一个实例 = "每次请求单独起表"。

**DashScope 适配（§3.1，asr.py:618–947）**：
- `_import_httpx()`：惰性 `__import__("httpx")`，缺失 → ASRHardError（不降级换库）。
- `_new_http_client(*, timeout_s)`（asr.py:628，**注入点**）：
  `httpx.HTTPTransport(retries=0, http2=False)` + `httpx.Client(timeout=Timeout(connect/
  read/write/pool 全部 = timeout_s), follow_redirects=False)`——三条硬要求是显式字面量，
  不依赖库默认值。
- `_new_request_id()`（uuid4 hex[:16]）、`_redact(text, secret)`（把 `Bearer <key>` 与
  key 值替换为 `[已脱敏]` 并截断 200 字）。
- `_audio_data_uri()` / `_build_request_payload()`（一条 user 消息、只含本次音频，
  顶层键恰为 `{model, input, parameters}`）/ `_build_request_headers()`。
- `_http_status_category()`：401/403→`auth`、429→`rate_limited`、3xx→
  `redirect_not_followed`、4xx→`request_rejected`、5xx→`service_error`。
- `_provider_error_code(response)`：非 2xx 时只取服务侧 `code`（如 `InvalidApiKey`）
  入日志，**不取 message**、不记正文。
- `_extract_transcript_text(body)`：`json.loads` → 顶层对象 → `output` 对象 →
  `output.text` 存在且为 str（允许空串）；否则 `_TranscribeFailure("bad_json"/
  "bad_payload", …)`。
- `_perform_transcribe_request(...)`：`client.stream("POST", endpoint, json=payload,
  headers=headers, timeout=剩余预算, follow_redirects=False)` → 非 2xx 判错；
  2xx 走 `response.read()`（**完整响应读取正是中断点**）；`finally` 必关客户端。
  解析在 `with _CloudDeadline` 之内 → deadline 覆盖到解析。
- `_transcribe(wav_bytes) -> str`（asr.py:850）：前置检查（`_state is None`、运行态缺
  model/endpoint/timeout/key、音频非 bytes/空）→ 组装请求 → `with _CloudDeadline(total)`
  → 分类映射：`deadline_timeout` / `_TranscribeFailure` 类别 / `item_timeout`
  （httpx.TimeoutException）/ `transport`（httpx.HTTPError）/ `refused`（ASRHardError，
  只补事件后原样上抛）/ `local_error` / `os_error`；每个分支
  `raise _transcribe_failure(...) from exc` **保留来源**（`__cause__`）。
  `except BaseException`（KeyboardInterrupt/SystemExit）→ 记 `aborted` 事件后**原样上抛**
  （见 DEC-E）。成功记一条 `outcome="ok"` 事件并返回文本。
- `_log_transcribe_event(...)`：`runlog.event("asr_transcribe", request_id, outcome,
  elapsed_ms, category/detail 或 error_class, model, endpoint, audio_bytes, http_status)`；
  不含 api_key/Authorization/音频 base64/响应正文；runlog 自身失败一律吞掉（不得掩盖故障）。

**未动**：`ASRHardError`、`_AsrState`、`_AudioConverter`、`_encode_wav_mono16`、
`_open_input_stream`/`_enumerate_input_devices`/`_load_vad`、`_capture`、
`listen_and_transcribe`、`init`、`_reset_state_for_tests`。

## 7. 自主决策

- **DEC-P2-02-A（活动 ITIMER_REAL 的检测方案：只读 `getitimer` + 装表返回值二次确认）**：
  候选①"用 `setitimer(ITIMER_REAL, 0)` 试探并读返回值"——**否决**，因为 0 值本身就会
  取消别人的定时器，正违反 §3.2"不能覆盖其他组件的定时器"。取②：`getitimer` 只读探测，
  返回 `(remaining, interval)` 任一 > 0 判活动并拒绝（消息含"不支持的调用环境"）。
  再加③作纵深：我们自己的 `setitimer(remaining)` **返回值**就是"我们装填前的读数"，
  若非零说明检查被绕过（并发/竞态），立刻撤销并拒绝。非主线程用
  `threading.current_thread() is not threading.main_thread()`，不用 `signal.signal` 自己
  抛的 `ValueError` 当探针（那样错误消息不可读且会掩盖真实原因）。两条拒绝都发生在
  **发起 HTTP 之前**（测试断言 stub 计数 0），且拒绝路径不碰处理器。
- **DEC-P2-02-B（httpx 超时结构：分项全部 = 当时的剩余预算，客户端级与请求级都传）**：
  §3.2 要求"分项 HTTP 超时不超过剩余预算"。取 `httpx.Timeout(connect=r, read=r, write=r,
  pool=r)`，`r = deadline.item_timeout_s()`，其中 `r ≤ 0` 直接判端到端到期（绝不带着
  非正预算发请求，也避免把负数喂给 `setitimer`）。四个分项取同一个值而不是
  "connect 短、read 长"的分配：任何一次分项阻塞都可能吃掉全部剩余预算，给它更大的额度
  就等于允许整次调用超预算；"别单次阻塞太久"的诉求由"≤ 剩余"这一条同时满足。
  同时在 `client.stream(..., timeout=r)` 再传一次（请求级覆盖客户端级），并在
  `Client(follow_redirects=False)` 之外再传请求级 `follow_redirects=False` —— 双写是
  刻意冗余：任一层的默认值变化都不能悄悄打开重试或 redirect。
- **DEC-P2-02-C（EINTR 语义与"在途信号"的处理顺序）**：处理器抛
  `_AsrDeadlineExceeded(BaseException)`——不继承 `OSError`（PEP 475 下 EINTR 自动重试的
  语义与"可重试的 OSError"混在一起，有被吞掉的风险），也不继承 `Exception`
  （httpx/httpcore 的 `except Exception` 映射层会在最后一刻把到期改写成 `TransportError`，
  丢掉 `deadline_timeout` 这一类别）。取消顺序固定为四步：
  `setitimer(0)` 停信号源 → 换成吸收处理器 `_drain_handler` → `_DISARM_GRACE_TICKS` 次
  `time.sleep(0)` 让出（让**已经 pending** 的 SIGALRM 在我们的处理器下消费掉）→ 恢复旧处理器。
  理由：`setitimer(0)` 只阻止未来投递；若先恢复旧处理器（很可能是 `SIG_DFL`），一个迟到
  的 SIGALRM 会**终止进程**。实测该顺序下 T18 五例（含到期/Ctrl-C/下一次请求）全绿。
- **DEC-P2-02-D（`__exit__` 的事后 monotonic 校验只是最后一道保险，不是中断机制）**：
  §3.2 明确"不能仅靠 finally 事后判断超时"。本实现的中断能力全部由 ITIMER 提供
  （T17 正面证明 + 反证实验：取消装表后同一用例跑到 3.028s 且类别变 transport）。
  退出校验的用途是补两个 ITIMER 覆盖不到的边角：①预算在"读完之后、解析之中"耗尽；
  ②假时钟类测试环境里闹钟不会真的到点。校验只在"正常返回"路径生效（`exc_type is None`），
  绝不改写已在传播的异常。
- **DEC-P2-02-E（Ctrl-C 不转 ASRHardError）**：`except BaseException` 分支只记
  `outcome="aborted"` 事件然后**原样上抛**。理由：KeyboardInterrupt 是用户/顶层生命周期
  的意图（P1 §4/§5 由 shutdown/terminate 处置），把它转成 `ASRHardError` 等于把"人按了
  Ctrl-C"洗白成"云服务出错"，且会让 `terminate("ASR_HARD_ERROR")` 掩盖真实退出原因。
  清理（取消计时器、恢复处理器、关响应、关客户端）在 `finally` 与 `with` 退出协议中照常
  完成，由 T18 的 Ctrl-C 用例逐条断言。
- **DEC-P2-02-F（改写 P2-01 的一条用例而非删除）**：P2-01 的
  `test_默认转写钩子未接线时明确抛P2_02未实现` 钉的是"P2-02 尚未接线"这一阶段事实，
  任务书已授权"保持 P2-01 测试适配或在其授权精神内修订并日志说明"。改写为
  `test_默认转写钩子缺云配置即拒绝且零HTTP请求`：同一条链路（不注入 `_transcribe`）、
  同样的"绝不伪造文本"强度，断言换成运行态缺配置 → 精确类型 `ASRHardError` +
  归因文案 + **stub 计数 0** + 输入流已停。新增 `test_整链路…` 补上两侧真实缝合的证据。
- **DEC-P2-02-G（"多余结构"的取值解释）**：任务书 T19 一行要求"缺 output/多余结构均
  HardError"，而 §3.1 的成功样例本身就会带 DashScope 的 `usage`/`request_id` 顶层字段。
  取："**允许**顶层与 `output` 内的额外字段（协议演进不破坏我们）；**判错**的是结构不符
  ——顶层非对象、`output` 非对象、缺 `text`、`text` 非字符串（含 `text` 是对象/数组这类
  多余嵌套）"。fixture 两侧都写了用例（含 `usage` 的成功 1 例 + 12 种坏结构）。
- **DEC-P2-02-H（注入点形态：`_new_http_client(*, timeout_s)` 工厂，而不是 patch transport
  或 patch httpx 全局）**：让测试注入"一个同形的 `httpx.Client`（transport 换成
  `httpx.MockTransport`）"，好处有三：①被测代码路径与生产**完全一致**（同样走
  `client.stream(...)` 与 `response.read()`，故 T18 能真的观察响应对象被 close）；
  ②不改 httpx 全局、不碰 socket（P2 §5 替身纪律）；③分项超时值可以被记录，用于断言
  "≤ 剩余预算"。T17 则刻意**不注入**，用默认工厂的真实 `HTTPTransport`。
- **DEC-P2-02-I（T17 服务用 `http://127.0.0.1`，运行态直装绕过 init 的 https 守卫）**：
  规格要求"127.0.0.1 本地服务子进程做真实墙钟测试"。用 http 是为了免证书与免 TLS 握手
  噪声（也保证零外网、无 DNS）；`init` 的 https 校验是**生产配置**守卫（P2 §3.1 北京
  https endpoint），不改它，测试按既有惯例直装 `_state` 的 endpoint。端口语义交给内核
  （bind 0）并由子进程 `PORT=` 握手回报，避免手工占口竞态；服务源码内联进测试文件而不是
  新建 `tests/fixtures/*.py`，以守住"修改范围只有两个文件"。
- **DEC-P2-02-J（错误分类词表与脱敏策略）**：类别常量
  `auth/rate_limited/redirect_not_followed/request_rejected/service_error/
  unexpected_status/bad_json/bad_payload/item_timeout/deadline_timeout/transport/
  os_error/local_error/refused`，由 `_TranscribeFailure` 显式携带（不靠字符串猜测），
  统一出口 `_transcribe_failure(...)` 负责"记一条脱敏事件 + 返回待抛的 ASRHardError"，
  调用点写成 `raise ... from exc` 保来源。服务侧只取 `code`（短、可索引），
  `message` 与正文一律不入日志/异常；任何外部文本先过 `_redact`（值级替换 + 200 字截断）。
  异常消息末尾固定写"不重试、不降级、不跨地域 fallback"，让运维一眼看到行为边界。
