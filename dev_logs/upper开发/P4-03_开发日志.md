## 2. 实现说明（文件 + 关键符号）

### 2.1 新增 `scripts/record_pick_place_trials.py`

- 固定 CLI（逐字）：`--profile --trials --output --operator --vision-config`；退出码
  `0` 正常/操作者主动停止、`2` 连接驱动**前**的输入/配置错误、`3` 连接驱动**后**的运行期硬故障。
- 注入点（模块级、可被测试替换；生产路径不触碰）：`make_motor`、`make_arm`、
  `cold_start_recover`、`vision`、`_prompt`、`git_commit`、`thresholds_from_params`。
- "连接驱动前"严格校验（`run()` 的第一段 try）：`_load_profile` 走真实
  `load_calibration_motion_params`（拒绝 simulation/null 未测字段）→ `load_trials` 校验必需列
  齐全、trial_id/sample_id 唯一、place_id ∈ `params.places` → `--operator` 非空。任一失败即
  `EXIT_INPUT(2)`，**绝不构造驱动、绝不调用 vision**。
- 装配（`_assemble`）：`make_motor(params)`（P1 默认安全启动=D17 六轴卸力准入）→ `make_arm`
  （`enable_motion_trace` 默认 True）→ `cold_start_recover` → `vision.configure` → `vision.init`。
  视觉桩在当前环境如实抛 `VisionHardError` → `EXIT_RUNTIME(3)`；**无回退替身**。
- 逐试验：`_confirm_start` 要求操作者明确 `y/yes` 才开始，EOF/Ctrl-C 或非肯定答复 → 干净结束、
  不自动接下一次；目标=`vision.get_target(0)`，断言 `valid_count==1`，违反记失败样本
  （`software_status=SKIPPED_MULTI_TARGET`、不执行抓取）；执行 `grasp_and_place(target, place_id)`
  → 返回后一次性 `arm.get_last_motion_trace()` 经 `_descent_from_trace` 导出
  `began_descend/descent_evidence`（submitted→True/submitted；rejected 或无事件→False；
  unknown→None/"unknown"）。
- 逐字段样本（`_build_sample_payload`）：软件 status/stage/holding/recovery_required、
  profile 参数哈希（与 metadata 一致）、目标位姿、grade/place_id/样本真值/场景、人工观察
  （`_read_observations`：实际成功/掉落/位置/yaw/损伤标签/观察时长/图像引用）、
  `feedback_span_s/stop_latency_s=None`（无实测不伪填）、`trace_ref`。落点误差在样本内重算，
  与 validate 用**同一** `_place_center_error_m`/`_place_yaw_error_deg` 口径。
- 旁路文件 `_write_trace_sidecar`：把视觉输出、软件返回、trace 事件、图像引用落到
  `<output>.traces/<trial_id>.trace.json`，`trace_ref` 指向它。
- JSONL：首行 metadata（`record_type=metadata`、`source=hardware`、operator、profile 路径、
  `profile_parameter_sha256`、`resource_sha256`={urdf,motor_calibration 实算}、
  `code_commit`=`git_commit()` 实际值），其后每试验一条 sample，复用 `calibrate.Record/append_records`。
- **导出器写盘前完整性检查**（`_integrity_failures`）：每追加一条 sample 前调用与 validate 同一
  份 `calibrate.pick_place_integrity_checks`，不通过则 `EXIT_INPUT(2)` 且不写该条（文件保持结构合法前缀）。

### 2.2 扩展 `scripts/calibrate.py` hardware pick_place 分支（`_stage_checks`）

- 新增**共用结构性清单** `pick_place_integrity_checks(meta, samples, *, candidate_param_sha,
  urdf_sha, motor_sha)`：source 精确 hardware / operator 非空 / 资源哈希与实算匹配 / metadata
  参数哈希与候选一致 / trial_id 唯一 / sample_id 唯一 / 全部 sample 参数哈希一致 /
  began_descend 取值合法(bool 或 null) / 观察证据字段齐备 / 实际成功试验位置·yaw 与误差可复算一致。
  导出器与 validate 双侧共判这份关键项，杜绝手工 JSONL 绕过。
- 仅对 `metadata.source == "hardware"` 施加上述关卡（以 `physical` 证据登记）；模拟源不进入
  （其 mock 证据由既有 real 加载关卡拒绝——"simulated 不得成为 physical 证据"语义保持）。
- 分母改为"开始 DESCEND 的次数"：`began_descend is not False`——unknown(null) **保留在分母内**
  （不静默折算 False、不丢弃）。
- 新增两条形同阈值的 hardware 关卡：`began_descend 全部为 bool`（null 令报告不通过）、
  `损伤观察时长达标`（缺失/未到 `damage_observe_minutes` → 报告不通过，"pending"）。
- 新增**实际放置 yaw 误差 P95 ≤ `acceptance.max_yaw_error_deg`**；中心误差 P95 既有门槛保持。
- 成功率/掉落率/损伤率阈值与既有实现**逐字不动**；`metadata_of`、`parameter_sha256`、
  `sha256_file`、资源路径解析沿用既有工具。既有校验**未被削弱**。
- 新增 import：`configs.motion_params.wrap180`（供 yaw 误差重算）。

## 5. 问题与限制

1. 工具的真实端到端（连硬件 + 真视觉）未在本环境运行——视觉尚未实现（P3 桩），`vision.init()`
   如实抛 `VisionHardError` 即正确行为；工具流逻辑由注入替身离线覆盖。
2. `code_commit` 取 `git rev-parse HEAD`，无 git 环境如实写 `unknown`，不伪造。
3. `feedback_span_s`/`stop_latency_s` 本工具无实测源，一律记 null（引用相应 timing 阶段证据），
   不伪填 0（§2.8.3）。
4. 观察字段（位姿/损伤/掉落）由操作者逐条录入；工具不从软件 SUCCESS 推定物理结果。
5. validate 的资源哈希从候选 profile 目录解析并 `sha256_file` 实算，与导出器同源同值。

## 7. 自主决策

- **DEC-1（began_descend=unknown 修订工作流）**：工具不做在线编辑，只如实导出 null；修订以
  "人工按 JSONL 把 null 定为 bool、descent_evidence 改一致 → 重跑 validate 复算拒绝不一致/仍 null"
  闭环实现（写进 `--help` 文档与本日志，测试 `test_修订工作流...` 钉住）。
- **DEC-2（分母对 unknown 的处理）**：§2.8.3 "不从分母删除"落实为 `began_descend is not False`
  入分母（unknown 计入），另设"全部为 bool"关卡令报告不通过——两条协同，既保留又不放行。
- **DEC-3（双侧同一清单的实现形态）**：把结构性清单抽成 `pick_place_integrity_checks` 纯函数，
  导出器与 validate 各自转成"写盘前拒绝/报告不通过"，避免判据漂移。阈值类检查（试验数/成功率/
  掉落/损伤/两个 P95/观察时长/began bool）只在 validate 侧，允许 null/pending 如实写盘。
- **DEC-4（既有 pipeline fixture 适配）**：收紧 hardware pick_place 校验后，`_mark_records_physical`
  的"手工改 source"不再满足（正是反绕过目标），故改为重建合规 hardware 记录；未削弱任何阈值。
- **DEC-5（测试文件组织）**：新建 `test_calibration_tools.py`（§4 指定），理由见 §2.3。
- **DEC-6（退出码约定）**：2=连接前输入/配置错误（含 profile 未测完整参数），3=连接后运行期硬故障；
  与 calibrate 的"2=配置/数据错误"惯例一致并加以区分。
- **DEC-7（按指示跳过全量）**：仅跑定向 `test_calibration_tools.py` + `test_calibration.py`
  （+附带 `test_calibration_loader.py`），未执行全量 pytest。
