  `deadline_s = self._clock() + timeout_s`；不按台数倍增、任何失败路径不重试、不静默降级）：

  - (a) `report["phase"]="卸力准入核对"`：读应答配置→身份→逐轴读 `Torque_Enable`；任一非 0 立即抛
    `MotorStateError`（→ 包成 `MotorStartupError`），**此时零 Goal/Torque 写**（D17）。
  - (b) `"反馈预置"`：`get_feedback()` → `_startup_check_static`（有限 + 五关节速度逐轴 ≤
    `motion.settle_velocity_tol_deg_s` + 夹爪速度绝对值 ≤ `gripper.settle_speed_pct_s`）→ 逐轴读旧

    Torque_Enable；`_startup_validate_torque_values` 拒绝非 0/1；**全 1→不重复写**（source=
    `goal_broadcast_implicit_all_verified`）；**存在 0→只 `_enable_axes` 为 0 的轴**（逐轴单播，
    source=`explicit_enable_zero_axes`）后再次完整读回六轴，非全 1 抛错。
  - (d) `"位移核对"`：`_startup_wait(0.10)`+`reset_input` → `_startup_wait(0.20)`+`reset_input` →

    `_require_actuating_ready`），`result="ready"`。禁止回 home/写 EEPROM/RESET（无任何相关代码路径）。

## 5. 问题与限制

- `startup_report` 进 runlog/terminate 的**接线不属于本任务**：main 已有 `except BaseException →
  terminate("MOTOR_INIT_FAILED", repr(exc))`，`MotorStartupError.report` 与 `startup_report` 属性
  均可取，P5 再消费。本任务只保证"异常携带报告 + 实例最后一次报告可读"。
- 0.10s/0.20s/5.0s/0.03s 与 `_INIT_TIMEOUT_S` 均为待真机回归后锁定的实验/保守值；**通过假总线测试
  不等于物理启动安全已验证**（§4.1 末段），真机验收另用实际 profile 记录参数与固件版本。
- 假总线是行为模型：`off/on/unknown`、隐式上力、位移跳变、清理超时都是按 §4.1 语义在测试侧构造的
  现象，不代表对真实 STS3215 上电时序的度量。
- 清理不承诺物理卸力成功（总线彻底死掉时全部 `unknown`）；这是"尽力、有界、如实记录"的语义，与
  shutdown "臂冻结不代表软件保证物理静止" 的既有措辞一致。

## 7. 自主决策

1. **`_startup_wait` 的 0.10s 放在 (d) 而非 (c) 显式使能分支内**：validate 脚本把 0.10s 绑在
   `configure_torque` 之后、0.20s 绑在最终读回之前。§4.1 把两个等待统一描述在 (d)"分隔写/读阶段"。
   取一致实现：(d) 内先 0.10 + reset_input、再 0.20 + reset_input，总等待量与脚本相同，隐式全上力
   路径也执行同一分隔（多两次排空，无副作用）。记为实验值，真机回归锁定。
2. **只读路径（enable_torque=False）不改失败类型**：只读握手仍抛底层 `MotorCommunicationError/
   MotorStateError`（不强制包成 MotorStartupError），以最小化对既有标定脚本异常处理的影响；MotorStartupError
   仅用于生产上力路径与 (a) 起的失败。§4.1 对只读路径只要求"零写"，不要求报告化，符合"供已有工具
   继续使用"。
3. **清理不做每轴读回重试**：validate 脚本对读回最多重试 3 次。§4.1 只要求"逐轴读回，读失败=unknown、
   某轴失败继续其余"，未要求重试。取单次读回以让"清理预算有界"与"unknown≠off"两条断言可确定性验证；
   真机如需重试裕度回归时再加，且仍受同一 `STARTUP_CLEANUP_TIMEOUT_S` 约束。
4. **清理范围=六轴全部**：§4.1 (c) 规定广播前"把六轴全部标记 torque_may_be_enabled"，故清理固定遍历
   `mapping.axes` 六轴（与 validate 脚本一致），不再按"实际被写过 1 的轴"缩小——因为 CAL-052 下无法
   用寄存器写值证明哪几台被隐式上力。
5. **`MotorStartupError` 选择继承 `MotorStateError`**：既满足任务字面要求，又让 main 现有
   `MOTOR_INIT_FAILED`/MotorError 归类无需改动。
6. **报告 `feedback_after` 在成功与失败路径都填**：失败在 (d) 时也尽量记录最后一次可读反馈，便于 P5
   区分"预置前/使能后"姿态；读不到则保持 None。
7. **`StartupBus` 用子类而非改基类 `FakeBus`**：任务允许新增测试辅助；改子类 + 默认关闭钩子把对既有
   60 余条用例的风险降到零（全量回归 0 failed 印证）。`cleanup_read_fail_ids` 用"已出现一次
   Torque_Enable=0 写"作为进入清理的判据，从总线上精确区分握手期的正常力矩读与清理读回，避免相位误伤。
8. **修订而非删除两条既有 initialize 用例**：`test_初始化链路...` 与 `test_初始化按等级1...` 按旧
   36 帧形态断言，§4.1 后不再成立；改为断言新事务序列的实质不变量（EEPROM/RESET 零写、Goal 恰 1 广播、
   只对 0 轴使能、READY、应答策略源自寄存器）。覆盖面**提升**而非下降（新增"广播/隐式上力/使能来源/
   报告 READY"，删掉的仅是"总帧数=36"这一已失效的具体数字，其意图由新的精确写事务 Counter 断言承接）。
