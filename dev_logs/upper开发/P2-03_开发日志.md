## 2. 实现说明（文件 + 关键符号）

### 2.1 `qingyun/cloud_model.py`（1064 行，替换桩体）

**公开面逐字不变**：`LLMHardError(RuntimeError)`、`init(cfg: AppConfig) -> None`、
`select_plan(text: str) -> str`、`__all__ = ["LLMHardError", "init", "select_plan"]`。
头 docstring 前 6 行保留"契约桩 / 替换桩体 / 文件名与公开签名不得改变 / P2"四个契约声明
（A 组 `test_桩文件头部声明契约桩与替换方式` 仍绿）。顶层 import 仍然只有
`__future__` + `typing`（AST 白名单），`AppConfig` 走 `TYPE_CHECKING`；所有重依赖
（httpx、json、hashlib、uuid、pathlib、time、signal、threading、configs.app_config、
qingyun.runlog）一律在函数体内 `__import__` 动态载入（T11）。

**§4 协议常量**（模型名与 base_url **不**硬编码，取 init 校验后的配置值）：
`CHAT_COMPLETIONS_PATH = "/chat/completions"`、`JSON_MODE_TYPE = "json_object"`、
`THINKING_DISABLED_TYPE = "disabled"`、`MAX_COMPLETION_TOKENS = 128`、
`STREAM_DISABLED = False`、`CONTENT_TYPE_HEADER_VALUE = "application/json"`、
`VALID_TASKS = frozenset({"strawberry", "invalid"})`、
`_TRUNCATED_FINISH_REASONS = frozenset({"length", "content_filter"})`、
`_MAX_SEMANTIC_REQUESTS = 2`、`_DEEPSEEK_KEY_NAME = "deepseek_api_key"`、
`_PLACEHOLDER_MODEL_NAMES`（15 项占位名单，见 DEC-A）。

**运行态 `_LlmState`（常驻，`_state` 单例）**：`model` / `endpoint`（init 里按
`base_url.rstrip('/') + CHAT_COMPLETIONS_PATH` 派生）/ `total_timeout_s` / `api_key`
（只在内存）/ `prompt_text`（全文一次读入）/ `prompt_sha256` + `prompt_chars`
（日志摘要）/ `client`（**init 构造一次**的 HTTP 客户端）。

**`init(cfg)`（真实语义）**：
1. `_state is not None` → `LLMHardError("云模型已初始化：init(cfg) 只允许调用一次…")`。
2. `_validate_llm_settings(cfg)`：`cfg.llm` 结构缺失（AttributeError）→ 消息含
   `cfg.llm`；空/占位模型名（`model.strip().lower()` 命中名单）→ 拒绝并要求 D20 的精确
   `deepseek-flash`；`base_url` 必须 `https://` 前缀且长度足够（明文 http 不允许承载
   Bearer 密钥）；`total_timeout_s` 必须有限正数（bool 拒绝，NaN/inf 拒绝）。
3. `_read_prompt(cfg.prompt_path)`：`pathlib.Path(...).is_file()` → `read_text(encoding
   ="utf-8")` **一次**；不存在 / OSError / 非 UTF-8 / 全空白都抛 `LLMHardError`；
   运行期不再读该文件（T：改写/删除文件后请求仍是原文）。
4. `_read_deepseek_key()`：`configs.app_config.load_secrets(SECRETS_LOCAL_PATH)` 取
   `deepseek_api_key`，缺失/非字符串/全空白 → `LLMHardError`（P1 预检之外的兜底，T13）；
   消息只点键名，不回显任何值。
5. `_new_http_client(timeout_s=total_timeout_s)`（**注入点**，只调一次）；失败即抛，
   `_state` 保持 None（可修复后重试）。

**`select_plan(text)`**：`_require_state()`（未 init → "未初始化"；运行态缺
model/endpoint/total_timeout_s/api_key/prompt_text/client 任一 → "配置不完整"，
**零 HTTP 请求**）→ 非 `str` 转写直接硬故障 → `_build_request_payload` +
`_build_request_headers` 各构造**一次**（两次语义请求共享同一 payload 对象，"原样重发"
成为结构性保证而非巧合）→ `for attempt in 1..2: _run_semantic_request(...)`，
违约 `continue`，任何一次合法即 `return task`，循环用尽 `return "invalid"`。

**`_run_semantic_request`（一次语义请求的全部动作）**：
`_new_request_id()` → `started_at = _monotonic()` → `with _CloudDeadline(total_timeout_s)`
（**每次调用重新起表**，R05）→ `_perform_llm_request` → `_extract_content` →
`_parse_task`。异常出口分三类：
- `_LlmContractViolation` → 记 `outcome="violation"` + 违约类别 + `finish_reason` 后
  原样上抛，交 `select_plan` 决定重问；
- `_LlmDeadlineExceeded` / `_LlmHardFailure` / `httpx.TimeoutException` /
  `httpx.HTTPError` / `ValueError|TypeError|UnicodeError` / `OSError` → 统一
  `_hard_failure(...)`：**记一条脱敏事件 + 返回**待抛的 `LLMHardError`（调用点写成
  `raise ... from exc`，`__cause__` 保来源），**不消耗**违约重问额度；
- `LLMHardError`（环境拒绝/缺 httpx）→ 补记 `category="refused"` 后原样上抛；
- 其余 `BaseException`（KeyboardInterrupt/SystemExit）→ 记 `outcome="aborted"` 后
  **原样上抛**，绝不转成 `LLMHardError`（不把 Ctrl-C 洗白成云故障）。
成功记 `outcome="ok"` + `task` + `http_status="2xx"`。

**`_perform_llm_request`**：`client.stream("POST", endpoint, json=payload, headers=…,
timeout=deadline.item_timeout_s(), follow_redirects=False)`；非 2xx → 先
`_provider_error_code(response)` 尽力取**短码**（`error.code`/`error.type`/顶层
`code`/`type`，≤64 字符），按 `_http_status_category` 归类
（`auth`/`rate_limited`/`redirect_not_followed`/`request_rejected`/`service_error`/
`unexpected_status`）后抛 `_LlmHardFailure`；2xx 才 `response.read()` 交出完整字节。
`with` 保证**被中断/未完成的响应一定关闭**；客户端常驻不在此关闭。

**协议层 `_extract_content(body)`（"包结构损坏"=硬故障）**：`json.loads` 失败 →
`bad_json`；顶层非对象 / 缺 `choices` / `choices` 非数组或空 / `choices[0]` 非对象 /
`message` 非对象 / 缺 `content` / `content` 非字符串 → `bad_payload`。**只读
`choices[0].message.content`**，`reasoning_content` 永不参与解析（§4 末段）。

**契约层 `_parse_task(content, finish_reason)`（违约）**：先判
`finish_reason ∈ {length, content_filter}` → `truncated`；再
`json.loads(content, object_pairs_hook=_single_object_pairs)`——
`_DuplicateJsonKey`（`ValueError` 子类）→ `duplicate_keys`，其它解码异常（代码块包装、
前后缀文字、半截 JSON、空串、尾逗号）→ `not_json`；顶层非 dict → `not_object`
（数字/布尔/null/字符串/数组）；键集合 ≠ `{"task"}` → `missing_task` / `extra_keys`；
值非字符串（含 bool）→ `task_not_string`；值 ∉ `VALID_TASKS` → `unknown_task`
（`blueberry`、`STRAWBERRY`、`" strawberry"` 全在这一档）。JSON 允许的**前后空白**与
键间距不算包装（`T10` 有对照例）。

**私有端到端 deadline（§3.2 在本模块的第二份，独立实现）**：
`_LlmDeadlineExceeded(BaseException)`（不继承 OSError/Exception，理由同 P2-02）+
`_reject_unsupported_call_environment()`（非主线程 / `getitimer` 只读探测到活动计时器 →
`LLMHardError`，**发生在发请求之前**）+ `_CloudDeadline`（`__enter__` 装表并二次确认
`setitimer` 返回值、`item_timeout_s()` 剩余 ≤0 即判到期、`__exit__` 四步 disarm
`setitimer(0)` → 换 `_drain_handler` → `_DISARM_GRACE_TICKS` 次 `sleep(0)` 让出 →
恢复旧处理器，且只在"正常返回"路径做事后截止点校验）。

**日志 `_log_request_event`（类别 `llm_request`，每次语义请求一条，上限两条）**：
`request_id` / `attempt` / `outcome(ok|violation|error|aborted)` / `elapsed_ms` +
`model` / `endpoint` / `prompt_sha256` / `prompt_chars` + 可选 `category` / `detail`
（先过 `_redact`：值级替换 `Bearer <key>` 与 `<key>` → `[已脱敏]`，再 200 字截断）/
`text_chars` / `task` / `finish_reason` / `http_status` / `error_class`。**永不写入**
api_key、Authorization 头、prompt 全文、转写文本、响应原文；`runlog` 自身失败被吞掉，
不掩盖云请求结果。

## 7. 自主决策

- **DEC-P2-03-A（deadline 复制策略：cloud_model 内独立实现第二份，不 import `asr` 私有名）**：
  候选①"把 `_CloudDeadline` 提到公共层或 `from qingyun.asr import _CloudDeadline`"——
  **否决**：跨模块私有依赖是坏形态（下划线名字不是契约，asr 改形状会悄悄破坏 LLM 侧），
  且 §3.2 的字面要求是"**两适配器各有私有 deadline 上下文**"，共享实例会把两个供应商的
  超时与清理耦合在一起。取②：本模块内复制一份（`_CloudDeadline`/
  `_LlmDeadlineExceeded`/`_reject_unsupported_call_environment`/`_drain_handler`/
  `_monotonic`/`_yield_to_signals`/`_new_http_client`/`_redact` 全部各自实现），代价是
  两份代码需各自维护（已在头 docstring 与 §6 写明理由）。类别词表与出口异常**不**通用：
  LLM 侧新增"到期属硬故障、不消耗重问"这一条 asr 侧没有的语义，复制而非泛化。
- **DEC-P2-03-B（客户端"构造一次"与"分项超时 ≤ 剩余预算"的调和）**：§4 要求 init 只
  **构造一次** HTTP 客户端，§3.2 要求分项 HTTP 超时不超过**当时**的剩余预算——两者在
  "每次新建客户端"的 asr 形态里不冲突，在这里会冲突。取：客户端级超时 = `total_timeout_s`
  作为**基线**（init 里显式写 connect/read/write/pool 四项 + `retries=0` +
  `follow_redirects=False`），每次请求再传**请求级** `timeout=deadline.item_timeout_s()`
  与 `follow_redirects=False`（httpx 允许请求级覆盖客户端级）。双写是刻意冗余：任一层
  默认值变化都不能悄悄打开重试或 redirect。副产品：客户端常驻 → 连接池复用（与"每次
  listen 新建"的 asr 相比少一次握手），且 T19 用 `len(stub.clients) == 1` 与
  `client.close_count == 0` 把"只构造一次、不随请求关闭"钉成可测事实。
- **DEC-P2-03-C（重复键判定：`object_pairs_hook` 而非解析后比较）**：标准
  `json.loads` 对重复键**静默取后者**（`{"task":"strawberry","task":"invalid"}` 会
  得到合法的 `invalid`），直接把违约洗白成成功——这正是规格点名"重复键属违约"要防的。
  方案：`json.loads(content, object_pairs_hook=_single_object_pairs)`，hook 逐对检查键名，
  第一次重复即抛 `_DuplicateJsonKey(ValueError)`。三点取舍：①它必须是 `ValueError`
  子类——标准库 `json`（含 C 加速 scanner）只对 `ValueError` 族一视同仁地原样向外传播，
  实测自定义异常不被包装、不被吞（用例 `test_T10_重复键不会被json后者覆盖洗白` 同时
  钉住"库默认取后者"这一前提）；②**任何层级**的重复键都判违约（合法 task 响应只有
  `{"task": <字符串>}` 一层，不存在合法的嵌套重复键）；③不用"解析后再比 keys"的方案，
  因为信息在解析时已经丢了。
- **DEC-P2-03-D（两层解析严格分立：`_extract_content` 硬故障 vs `_parse_task` 违约）**：
  §4 把"HTTP 失败/返回包结构损坏"归 HardError、把"存在 content 但内容不满足任务 JSON
  或 finish_reason 截断"归语义违约。实现上分成两个私有函数并以两个不同的内部异常承载
  （`_LlmHardFailure` / `_LlmContractViolation`），避免用字符串猜测类别。关键取值：
  `content` **缺键或非字符串** = 包结构损坏（HardError）；`content` 存在且是字符串、
  哪怕是空串或垃圾文本 = 违约（走重问）。这条分界线有 11 例硬故障 + 33 例违约矩阵锁死。
- **DEC-P2-03-E（`finish_reason` 词表与"未知值"的宽容）**：规格只定义"截断 = 违约"，
  未给词表。取 `length`（`max_tokens=128` 的截断，正是要防的）与 `content_filter`
  （输出未完整交付）两类为截断，大小写不敏感；`stop`/`None`/未来新增非截断值一律放行，
  交给 content 判定——与"协议演进的顶层额外字段（`id`/`usage`/多 choices）允许存在"
  （P2-02 DEC-G 同一取向）保持一致。反向风险（把新取值误判成截断）会白白消耗一次重问，
  故只登记**明确是截断**的两个值。
- **DEC-P2-03-F（占位模型名单与 `asr` 侧同源但不共享）**：名单复制 asr 的 15 项
  （`mock`/`mock-model`/`placeholder`/`changeme`/`todo`/`tbd`/`none`/`null`/`unknown` 等），
  比对前先 `strip().lower()`；真实模型 `deepseek-flash` 不在其中，`app.mock.json` 的
  字面占位 `mock` 在（D15 的 mock 入口本来就不调本 init，这条只是生产误配兜底）。
  **不**从 `asr._PLACEHOLDER_MODEL_NAMES` import：同一模块私有名字依赖问题（DEC-A），
  且两家的合法模型名规则将来可能各自变化。
- **DEC-P2-03-G（改写一条 B 组桩用例而非删除）**：任务书授权"若 test_module_stubs 的
  cloud 桩专属用例需按 P2-01 同法改写（B 组'桩阶段专属'），允许并日志说明"。改写保持
  三项强度：①`type(exc) is LLMHardError`（不放宽为 `Exception`）；②消息里必须能看到
  契约名（`init` / `select_plan`）与"未就绪"归因（`cfg.llm` / `未初始化`）；③先
  monkeypatch `_state = None` 强制未就绪形态，且**绝不返回 `invalid`**（那会被 P1 §5
  读成"口令与本期无关"而静默跳过，正是桩文件 docstring 警告的洗白路径）。
  `LLM_MESSAGE_PREFIX` 常量保留并加注释说明"随桩退役"，避免悄悄删掉一处历史锚点。
- **DEC-P2-03-H（`llm_request` 事件不落转写文本与 prompt 全文）**：§4 只要求"每次请求
  的耗时入日志"，P1 §7 已把"转写文本 + task + 耗时"分配给 main 的 `llm_result`。为遵守
  任务书"内部日志不与 main 重复计"，本模块记 `text_chars`/`prompt_chars`/`prompt_sha256`
  这类**摘要**字段而不记正文；prompt 全文与密钥一样属于不得入日志的内容（它可能含业务
  敏感描述）。用例逐条断言 JSONL 里不含密钥、不含 `Authorization`、不含 prompt 文本片段、
  不含转写文本。
- **DEC-P2-03-I（T17 用 `http://127.0.0.1` + 直装运行态绕开 https 守卫）**：与 P2-02
  DEC-I 同一取向——`init` 的 https 校验是**生产配置**守卫，不为测试放宽；墙钟证明需要
  一个真实 socket，故用例直接构造 `_state`（endpoint 为 127.0.0.1）并用默认工厂建真实
  `HTTPTransport` 客户端。端口语义交给内核（bind 0）+ 子进程 `PORT=` 握手回报；服务源码
  内联进测试文件（不新建 `tests/fixtures/*.py`），以守住"修改范围只有三个文件"。
- **未改动项（避免越界）**：`select_plan` 对**空白转写**不做额外拒绝（main 的
  `run_session` 已在 `if not text.strip(): continue` 处拦掉，规格未要求本模块再判，
  加一层就等于替模型决定"无意义输入 → invalid"）；`_state.client` 无关闭钩子
