### 2.2 本次修复（两处，均在 `test_E2E_05b`，行号 918/919 附近）

修复前实测：运行该用例失败于 line 918 `assert 1 == 0`，且 captured stdout 出现 `[TERMINATE] status=KEYBOARD_INTERRUPT`——证实生产输出 `consecutive_failures=1`，并证实会话末尾确有 terminate 事件。

1. **line 918（任务书登记的根因）**：`done["consecutive_failures"] == 0` → `== 1`，并补注释引用 P1 §6.1 计数器表 / D02 / P1-T08。
   - 规格依据：§6.1 表 NoTarget 行 `consecutive_failures = 不变`、仅 `ignore = 0`；只有 SUCCESS 行同时清零 `ignore` 与 `consecutive_failures`；P1-T08 明示"失败后 NoTarget 再获目标：ignore 清零、连续失败数不清零"。本场景 GRASP_UNCERTAIN（重试类，+1）→ 人工确认恢复 → NoTarget×3，全程无 SUCCESS，审计值应为 1。原断言值 0 与其**自身注释**"NoTarget 不清零失败预算"及规格同时相反。
   - 生产核实：`qingyun/plans/base.py` L177-178（NoTarget：`self.ignore = 0; self.no_target_streak += 1`，不动 `consecutive_failures`）、L226-230（SUCCESS 才 `consecutive_failures = 0`）、L241-242（重试类 `consecutive_failures += 1`）、L620-630（`_finish` 如实记 `consecutive_failures`）。**生产代码符合规格，不迁就断言、不改生产代码。**

2. **line 919（同一失败用例内的第二处矛盾，修复 918 后必显形）**：`assert case.of("terminate") == []` → 改为对齐 E2E-01 的钉法（`sole("terminate")` 为 `KEYBOARD_INTERRUPT` 且不带 `task_instance_id`）。
   - 依据：`main.run_session` 是 `while True`，仅经 `terminate → SystemExit` 退出（main.py L207-248）；会话末尾注入的 `_KI` 在第二次 `listen()` 抛出 → L242 `except KeyboardInterrupt` → `terminate("KEYBOARD_INTERRUPT")`。任务本身以 NoTarget×3 正常完成、无任务级 terminate，故该 terminate 无 `task_instance_id`（与 E2E-01 line 594-596、E2E-09 line 1125、E2E-14 line 1422 同构）。`case.of("terminate") == []` 在任何 `drive_session` 用例中恒不成立。
   - 该改动**未削弱**任何断言（反而从"无 terminate"这一不可能断言，收紧为"唯一 terminate 且其身份为会话级 Ctrl-C、无任务级 terminate"）。
