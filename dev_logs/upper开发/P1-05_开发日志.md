## 2. 实现说明（文件 + 关键符号）

### 2.1 `main.py`（生产入口；import 零装配副作用，仅 `__main__` 启动）

- `thresholds_from_params(params) -> VisionThresholds`：P0 六字段来源逐一复制的
  纯构造辅助；放 main 供 run_mock import 复用；数组复制由 VisionThresholds 自身
  完成。
- `file_sha256(path)` / `_sha256_or_reason(path)` / `log_startup(entry, cfg,
  app_config_path)`：startup 事件（§7）；三个被引用资源**各算各文件**的 SHA256；
  读不到时如实记 `"unreadable: <原因>"` 字符串（存在性判定属后续步骤，见 §7 决策
  DEC-P1-05-B）。
- `cold_start_recover(arm)`：§4 步骤 7 伪代码逐字（`np.all(|fb−home| ≤
  settle_position_tol_deg)` 逐轴）；容差内零动作；否则 open_gripper →
  按 safe_waypoints_deg **列表顺序**逐个 move_joints → move_joints(home)。本体不做
  terminate 映射（§4 末段：映射是入口职责），任意异常/Ctrl-C 向上抛。
- `run_session(cfg, arm, *, registry) -> NoReturn`：§5 循环逐字。asr_result 事件在
  空/非空转写后各发一条（text+duration_s），空串 continue；llm_result 带
  text+task+duration_s；invalid continue；`task not in registry →
  terminate("LLM_CONTRACT_VIOLATION", repr(task))`；task_instance_id session 内
  单调 +1；`with runlog.context(task_id, task_instance_id)` 包住"新建 Plan +
  run()"；不重复打印任务完成（L9）。异常映射：ASRHardError→ASR_HARD_ERROR、
  LLMHardError→LLM_HARD_ERROR（内层各自捕获）；外层
  `except SystemExit: raise`（直通不包装）→ `except KeyboardInterrupt:
  terminate("KEYBOARD_INTERRUPT")`（WAITING 阶段路径）→ `except VisionHardError:
  terminate("VISION_HARD_ERROR")`（plan 外保险）→ `except BaseException:
  terminate("UNEXPECTED", repr)`。
- 装配：`assemble_production() -> (cfg, params, arm)` 按 §4 步骤 1–11 固定顺序；
  每一步只经**模块级名字**调用外部依赖（load_app_config/runlog/
  load_motion_params/preflight/Sts3215MotorController/ArmController/
  cold_start_recover/asr/cloud_model/vision/shutdown），测试可逐名注入探针。
  步骤 1/2 失败 → `_abort_before_log`（stderr 一行 + terminate，此时无正式日志）；
  步骤 4/5 失败 → `preflight_failed` 事件（尽力而为，写失败只 stderr）+ terminate
  （`MOTION_PARAMS_INVALID` / `PREFLIGHT_FAILED`，**motor 尚未构造**——初审 L1）；
  步骤 6 构造即握手异常（含 KeyboardInterrupt，SystemExit 除外直通）→
  `MOTOR_INIT_FAILED`；步骤 7 → `COLD_START_RECOVERY_FAILED`；步骤 8/9/10 →
  `ASR_INIT_FAILED`/`LLM_INIT_FAILED`/`VISION_INIT_FAILED`（configure 与 init 同归
  VISION_INIT_FAILED，§4 步骤 10）；步骤 11 ready + console("系统就绪，等待语音指
  令")。`main()` = assemble → `run_session(cfg, arm, registry=PLAN_REGISTRY)`。

### 2.2 `scripts/run_mock.py`（D15 豁免入口；import 零装配副作用）

- sys.path 引导：脚本直跑时把项目根插到 sys.path（`configs.*`/`qingyun.*`/`main`/
  `tests.*` 从根绝对导入）。
- `MOCK_AREA_THRESHOLD_M2 = 0.05 * 0.024`（**名义值，非实测**）+
  `MockStrawberryPlan(StrawberryPlan)`（只覆盖 AREA_THRESHOLD_M2）+
  `MOCK_REGISTRY = {"strawberry": MockStrawberryPlan}`——生产类与 PLAN_REGISTRY
  零改动（T27 对象同一性断言钉死）。
- `load_scenario(cfg)`：P5 §2 形态校验（utterances 字符串列表；attempts 恰含
  `contact ∈ {present, absent}`；允许 `_comment`；未知键拒绝）。
- `ScenarioStubs` / `install_stubs(cfg)`：模块属性赋值替换
  `qingyun.asr.listen_and_transcribe`（逐条消费 utterances，耗尽后按真实墙钟
  sleep 0.2s 返回空串——"阻塞等 Ctrl-C、不持续空串忙循环"与装配契约"耗尽后返回
  空串"两条要求的并集实现）与 `qingyun.cloud_model.select_plan`（含"草莓"→
  strawberry，余 invalid，零网络）；**不调用任何真实 init**（D15）；重复调用抛
  RuntimeError；`reset_stubs_for_tests()` 供测试恢复（与 runlog/shutdown 同族惯例）。
- `ScenarioArmController(ArmController)`：唯一的 grasp_and_place 覆盖——先消费
  attempt 设置 `motor.object_gap_m`（present=float(mean(contact_gap_range_m))，
  absent=None），随后**原样 super() 调用、不替换返回结果**；耗尽先 terminate
  (`SCENARIO_ATTEMPTS_EXHAUSTED`) 再动任何开关（哨兵断言证明拒绝在设置之前）。
- `assemble(cfg=None, *, vision=None) -> (cfg, params, motor, arm)`：P5 §2 顺序
  逐段；`runlog`/`preflight`/`load_app_config`/`cold_start_recover`/
  `thresholds_from_params`/`log_startup`/`run_session` 全部为模块级名字（可
  monkeypatch）；`SimTime()` → `MockMotorController(params, sim_time)` →
  **显式 motor.initialize() 恰一次** → `ScenarioArmController(..., clock=
  sim_time.monotonic, sleep=sim_time.sleep, clock_ns=sim_time.monotonic_ns)`
  （R04）→ install_stubs → cold_start_recover → `vision.configure(
  thresholds_from_params(params), cfg.vision_config_path)` → `vision.init()` →
  ready。**vision 默认真实桩模块**（`from qingyun.grabbing import vision`），
  注入参数 `vision=FakeVision实例` 仅供测试复用同一装配（DEC-002，见 §7）。
- `main()` = assemble() → `run_session(cfg, arm, registry=MOCK_REGISTRY)`；
  与生产共享同一会话实现。

## 7. 自主决策

- **DEC-P1-05-A（KeyboardInterrupt 的 terminate 状态名取 `KEYBOARD_INTERRUPT`）**：
  §5 表只写"→ terminate"不给状态名；候选①`UNEXPECTED`——把有明确语义的操作员
  动作洗成"未预期"，日志复盘时无法区分；候选②复用 `MANUAL_CONFIRM_ABORTED`——
  那是 plan 恢复确认中断的既有码（§6.5），语义不同。取自描述新码并在用例钉死，
  detail 注明"臂在 home"。若验收要求改名，只动一处字符串。
- **DEC-P1-05-B（startup 哈希读不到时记 `"unreadable: 原因"` 字符串而非 fail-fast）**：
  startup 事件在 §4 步骤 3，早于资源存在性检查（步骤 4/预检）；此处 raise 会把
  "profile 不存在"洗成无源头的启动失败，吞掉后续 `MOTION_PARAMS_INVALID`/
  `preflight_failed` 的精确归因。取"如实登记 + 让该管的步骤去拒绝"。哈希语义
  （各资源独立、非配置文件哈希）由哈希用例双重钉死。
- **DEC-P1-05-C（装配失败事件名沿用 `preflight_failed` + stage 字段）**：候选①为
  profile 加载失败另造 `params_load_failed`——§7 未登记该事件名，会成为无源字段；
  候选②不发事件直接 terminate——丢失"预检/参数阶段"审计链。取§7 已登记事件名 +
  `stage="load_motion_params"` 扩展字段（§7 表格是最低字段要求）。
- **DEC-P1-05-D（vision configure+init 统一 `VISION_INIT_FAILED`，且按
  BaseException 兜底）**：§4 步骤 10 字面只点名 VisionHardError；但该阶段任何
  异常（含装配期意外类型）都属"视觉未就绪"，落到 UNEXPECTED 反而丢阶段信息；
  KeyboardInterrupt 同阶段映射 VISION_INIT_FAILED 与 §4.1"读回中断"同族处理。
  SystemExit 显式直通保持全装配一致。
- **DEC-P1-05-E（utterances 耗尽=小段真实墙钟 sleep + 返回空串，循环往复）**：
  P5 §2 同一小节先写"耗尽后返回空串模拟静音"（代码注释）、后写"耗尽后按真实
  墙钟阻塞等 Ctrl-C（可用小段 sleep），不持续空串忙循环"——字面并存的两要求以
  "每 0.2s 返回一个空串"实现：空串喂给会话的 continue 分支（会话语义与生产一致），
  sleep 保证不忙循环，Ctrl-C 随时可从 sleep 中打断走 terminate。`IDLE_POLL_S`
  为入口层名义常量，非业务参数。
- **DEC-P1-05-F（install_stubs 全局守卫 + `reset_stubs_for_tests`）**：P5 §2 的
  "重复调用拒绝"登记在入口模块级（一次进程一个 mock 装配），未做 per-module-target
  参数化——保持 `install_stubs(cfg)` 签名逐字；同进程测试复用 runlog/shutdown 已
  建立的 `reset_for_tests` 惯例恢复现场，生产代码不调用。
- **DEC-P1-05-G（attempts 耗尽走 `terminate("SCENARIO_ATTEMPTS_EXHAUSTED")`）**：
  任务书允许"抛/terminate"。取 terminate：它发生在真实运动之前、唯一出口，
  且 detail 指明 place_id 供定位；抛出则会被会话兜底洗成 UNEXPECTED，丢失场景
  拒绝语义。哨兵值用例证明拒绝先于开关写入。
- **DEC-P1-05-H（mock 的 `cold_start_recover`/`thresholds_from_params`/
  `log_startup`/`run_session` 全部从 main import 而非复制）**：D15"复用生产会话
  不复制业务循环"的最小闭包；`log_startup` 是装配与 mock 共享的 §7 事件生产者，
  复制两份哈希逻辑正是"配置文件哈希冒充资源哈希"这类错误的温床。为此 main 多
  导出 `log_startup`/`thresholds_from_params`/`file_sha256`（后者为前者的公开
  辅助），均为纯函数、无装配副作用。
- **DEC-P1-05-I（mock profile 副本用相对引用而非复制 motor_calibration.json）**：
  修改范围只允许提交列出的资产文件；把校准文件指回
  `../../../calibration/SIM_ROBOT/simulation/motor_calibration.json` 同样满足
  "从该目录可解析"，且避免第二份校准数据漂移。urdf_path 因目录同深（均 3 层）
  无需改动，实测 `urdf resolves: True`。
- **DEC-P1-05-J（副本 places 名义坐标取 |y|=0.15/0.16/0.18/0.21、x=0.30、z=0.030）**：
  "target_bounds 之外语义上合理"——A 槽位三连排在基座一侧成行（等距 0.03m），

- **DEC-P1-05-K（T25"会话不进入"以 run_session 探针断言）**：assemble_production

- **DEC-P1-05-L（`preflight_failed` 详情用 `check`/`reason` 双字段；terminate
