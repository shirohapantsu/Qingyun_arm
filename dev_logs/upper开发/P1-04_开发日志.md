## 2. 实现说明（文件 + 关键符号）

### 2.1 `qingyun/plans/base.py`（新增，654 行）

- 模块级注入缝隙（§3.6 末段/§2 末段）：
  `from qingyun.grabbing import vision`（**模块对象**，测试整体替换）、
  `from qingyun import runlog, shutdown`（同）、
  `from qingyun.grabbing.vision import NoTarget, VisionHardError`（**按名导入真实类**，
  使 `except` 子句不随 `vision` 名字被替换而改变识别目标）、
  `_input: Callable[[str], str] = input`（D13 唯一人工输入口）。
  用例 `test_A05` 逐条钉死这四条缝隙本身（含 `base.NoTarget is vision.NoTarget`）。
- 常量：`RETRYABLE_STATUSES`（§3.5 逐字五状态）、`MAX_CONSECUTIVE_FAILURES = 10`（D02）、
  `NO_TARGET_STREAK_LIMIT = 3`（§6.2 三连）、`STAGE_FAULT_UNCONTROLLED =
  "FAULT_UNCONTROLLED"`（不 import `arm_control`，避免 placo/URDF 进 plans 的 import 链；
  两侧一致性由 `test_A06` 文本对等钉死）。
- `class BasePlan`：四个 ClassVar（`TASK_ID/AREA_THRESHOLD_M2/A_PLACE_IDS/B_PLACE_ID/
  C_PLACE_ID`，`ClassVar` 标注，命名与 `preflight._plan_class_attrs` 读的完全一致）；
  `__init__(self, arm: ArmController)` 把 §6.1 四个计数器 + `success_count/
  failure_counts/scan_id/attempt_id` 全部归零；`ArmController` 只在 `TYPE_CHECKING`
  块里引用（运行时间接依赖为零）。
- `run()` 严格按 §6.2 顺序逐行落地（注释里带步骤号 0→7）：
  每轮 `scan_id += 1` + `with runlog.context(scan_id=self.scan_id)` 包住
  "扫描→分配→抓取→恢复"（`continue`/`return`/`SystemExit` 三种离开方式都由 `with`
  释放，`test_C06/test_C07` 分别断言）；`except NoTarget` → `ignore=0`、
  `no_target_streak+1`、三连 `_finish` + `return`；`except VisionHardError` →
  `terminate("VISION_HARD_ERROR", …)`；成功 → `no_target_streak=0` →
  `_validate_target_contract` → `classify` → `next_place_id` → `attempt_id += 1` →
  `runlog.event("assign", …)` → `arm.grasp_and_place(target, place_id)` →
  `_audit_grasp_result`（事件 + 非 SUCCESS 累计 `failure_counts`，排在任何分支之前）→
  1 失控阶段 → 2 SUCCESS → 3 非重试类 → 4 `ignore+1`/`failures+1` →
  5 `ignore ≥ valid_count` → `NO_GRASPABLE_TARGET`（detail 逐字用规格的
  `ignore=… ≥ valid_count=…，末次 {status}/{stage}`）→ 6 预算 →
  7 `_recover(result)`。
- `classify(target)`：`ripe is False → "C"`；否则 `length_m*width_m >= K → "A"`、
  余 "B"；K 为 None/非数值/bool/非有限/非正 → `terminate("PLAN_CONFIG_INVALID")`
  （§3.5"不能靠 classify 默认填值"的运行期兜底，见 DEC-P1-04-F）。
- `next_place_id(grade)`：§6.3 逐字（`A_SLOTS_EXHAUSTED`/`PLAN_CONFIG_INVALID` 两个
  terminate 与规格文案一致；分配即消耗，末尾 `raise AssertionError("unreachable")`
  只防"terminate 被换成不抛的替身"后静默返回 None）。
- `_validate_target_contract(target)` + `_require_contract(target)`（§6.4 五条）：
  六字段存在性；`length_m`/`width_m` 为非 bool 有限数值且 `> 0` 且
  `length_m ≥ width_m`；`ripe` 严格 bool；`valid_count` 非 bool 整数、`> 0`、
  `> self.ignore`；`yaw_deg` 非 bool 有限且 `∈ [-90,90)`。违约统一经
  `_ContractViolation` 内部信号 → `terminate("VISION_CONTRACT_VIOLATION", detail)`；
  位置/深层几何不重复实现（归运动 INVALID_INPUT）。
- `_recover(result)`（§6.5 七行逐条）：IK_FAILED/PLAN_INVALID 且 `recovery_required`
  → `terminate(状态名, "D08：…")`；不带 → 记一条 `recovery(mode="skip")` 后返回
  （不 reset、不搬臂）；MISS/UNCERTAIN/SLIP 且 `recovery_required=False`、或 MISS 而
  `holding≠EMPTY` → `_result_contract_violation`（detail 保留原 result 六个字段）；
  UNCERTAIN/SLIP → `_confirm_scene` 人工确认；然后 `_return_route`。
- `_confirm_scene`：两行 `runlog.console` 打印 status/stage/holding/reason →
  `_input("确认物体已处置、可继续后回车...")` 阻塞；`EOFError`/`KeyboardInterrupt`
  → `terminate("MANUAL_CONFIRM_ABORTED")`（D13；回车即确认，不解释返回值）。
- `_return_route(result, *, mode)`：读 `arm.params.workspace.safe_waypoints_deg`
  （ndarray 行优先，按列表顺序）与 `home_joints_deg` → `arm.reset_fault()` →
  逐个 `arm.move_joints(wp)` → `arm.move_joints(home)` →
  `runlog.event("recovery", mode/status/stage/holding/reason/reset/waypoint_moves/
  home/confirm/attempt_id)`。任一步异常 → `_recovery_failed` →
  记 `recovery(failed_step=…, error=…)` 后 `terminate("RECOVERY_FAILED")`，
  不追加 ignore、不重试恢复。
- `_audit_grasp_result` / `_finish` / `_failure_counts_text` / `_terminate`：
  `task_done` 事件带 `reason/success/failure_counts/a_slots_used` +
  `no_target_streak/consecutive_failures/ignore/attempts`；终端一行
  `任务完成：结束原因=…，成功=…，失败码计数=…，已分配优品槽位=…`
  （§6.6 逐字，失败码计数用紧凑 JSON 渲染，`{}` 表示零失败）。

- `Call`（frozen dataclass：name/args/kwargs）+ `EventScript`（按序消费，元素是"返回值"
  或"要抛出的异常实例"；`on_exhausted` 用哨兵 `EXHAUST_HARD_ERROR`/

  `NoTarget`/`VisionHardError`（类属性同名，且 plan 的 except 用的是从桩按名导入的
  同一对象）；记录 `get_target_calls`（含每次 `ignore` 实参、调用序号、剩余脚本长度）、
  `configure_calls`、`init_calls`；默认耗尽抛 `VisionHardError`（防"静默重复最后一个

- `FakeArm`：构造参数 `(results, params=None, *, motor=None, on_exhausted)`；
  `params` 缺省用 `make_arm_params()`（`workspace.safe_waypoints_deg` 为 (2,5)
  float64 ndarray、`home_joints_deg` 为 (5,)、`places` 映射），与真实 `MotionParams`
  同为"按行迭代"的 ndarray 语义；`motor` 属性保留给 P1-05 的冷启动复位。
  公开原语同名同形：`grasp_and_place/move_joints/move_cartesian_top_down/open_gripper/
  close_gripper/wait_settled/reset_fault`，全部经 `_begin()` 记入有序 `events` 与
  `call_counts`（`move_joints` 的参数归一成 `tuple[float]` 以便按值断言）；

  断言辅助 `command_sequence/calls_of/count_of/place_ids/grasp_targets/
  moved_positions/motion_command_count/reset_ledger`。
  脚本耗尽抛 `AssertionError`（测试基建错误，不是业务状态码）。
- `make_result(status, *, stage/holding/recovery_required/reason/place_id)`：
  未给的字段取该状态的**典型组合**（抄自 `arm_control._refuse/_early_fail/

- `FakeASR`/`FakeLLM`：`init(cfg)` + `listen_and_transcribe()`/`select_plan(text)`，

  "不能把省略号当实际错误详情"——纯字面会把相机断流与深度帧全废洗成同一句话。
  取 `f"视觉管线故障：{exc}"`：前缀逐字保留（用例按 `startswith` 钉死），后缀是真实
  故障原因。`NO_GRASPABLE_TARGET` 的 detail 则**逐字**照抄规格模板（T06/T26 按全等断言）。
- **DEC-P1-04-C（不 import `arm_control`，改用同名文本常量 + 对等用例）**：
  候选①`from qingyun.grabbing.arm_control import STAGE_FAULT_UNCONTROLLED` 会把
  placo/URDF/IK 栈拉进 plans 的运行期 import 链（`plan` 只需一个字符串），也会让
  `scripts/run_mock.py` 之外的轻量装配被迫加载运动栈；候选②直接写字面量——两侧改名
  就静默失配。取③：常量写在本模块并在注释里点名来源，另用 `test_A06` 与
  `arm_control` 的真实常量做双向对等断言（任一侧改字面量即失败）。
- **DEC-P1-04-D（三连阈值提取为 `NO_TARGET_STREAK_LIMIT = 3`）**：§3.5 的常量清单里没有
  它，但 §6.2/§9 把"三连"当固定契约。硬编码 3 会让"为什么是 3"无处注释；把它命名并
  导出后，`test_T03/T04/T19/T23` 可以按常量而非字面量断言轮次，规格改动（若哪天调成
  4）只需动一处。它不是新的业务语义，只是同一常数的具名。
- **DEC-P1-04-E（§6.4 链式判据拆成三句）**：`length_m >= width_m > 0` 拆成
  "length 为正""width 为正""length 不小于 width"三次判定，判定的**集合完全等价**
  （M15/M22 变异证明两半都有牙），换来的是 terminate detail 能指到具体坏字段。
  规格 §6.4 只给判据不给文案，此拆分不改变任何接受/拒绝边界。
- **DEC-P1-04-F（classify 对非法 K 走 `PLAN_CONFIG_INVALID` 而不是抛 TypeError）**：
  §3.2 第 3 条要求预检拒绝 `None`/非有限/非正/bool，§3.5 又写"不能靠 classify 默认
  填值"。若 classify 什么都不做，`float >= None` 会变成未预期 TypeError 走
  `UNEXPECTED`，把"K 未标定"降级成一条栈回溯。取运行期同判据 +
  `PLAN_CONFIG_INVALID` 显式终止（detail 里点名"预检应已拒绝运行"），并由
  `test_B06_*`（6 例，含 `True` 这个 bool 陷阱）覆盖。这条兜底不放松预检，
  预检仍是第一道。
- **DEC-P1-04-G（`recovery` 事件字段用 ASCII 名 `mode` 承载 §7 的"方式"）**：
  §7 表格是中文说明、事件行是 JSONL，键名进 JSON 后需要被 P5 的验收脚本与 grep
  稳定消费，故取 `mode/reset/waypoint_moves/home/confirm/failed_step/error`；
  值 `auto/manual/skip` 逐字用规格括号里的三个英文词。`skip` 的引入见 DEC-P1-04-S。
- **DEC-P1-04-H（`grasp_result` 事件额外带 `place_id/grade/ignore_used/valid_count`）**：
  §7 是最低字段要求；带上本次分配的上下文后，单条日志就能回答"这一枪打的是哪个
  落点、视觉当时报了几颗"。`grade` 只出现在 plans 自己的事件里（§7 末段），运动侧
  仍然只见 place_id。
- **DEC-P1-04-I（`failure_counts` 的键用状态名字符串而不是枚举对象）**：日志要能直接
  `json.dumps`，且 §6.6 的终端行需要稳定顺序 → `sort_keys=True` 紧凑 JSON；
  `dict(self.failure_counts)` 传快照，避免 runlog 之后被复用同一 dict 造成串改。
- **DEC-P1-04-J（审计函数命名 `_audit_grasp_result` 并显式排在分发之前）**：§6.2 的
  注释"任何直死/封顶分支之前都必须完成该次结果审计"是最容易被"顺手优化"掉的一条
  （把它并进分支里就不会有 terminate 前的最后一条记录）。单独成函数 + 步骤号注释 +
  `test_DP02`（事件顺序 `assign → grasp_result → terminate`）三重视障。
- **DEC-P1-04-K（不给 NoTarget 发 plan 侧事件）**：见 §5"NoTarget 不发日志事件"条。
  替代方案（发一条 `no_target` 事件）会让 `sink.kinds == ["task_done"]` 这类
  "整场循环只写了这一条"的强断言变成枚举式断言，且抢了 P3 `vision_scan` 的表达位。
- **DEC-P1-04-L（替身脚本耗尽默认抛错 + `on_exhausted` 用哨兵而非保留字符串）**：
  候选①"重复最后一个目标"——会让 T05/T06 这类"轮次数必须精确"的用例假通过；
  候选②把 `"invalid"`/`""` 这类**业务合法值**当保留字识别——LLM 的 `invalid` 与
  ASR 的空串本身就是合法返回值，字符串保留字会与之混淆。取③：内建行为用
  `EXHAUST_HARD_ERROR`/`EXHAUST_REPEAT_LAST` 哨兵对象，替身各自把别名
  （`no_target`/`empty`/`invalid`）在构造时映射成值，未知别名直接 `ValueError`

  而不是业务异常：多跑一轮是用例编排错误，不该被 plan 当成可分发的运动结果。
- **DEC-P1-04-M（K 用乘式 `0.05 * 0.024` 定义）**：`test_T32` 的"等于阈值归 A"若用
  十进制字面量比较浮点乘积，会在别的机器/别的四舍五入路径上变成不稳定断言。用同一

  避免资产本身被改坏。
- **DEC-P1-04-N（autouse fixture 默认把 `_input` 换成"调用即 AssertionError"）**：
  D14 封顶、M13 类路径、预算耗尽等分支都要求"**没有**人工确认"。只靠"没断言"是
  无法证伪的；默认封死之后，任何多走一步的实现都会立刻在无关用例上炸出来，
  而 T15/T16 用显式 `monkeypatch.setattr` 覆盖同一名字（也顺带证明这个缝隙有效）。
- **DEC-P1-04-O（人工确认打印走 `runlog.console`）**：§3.4 把终端简洁输出定成

- **DEC-P1-04-Q（`next_place_id` 末尾 `raise AssertionError("unreachable")`）**：

- **DEC-P1-04-R（A 槽位上限读 `len(self.A_PLACE_IDS)` 而不写死 3）**：§3.5 注明

- **DEC-P1-04-S（`recovery` 事件也覆盖 skip 分支，并给 manual/auto 共同的回程记
