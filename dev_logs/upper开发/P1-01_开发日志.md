## 2. 实现说明（文件 + 关键符号）

### 2.1 `configs/app_config.py`（新增）

模块级常量：
- `ROOT = Path(__file__).resolve().parents[1]`（不依赖启动目录）。
- `PRODUCTION_APP_PATH = ROOT/"configs/app.local.json"`、`MOCK_APP_PATH = ROOT/"configs/app.mock.json"`
  （D15 固定入口，供 P1-05 装配时引用；本任务不提供调用方）。
- `SECRETS_LOCAL_PATH = ROOT/"configs/secrets.local.json"`（P1 §3.1 固定位置；**模块级变量**，
  preflight 在调用时按全局查找读取，测试可 monkeypatch）。
- `SECRET_KEYS = ("dashscope_api_key", "deepseek_api_key")`、`ALLOWED_PLAN_KEYS = frozenset({"strawberry"})`
  （D06/D07）、`ALLOWED_YAW_OFFSET_DEG = (0.0, 90.0)`。

异常层：
- `AppConfigError(ValueError)`：与 `ParamsError` 同形态的 `(field_path, message)` 两参数构造，
  `str(exc) == f"{field_path}: {message}"`，属性 `field_path`/`message`。
- `PreflightError(AppConfigError)`：额外 `check` 属性，取值 `registry/places/area_threshold/
  vision_config/prompt/yaw_offset/secrets/mock_assets/log_dir`；`field_path` 为 `preflight.<check>`。
  调用方只捕获 `AppConfigError` 即可同时接住加载与预检失败，需要区分时用 isinstance。

纯数据类（字段与 §3.1 逐字一致，全部 `@dataclass(frozen=True)`）：
`AsrSettings(model, endpoint, cloud_total_timeout_s)`、`LlmSettings(model, base_url,
total_timeout_s)`、`MockSettings(asr_script_path: Path, vision_replay_dir: Path)`、
`AppConfig(profile_path, vision_config_path, prompt_path, log_dir, asr, llm, mock=None)`，
四个路径字段均为已解析的绝对 `Path`。

校验原语（与 motion_params 同一严格度）：
`_reject_constant`（JSON 的 NaN/Infinity 扩展字面量直接拒）、`_load_json`、`_require_object`
（非对象/未知键/缺失键）、`_require_str`（非字符串或空白拒）、`_require_positive_finite`
（bool 与非数值拒、非有限拒、≤0 拒）、`_resolve_path`（相对基目录 → `.resolve()` 绝对化，
绝对值原样保留；只解析不查存在性）。

`load_app_config(path, *, entry)`：先校验 entry ∈ {"production","mock"}（不从 JSON/文件名/CLI
猜测）；文件存在 + 合法 JSON；**production 出现 mock 段**走专用拒绝分支（消息点名
`app.mock.json`），mock 入口把 `mock` 并入必选键集合；顶层与 asr/llm/mock 子段未知键一律拒绝；
超时/字符串/路径逐项校验后构造 `AppConfig`。

`load_secrets(path)`：文件存在 + 合法 JSON + 恰好两键（未知键拒绝）+ 值必须为字符串；
**空字符串允许返回**（非空要求属 preflight 第 7 条）。异常消息只出现键名，不出现键值。

`preflight(cfg, params, registry)`：§3.2 八条按编号顺序执行，各自私有函数，失败即抛
`PreflightError` 并指明检查项：
1. `_check_registry`/`_plan_class_attrs`：键集合恰为 `{"strawberry"}`；五个契约属性存在
   （`hasattr` 鸭子类型，不 import plans）；`TASK_ID == 键`；`A_PLACE_IDS` 为非空
   `tuple[str]` 且无重复；`B_PLACE_ID`/`C_PLACE_ID` 为非空字符串；A/B/C 三组互不重叠。
2. `_check_places`：A∪B∪C 每个 place_id ∈ `params.places`（消息列出 profile 已有的 places）。
3. `_check_area_threshold`：`AREA_THRESHOLD_M2` 非 None（"K 未标定"提示）、非 bool、数值、
   有限且 > 0。
4. `_check_vision_config`：`cfg.vision_config_path` 是存在的文件且可解析为 JSON 对象；
   **不读内部字段**（L7 收窄，交 P3 init）。
5. `_check_prompt`：`cfg.prompt_path` 存在且 `strip()` 后非空。
6. `_check_yaw_offset`：`params.grasp.yaw_offset_deg ∈ {0, 90}`（产品限制，非几何必然）。
7. `_check_secrets`（`cfg.mock is None` 时）：`load_secrets(SECRETS_LOCAL_PATH)` 的两 key
   `strip()` 后非空。mock 入口跳过（D15：mock 不加载密钥）。
8. `_check_mock_assets`（mock 时）+ `_check_log_dir`（两入口）：`asr_script_path` 为已存在
   文件、`vision_replay_dir` 为已存在目录；`log_dir` 已存在且可写，或 `mkdir(parents=True)`
   创建后再判 `os.access(W_OK|X_OK)`。

`preflight` 及其依赖只 import 标准库与 `configs.motion_params`（无 qingyun/serial/placo），
测试用 AST 静态断言这条边界（§3.2"先于 motor 构造"的可验证形式）。

- **耗时**：本任务全部用例为纯文件/JSON 操作，`tests/test_app_config.py` 单独跑 0.18s，
  与 `test_motion_params.py` 合跑 0.30s；全量回归耗时由 P0-01 登记的 ~570s 基线决定
  （DEC-001），本任务不新增慢用例。全量结果见 §3 表格（0 failed）。
- **仓库仿真 profile 的 places 只有 `default`/`bin`**（已核实
  `calibration/SIM_ROBOT/simulation/profile.json`），因此 P1 §3.2 第 2 条与替身 plan 的

  副本追加四个落点（`sim_params_with_strawberry_places`），不改仓库真配置；
  `test_仓库仿真profile的places只有default与bin` 把这一环境事实钉成断言，避免后来者误以为
  可以直接拿 `load_sim()` 跑完整预检。
- **仿真 profile 的 `grasp.yaw_offset_deg = 0.0`**（已核实），落在第 6 条允许集合内，
  故第 6 条无需替身即可通过；负向用例用 `stub_params(yaw_offset_deg=…)` 替身，不动真配置。
- **`load_app_config` 不校验 endpoint 的 URL 形态、也不校验模型名是否为占位值**：
  §3.1 只要求字符串非空，且"模板占位模型名不能用于真实请求，P2 init 拒绝占位值"明确把
  该职责交给 P2。`secrets`/profile 的存在性同理属预检与 `load_motion_params`。
- **preflight 第 4 条只到"合法 JSON 对象"这一层**（L7 收窄）：vision 配置内部 schema 属 P3，
  本任务不解析，也不复制第二份视觉 schema。
- **`configs/app.mock.json` 与其 fixture 资产不在本任务范围**（P1-05 冒烟资产 / P5 场景资产）；
  本任务只保证该结构能被 `entry="mock"` 正确加载与预检（用 tmp 副本演示）。

  `Sts3215MotorController(params)` 之前；捕获 `AppConfigError`（含其子类 `PreflightError`）
  映射 `terminate("APP_CONFIG_INVALID"/...)`，`PreflightError.check` 可直接作为 detail 的
  失败项标识（§7 的 `preflight_failed` 事件字段）。
- **P1-04（plans）**：`StrawberryPlan` 必须提供 `TASK_ID/A_PLACE_IDS/B_PLACE_ID/C_PLACE_ID/
  AREA_THRESHOLD_M2` 五个类属性；`A_PLACE_IDS` 必须是**非空 tuple**（list 会被预检拒绝）、
  三组 ID 互不重叠；P4 回填前 `AREA_THRESHOLD_M2 = None` → 生产预检按"K 未标定"拒绝运行；

- **P1-02/P2/P3**：`load_secrets` 返回的键值只能内存使用，日志/异常不得回显（本模块的

## 7. 自主决策

- **DEC-P1-01-A（preflight 内部按模块级 `SECRETS_LOCAL_PATH` 定位 secrets，不改公开签名）**：
  P1 §3.2 第 7 条要求"secrets.local.json 两个 API key 非空"，但 `preflight(cfg, params,
  registry)` 签名没有 secrets 参数，而 §3.1 又把 secrets 位置固定为
  `ROOT/configs/secrets.local.json`（通过 `__file__` 定位）。故实现为第 7 条内部调用
  `load_secrets(SECRETS_LOCAL_PATH)`，`SECRETS_LOCAL_PATH` 保持模块级可 monkeypatch 变量。
  备选：入口在 preflight 前加载并作为第 4 参传入——会改动 §3.1 公开签名（任务明令禁止），
  且让 mock 入口也必须构造一个"空的 secrets"参数，语义更含糊。代价：preflight 有一处文件
  读取副作用（只读），测试用 monkeypatch 定位。
- **DEC-P1-01-B（`PreflightError(AppConfigError)` + `check` 标识）**：任务允许"专用可区分
  异常（或等价可区分类型）"。取子类 + 稳定 `check` 名：既允许 P1-05 单一 catch
  `AppConfigError`，又允许按检查项映射 terminate detail，测试可精确断言"哪一条失败"，
  并支撑"第 1 条先于其他条"的顺序断言（`test_注册表检查先于其他检查项`）。
- **DEC-P1-01-C（registry 注解用 `Mapping[str, type]`，鸭子类型检查）**：`qingyun/plans/base.py`
  属 P1-04 产物，本阶段 import 会造成反向依赖与导入失败；按任务指示用属性存在性检查替代
  isinstance，docstring 记录该约束来源。
- **DEC-P1-01-D（路径 `.resolve()` 绝对化；加载器不查存在性）**：`(base / rel).resolve()`
  使 `../` 可词法比较（`Path("configs/../prompt.md") != Path("prompt.md")` 的坑），且与
  `tests/support.py` 的 `ROOT` 同风格。存在性/哈希属预检与 `load_motion_params`，加载器保持
  单一职责，也让替身路径的负向测试可控。
- **DEC-P1-01-E（preflight 第 4 条额外要求 vision JSON 顶层为对象；第 5 条按 strip 后非空判"非空"；
  第 8 条把 `asr_script_path` 判为文件、`vision_replay_dir` 判为目录）**：均为"存在且合法"
  的最小可判定形态，不引入字段级解析（守住 L7 收窄）。P5 §2 的 vision.json 与 scenario.json
  顶层都是对象、frames 是目录，故不会误拒合法资产。`log_dir` 判可写只查 `os.access`，
  不写探针文件，避免在只读或生产根目录留下垃圾。
- **DEC-P1-01-F（负向断言改为比对 `exc.value.field_path`/`message` 正文）**：自查发现
  pytest `tmp_path` 目录名包含测试函数名，"关键词出现在 `str(exc)`"这类断言可能被文件路径
  意外满足（实测变异后仍通过）。改为断言结构化字段，保证测试真的咬住规则；随后 13 处变异
  逐条复跑确认全部被拒。
- **DEC-P1-01-G（`load_secrets` 拒绝未知键；只校验键存在与值为字符串，允许空串返回）**：
  与 app.json 的"未知键拒绝"同一严格度，防止密钥文件漂移出未审计字段；"非空"属生产附加
  检查（§3.2 第 7 条），因此模板可原样加载、mock 入口可零密钥运行。若 P2 需要扩展密钥字段，
  应同步改 `SECRET_KEYS` 与文档（已写入交接事项）。
- **DEC-P1-01-H（额外导出 `PRODUCTION_APP_PATH`/`MOCK_APP_PATH` 常量）**：D15 把两个入口路径
  钉为固定值，常量放配置层可由 P1-05 直接复用、并由测试钉住（避免 main 里出现字符串字面量
  分叉）。本模块不实现入口逻辑，只给路径事实。
