## 2. 协议与数据契约变更

### ASR

生产模板 `configs/app.json` 的模型名改为官方该协议对应的 `qwen3-asr-flash`；同步 P1/P2 实施文档、决策索引及测试夹具。北京 DashScope 原生同步 endpoint 保留，请求使用 WAV Data URI；未修改本地账号密钥或发起真实云请求。

协议依据：[阿里云 Qwen-ASR 官方 API](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)。本次核对并测试的是原生请求/响应结构及本地 HTTP 行为，真实账号的模型权限仍需现场验证。

### 抓放 JSONL

新增必需字段 `planned_place_position_m` 和 `planned_place_yaw_deg`。原有 target_position_m/target_yaw_deg 保持视觉抓取目标语义。中心误差改为 $e_p=\|p_{actual}-p_{place}\|_2$；yaw 误差使用配置放置 yaw 与实际 yaw 的模 180° 最小角差。

审查中的正确放置例子现在得到 **0 m / 0°**；30 条字符串成功标志或 NaN 观察样本不能作为合格 hardware 验收输入。began_descend=null 仍保留在下降分母内并使验收不通过，未测损伤观察仍是 pending。

旧 JSONL 若缺 planned_place_* 会被拒绝。历史放置误差不能直接沿用，应绑定原候选 profile 的配置落点重新导出/复算并重新 validate；无法补齐观察证据时保持未验收。

### 部署清单与报告

保留 schema_version=1，收紧声明完整性；旧通用角色不能代替以下角色，各角色恰好一份：

`urdf`、`motor_calibration`、`requirements`、`weights`、`class_map`、`camera_intrinsics`、`camera_extrinsic`、`app_config`、`vision_config`、`prompt`、`mock_config`、`sample_manifest`、`grade_samples`。

必需报告类别各一份：`profile_validation`、`demo_acceptance`、`grade_threshold`、`vision_accuracy`、`footprint_validation`、`ripe_confusion`；可另附 `place_calibration`。

K 报告按拟合工具的真实 schema 校验，并绑定 grade_samples 的输入 SHA256。视觉报告要求 overall_pass/operator_reviewed 严格为 true。profile_validation 使用八阶段共享校验；纯 mock/offline、空/缺失阶段、失败阶段/检查及字符串通过标志均拒绝。

完整模板和报告关联规则已同步到[部署检查与验收清单](../../docs/部署检查与验收清单.md)。发布检查中的离线合成树仅供验证校验逻辑，不能作为实际测量证据。
