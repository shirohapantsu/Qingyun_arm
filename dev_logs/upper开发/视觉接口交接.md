## 1. 公共类型与字段单位（P0 已冻结，configs/common_interface.py）

```python
@dataclass(frozen=True)
class VisionInterface:
    position: FloatArray  # np.float64，shape (3,)，base_link 系，单位 m，几何中心
    yaw_deg: float        # 物体水平长轴相对基座 +X，绕 +Z 为正，模 180°，[-90,90)
    length_m: float       # 长轴长度，m
    width_m: float        # 短轴长度，m（契约要求 length_m ≥ width_m > 0）
    ripe: bool            # 成熟度（严格 bool；C 级唯一来源）
    valid_count: int      # 当前扫描过滤后合法候选总数（非剩余数；ignore 封顶判据）

@dataclass(frozen=True)
class VisionThresholds:   # P1 从已校验 motion profile 组装，经 configure() 注入
    target_bounds_m: FloatArray    # (2,3) [min,max]，合法候选中心判定域，m
    object_envelope_m: FloatArray  # (3,)   物体长、宽、高，m；与运动 profile 同源同值
    clearance_m: float             # 邻物最小净距，m
    approach_height_m: float       # 接近高度，m（头顶净空检查推导用）
    table_z_m: float               # 桌面平面高度，base_link，m（几何中心估计用）
    table_flatness_m: float        # 桌面平整度容差，m
```

来源映射（P0 §3）：`workspace.target_bounds_m`、`grasp.object_envelope_m`、
`collision.clearance_m`、`grasp.approach_height_m`、`workspace.table_z_m`、
`workspace.table_flatness_m`；构造时数组 `np.asarray(..., float64)` 并复制（已实现于
`__post_init__`）。视觉模块**只导入本类型**，不得 import motion_params/plans/main/app_config
（P3 §2 依赖方向）。检测参数 `detection_floor/conf_threshold` 等属视觉配置，不进入公共类型。

## 2. 函数签名与异常语义（vision.py 公开面；P1 §3.6 / P3 §3）

```python
class NoTarget(Exception): ...         # 业务"无目标"：ROI 无物体/全部被过滤/跳尽
class VisionHardError(Exception): ...  # 硬故障：相机/帧/管线/标定/调用序错误 → terminate

def configure(thresholds: VisionThresholds, config_path: Path) -> None
def init() -> None
def get_target(ignore: int = 0) -> VisionInterface
```

- 基类固定为 `Exception`（不是 RuntimeError）；两类互不为父子。调用方
  `qingyun/plans/base.py` 按名导入真实类做 `except` 分派，**类名与基类不得改**。
- `configure`：main 冷启动段在 `init()` 前调用**恰好一次**；未 configure 即 init、重复
  configure、init 后 configure → `VisionHardError`（P3-T15）。`config_path` 指向
  `configs/vision.local.json`；其内相对路径**相对该文件所在目录**解析（D16）；P1 预检只查
  "存在+合法 JSON+顶层对象"（L7 收窄），schema/模型/标定包校验整体归队友 init。
- `init`：一次性加载 YOLO 权重（不得懒加载、不得放 import 时）、打开相机并验证可采集一帧
  （replay 验证目录非空且首帧可读，只验证**不消费**）；任何阶段故障抛 `VisionHardError`，
  **不得伪装成 NoTarget**（P1 §4 步骤 10）。ready 前完成权重/内外参哈希与相机/流身份记录
  （P1 §7）。
- `get_target(ignore)`：前置条件臂在 home；一次调用 = 一次完整采集-检测-测量-过滤-排名，
  无跨调用缓存（内部多帧融合不受限）；返回确定性排名第 `ignore+1` 名；
  `ignore ≥ valid_count` 必抛 `NoTarget`（原因 `skip_exhausted`）；`ignore` 非负 int，
  负值/非整数属调用方程序错误抛 `VisionHardError`（不静默取 0）。每次调用（含 NoTarget 与
  HardError）**恰好一条** `runlog.event("vision_scan", ...)` 结论日志（P3 §6 第 8 步、
  P1 §7 字段：scan_id、ignore、valid_count、候选数、逐项拒绝原因）。
- 业务计数语义（调用方已实现，队友只需保持异常类型正确）：`NoTarget` → plan 置
  ignore=0、no_target_streak+1，三连为唯一正常完成出口（D14）；`VisionHardError` →
  `terminate("VISION_HARD_ERROR")` 不参与计数。plan 侧还会复核返回值
  （`valid_count > requested_ignore`、`length_m ≥ width_m > 0`、ripe 严格 bool、
  yaw ∈ [-90,90)，P1 §6.4）——违约直接 terminate，不回头修数据。
- 桩现状（队友替换前）：三函数一律抛 `VisionHardError("视觉未实现（P3/队友替换本桩）…")`，
  含契约要点说明；可正常 import，零依赖副作用（tests/test_module_stubs.py 已钉死）。

## 3. 调用顺序（运行时装配）

生产 main（`main.py` `assemble_production`，§4 步骤 1–11）与 mock 入口
（`scripts/run_mock.py` `assemble`，P5 §2）顺序一致：

```
load_app_config → runlog.init → startup → load_motion_params → preflight（此时零串口）
→ 驱动构造/握手 → ArmController → 冷启动复位
→ asr.init → cloud_model.init            （mock 入口：install_stubs，不调真实 init）
→ vision.configure(VisionThresholds(…从 params), cfg.vision_config_path)
→ vision.init()                            （失败 → terminate("VISION_INIT_FAILED")）
→ runlog.event("ready")
→ run_session：asr → cloud_model.select_plan → 每任务新建 Plan
   → Plan.run(): 每轮 scan_id+1 → get_target(ignore) → classify → next_place_id
   → grasp_and_place → 分发/恢复矩阵（ignore 跳选、D14 封顶、D02 预算、D08）
```

## 5. 日志与资源生命周期职责

- 视觉只经 `qingyun.runlog` 记日志（`vision_scan` 等，事件自动带
  session_id/task_instance_id/scan_id context——scan_id 由 plans 每轮递增包住，P1 §3.4）；
  独立 P3 测试/工具自行建立自己的 runlog 上下文。
- 权重与内外参哈希在 ready 前记录（P1 §7）；`NoTarget`/`VisionHardError` 路径也必须完成
  当次 `vision_scan` 记录（恰好一条，含原因码）。
- 资源：相机句柄生命周期归 vision 模块内部（init 打开、进程退出前释放）；
  `terminate` 出口保证零追加运动命令，视觉侧关闭动作不得触碰串口/舵机（shutdown §3.3 边界）。
  mock 入口豁免"生产禁 import tests"仅限 `scripts/run_mock.py`。

## 7. FakeVision（测试替身，tests/support_upper.py）

- 供 plans/main/E2E 测试：脚本化返回预设 `VisionInterface` 或抛**真实**
  `NoTarget`/`VisionHardError`；记录调用参数（含 ignore 序列）；耗尽默认抛错防静默假通过。
- 使用方式：测试内 monkeypatch `qingyun.plans.base.vision`，或经
  `run_mock.assemble(cfg, vision=FakeVision(...))` 注入装配。
- 边界：替身不做任何图像处理/候选筛选/几何计算/replay；生产入口永不自动回退替身。
  队友的视觉单测/集成资产请新建自己的文件（P3 §7 的 fixtures 目录与 test_vision_pipeline.py），
  不要扩展 support_upper.py 承担真实管线验证。
