## 2. 实现说明（文件 + 关键符号）

### 2.1 `qingyun/runlog.py`（新增）

模块级状态（单线程同步、无锁，P1 §3.4）：`_session_id/_log_path/_file/
_context/_sink`，`RESERVED_KEYS = ("kind", "ts", "session_id")`。

- `init(log_dir: Path) -> str`：mkdir(parents) 后创建
  `run-YYYYMMDDTHHMMSSZ-<pid>.jsonl`（追加模式打开），**session_id=文件主名**
  （与会话一一对应）。**一次进程一个 runlog**：重复 init 在动任何文件系统之前
  抛 `RuntimeError`（含当前 session_id 与"测试复用请 reset_for_tests"指引）。
- `event(kind, **fields)`：未 init → `RuntimeError("…未初始化…")`；已 close 且
  无 sink → `RuntimeError("…已关闭…")`；kind 空/非 str、字段名非 str 或占用保留
  键 → `ValueError`。记录 = `{kind, ts(UTC ISO 毫秒+Z), session_id} + context +
  fields`（fields 覆盖同名 context 键；保留键无从被覆盖因为直接拒绝）。ndarray
  经 `_normalize` **递归** tolist（dict/list/tuple 容器内也处理）。
  `json.dumps(ensure_ascii=False, allow_nan=False)`——**先整体序列化成功、后落
  盘**：NaN/Infinity 抛 `ValueError`、不可序列化对象抛 `TypeError`，全部在写
  之前，文件永远不会出现半行非法 JSON。写后立即 `flush()`。
- `console(msg)`：终端 `print(msg, flush=True)`；与 event 同样要求已 init
  （未 init 抛 RuntimeError 供 terminate 侧捕获）。不写 JSONL（简洁输出与详细
  日志分通道，需要留档由调用方另发 event）。
- `context(**fields)`：`@contextlib.contextmanager`；进入时校验键名（非空 str、
  非保留键）并记录受影响键的旧值（含"原本不存在"哨兵），finally 恢复——同键
  嵌套覆盖、退出恢复前值、外层没有的键退出时删除；异常退出同样恢复。**不要求
  init**（纯内存关联状态，terminate 降级路径也依赖 snapshot）。
- 注入点与辅助：`set_sink(callable|None)`（§3.4"单测可注入内存日志接收器"，见
  DEC-P1-02-C）、`snapshot_context()`（浅拷贝）、`current_session_id()`、
  `current_log_path()`、`close()`（幂等，捕获 OSError 转 stderr 告警；关闭后
  session_id 保留可审计）、`reset_for_tests()`（仅供测试关闭并清空全部模块状态）。

### 2.2 `qingyun/shutdown.py`（新增）

import 面：`__future__/atexit/sys/typing` + `from qingyun import runlog`——**没有
任何通向 qingyun.grabbing/serial 的路径**（AST 白名单测试 + 运行时探针双重钉死）。

- `terminate(status, detail) -> NoReturn`（P1 §3.3 签名逐字一致）：
  1. 幂等：模块级 `_terminated` 标志**先于一切动作**置位；已置位则直接
     `raise SystemExit(1)`，不打印、不记日志、不清理。
  2. `status/detail` 经 `_safe_str` 三级兜底（str→repr→类型名占位），怪异入参
     不能让出口本身抛非 SystemExit。
  3. 终端报告（内置 print，不经 runlog.console——未 init 时 console 会抛，而
     报告必须无条件输出）：`status`、`detail`、`_format_stage()`（runlog 的
     session 与当前 context 快照；未 init 标注"runlog 未初始化"）、现场处置指引
     `_GUIDANCE_LINES`（"不发送任何舵机/串口指令：不回 home、不卸力、不关扭矩、
     不松开夹爪；机械臂冻结在当前位姿（沿用既有保持状态，不代表软件能保证物理
     静止）；现场处置由操作者负责…"）。整段打印包 try/except：stdout 坏了降级
     stderr，仍继续退出。
  4. `runlog.event("terminate", status=…, detail=…, stage=snapshot)`——stage 显式
     冗余字段满足 §7"所处阶段"，context 关联键由 event 自动合并。任何异常
     （未 init RuntimeError / 写失败 OSError / sink 抛错）只 `_warn_stderr` 一条
     告警，**绝不回调 terminate**（无递归）。
  5. `sys.exit(1)`。
- `_atexit_flush()`：**模块导入时 `atexit.register` 恰好一次**（terminate 内不
  注册）；函数体只调 `runlog.close()`（flush+关句柄，无串口写入的资源关闭），
  异常就地 stderr 降级；不引用 terminate、不 sys.exit（AST 测试钉死调用面
  ⊆ {runlog.close, _warn_stderr, print, type}）。
- `reset_for_tests()`：仅清 `_terminated`（钩子注册不撤销——重复注册本身就是
  被禁止的形态，测试要测的是"每次 import 恰好注册一个"）。

  `runlog.close()` 幂等且无副作用外溢，已验证与 469 条既有用例共存无干扰。
  `importlib.reload` 类测试会在解释器退出时遗留额外（幂等）钩子注册，属测试
  自身机制，不影响生产 import 的"恰好一次"（增量断言只约束单次 reload）。
- **sink 语义是"接管"而非"旁路"**：设置 sink 后文件不再增长（`set_sink(None)`
  恢复）。选择理由见 DEC-P1-02-C。P5 若要"文件+内存双份"，在 sink 里自行做
  二路分发即可（sink 收到的就是本来要落盘的逐字节行）。
- **`console` 不落 JSONL**：简洁输出与详细日志分通道；P1-04/P1-05 若要求某句
  终端提示同时留档，需另行 `event`（§7 的事件由各模块自己产行，runlog 不越权
  决定哪些终端消息值得记录）。
- **fsync 不做**：规格只要求"立即 flush"（§3.4），逐事件 `os.fsync` 会把日志
  变成磁盘往返；掉电场景的最后若干行不在本期承诺内。close/atexit 走句柄关闭。
- **单线程假设**：无任何锁；P1 §1 明确本阶段"不另建线程或实时控制循环"，若未来
  引入线程需整体重新设计（届时至少 `_context` 需线程本地化）。
- **`tests/test_module_stubs.py` 不存在**：验证命令组合里显式标注（属 P1-03），
  未因缺文件削弱任何断言。

## 7. 自主决策

- **DEC-P1-02-A（重复 init = 拒绝，非重新初始化）**：P1 §3.4 只给了签名，§4 冷启动
  里 init 恰出现一次且进程活到 terminate；"一个 run 一本日志"才能让 session_id
  当主键用。重新 init 会静默换会话、撕裂关联链，属更危险的默认。故第二次 init 抛
  `RuntimeError`（发生在任何文件系统动作之前），消息自带"测试请
  reset_for_tests"指引。代价：生产装配代码 bug 走两遍 init 会硬失败——这正是想要
  的行为。
- **DEC-P1-02-B（非有限值=明确拒绝并抛，不消毒转换）**：规格允许"拒绝或安全转换"
  二选一。取拒绝：日志里的 NaN 往往是上游真 bug，替换成 null 会把 bug 洗白；
  `allow_nan=False` + "先序列化后落盘"同时保证文件逐行合法，异常由顶层映射
  terminate（其自身的 event 失败另有 stderr 降级，两条路径在测试里分开钉死）。
- **DEC-P1-02-C（注入点=sink 函数接管逐字节 JSON 行）**：候选形态①可替换文件
  路径（不可注入内存）；②event 记 dict 前回调（绕过序列化，NaN 防线对 sink
  失效、与落盘形态可能漂移）；③`set_sink(callable|None)` 接管**序列化后的行**。
  取③：注入点最小、P1-04/P5 拿到与文件逐字节同形的行自行 loads/双路，且"进
  sink 前同样拒 NaN"成为可测语义（有对应用例）。`None` 恢复文件输出。
- **DEC-P1-02-D（session_id = 日志文件主名 `run-<UTC>-<pid>`）**：文件名与日志行
  的会话字段一一对应，事后可直接从目录名反查；备选 uuid 与文件名脱钩、pid+时间戳
  在单机同进程内已唯一。UTC 明确：文件名 `%Y%m%dT%H%M%SZ`，事件 ts ISO 毫秒 + Z。
- **DEC-P1-02-E（kind/ts/session_id 为保留键，fields 与 context 一律禁占）**：否则
  任何 `event("x", session_id=...)` 可伪造会话归属，关联键失去可信度。event 的
  kind 是具名位置参，重复传由 Python 直接 TypeError（同样拒），测试两路都断言。
- **DEC-P1-02-F（幂等标志先于一切动作置位 + 第二次调用零输出）**：打印/序列化中途
  出异常也不给"半记录"重来的机会；重复调用只重申 SystemExit(1)。`test_幂等标志
  先于一切动作设置` 用 flaky print（第 3 行抛 OSError）证明降级后事件仍完整、
  第二次调用仍不重复记录。
- **DEC-P1-02-G（atexit 钩子在 import 时注册一次）**：在 terminate 内注册会让
  "幂等二次调用是否重复注册"变成运行时问题、且钩子引用闭包状态；import 时注册
  使钩子集合恒为 1 个幂等函数，`_ncallbacks` 增量测试钉死"恰好一个/次 import"。
  钩子调用面用 AST 封闭集（runlog.close/_warn_stderr/print/type）防止未来漂入
  设备逻辑。
- **DEC-P1-02-H（终端报告不经 runlog.console + 入参三级 _safe_str 兜底）**：
  console 未 init 会抛，而 terminate 的报告必须先于且独立于日志成败无条件输出；
  §5 会把各种 repr/异常对象直传 status/detail，出口自身绝不允许多一种死法。
  最坏退化 `<unprintable 类名>`，仍 SystemExit(1)。
- **DEC-P1-02-I（未 init：event/console 抛 RuntimeError；context/snapshot 不要求
  init）**：前两者是"日志通道未就绪"，抛出让 terminate 降级；后两者纯内存关联
  状态，terminate 的 `_format_stage` 在未 init 时也要能安全取快照打印"未初始化"。
  close 后 event 抛 RuntimeError("已关闭") 同属通道未就绪族。
- **DEC-P1-02-J（terminate 行 stage 显式冗余字段）**：§7 要求 terminate 行含"所处
  阶段"；context 关联键虽已自动同行，但"阶段"语义应可独立于关联键提取（后续
  plan 可能用嵌套 context 表达阶段名），故同时写 `stage={context 快照}` 一份。
- **DEC-P1-02-K（`reset_for_tests()` 命名与定位）**：仿 `tests/support.py` 的
  "测试专用工具"惯例提供显式命名的公共函数（runlog 关文件+清全部模块态；
  shutdown 只清幂等标志），而不是让测试直接写私有变量——P1-04/P5 大量复用时
  契约稳定、且 grep 可审计"谁动了模块状态"。
- **DEC-P1-02-L（运动零调用采用"运行时探针 + 静态 AST"双保险）**：单靠运行时
  探针无法排除"terminate 在测试没走到的分支里 import 了设备模块"；单靠 AST 无法
  证明 getattr 动态派发。两路合钉：七个设备/串口模块名的 `__getattr__` 记录探针
  （自检后清空）× 五条 terminate 路径 × import/属性/函数名三层 AST 白名单。
  测试替身名单里的原语（10 个）取 P1 §3.3 点名的 4 个 + arm/motor 公开面同族 6 个，
  后续若运动层新增原语命名需同步该列表（已在测试常量处注明）。
