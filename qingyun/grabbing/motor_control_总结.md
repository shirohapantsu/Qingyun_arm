# motor_control.py 总结

> 青云机械臂抓取子系统 · 电机侧（C/3 号）真机驱动，实现 MotorController 冻结契约
> 对应文件：`Qingyun_arm\qingyun\grabbing\motor_control.py`（526 行）
> 依赖：`servo_params.py`（全部真值）、`feetech_bus.py`（帧级收发）、`common_interface.py`（契约）

---

## 一、一句话定位

`motor_control.py` 给上层应用（B 侧）提供**"关节怎么动"的语义层**：把"关节角(deg) + 夹爪百分比"翻译成"舵机刻度(0..4095)"安全下发，把舵机回传的原始字节翻译成"角度/速度/电流"。换算用的"汇率"问 `servo_params.py`，字节搬运交给 `feetech_bus.py`，**自己只做换算、安全、时序**。

在抓取应用里它是唯一的"肌肉"；在 B 侧落地前，它（连同其命令行入口）就是项目**当前唯一能跑起来验收的东西**。

---

## 二、它在上层眼里的五种能力

| 方法 | 上层说 | 它做什么 | 谁在用 |
|---|---|---|---|
| `send_action(5关节角, gripper_pct)` | "去这个姿态，夹爪开 50%" | 软限位钳位 → deg→raw 换算 → 逐舵机非阻塞写 | 抓取/放置动作（B 侧） |
| `get_feedback()` | "现在臂是什么姿态？" | 读 6 关节角度/速度/电流（15B 块读 ×6） | 回传显示、闭环、状态判定 |
| `wait_until_settled(timeout, tol)` | "等它停稳（或超时告诉我）" | 位置差分测速，连续两拍判静止 | 动作完成后确认到位 |
| `emergency_stop()` / `release_freeze()` | "停下！" / "确认安全，恢复" | 后台 30Hz 实测→回写，把臂冻在原地 | 安全链路 |
| `enable_torque(on)` / `diagnose()` | "上电/检查" | 6 舵机力矩开关；逐个 ping+读型号+电压温度自检 | 初始化、排障 |

"舵机当前角度在寄存器 0x38、每刻度 0.08789°"这类**硬件知识**全被收进下层（`feetech_bus` 的 `REG_*` 与 `servo_params` 的因子/模型）——上层永远只跟"关节名、度数、百分比"打交道。

---

## 三、它默默兜住的六件事（真正的价值所在）

1. **单位换算只此一份**：`deg ↔ raw` 用 `ServoJointConfig` 的互逆公式，读回和下发共用同一套标定模型（zero_raw / direction / offset_deg），永远一致。
2. **安全四层闸**：①形状校验（必须是 5 角，错了 raise）→ ②急停闸门（冻结中拒绝新指令）→ ③deg 域软限位钳位（越界默默钳到关节行程，护机械）→ ④raw 域钳位 0..4095（换算错乱也发不出非法刻度，护协议）。安全不靠单点，靠层层设防。
3. **异常跨层带上上下文**：底层的 `FeetechError`（"校验和不符"这类技术语言）被包成 `ServoFeedbackError`——带着"哪个关节、哪个 ID"；错误信息永远能指导排障。
4. **线程安全双锁 + 可中断停止**：总线锁（收发互斥，急停线程永远挤得进来）与状态锁（`_frozen`）分离；冻结循环每拍"实测→回写"动态锁位（抗外力推动漂移）；`Event.wait()` 让冻结线程可被立即唤醒、优雅退出；`daemon` 线程不挡进程退出。
5. **非阻塞动作下发**：`write` 默认不等应答，一次 `send_action`（6 次写）亚毫秒级返回——30Hz 控制节拍(33ms)稳如泰山。
6. **时序与状态原语自洽**：`wait_until_settled` 用位置差分测速（不依赖单位存疑的速度寄存器）、"动得最快的关节"判据、连续两拍滤抖；定时循环一律绝对时间对齐，不漂移。

## 四、它在项目里的位置

```
main.py（总开关：真机 / Mock —— 尚未落地，规划中）
  └─ arm_control.py（B 侧上层：按 MotorController 契约编程 —— 尚未落地，规划中）
        └─ motor_control.py ← 本文件（C 侧：契约的真机实现，已完工）
            ├─ 真值问 servo_params.py（ID/限位/标定模型/换算因子）
            ├─ 形状约定来自 common_interface.py（Protocol + JointFeedback）
            └─ 收发调 feetech_bus.py（只认 ID + 寄存器 + 字节）
                  └─ pyserial → USB2Serial → 6 台 STS3215 总线
```

数据流一句话：**上层要角度(deg) → motor_control 钳位+换算 → feetech_bus 写 raw**；回传方向相反。本文件是"两套单位制"与"人与机器"之间的翻译官兼安全员。

## 五、它刻意不做什么

- **不懂协议**：不拼帧、不算校验和、不知道寄存器布局（那是 `feetech_bus.py`；它只引用 `REG_*` 常量）；
- **不藏真值**：代码里没有魔法数字——ID/量程/因子/超时全部来自 `servo_params.py`，带来源注释、带标定 TODO；
- **不做任务决策**：不懂视觉、不懂抓取流程、不做运动规划（那是 B 侧 `arm_control` 的事）；
- **不自持时钟节拍**：30Hz 绝对时间对齐循环归 B；本文件只在自己的阻塞原语（settled/急停）里短循环；
- **不替代 Mock**：真机实现与 `mock_motor.py`（规划中）同实现一个契约，main.py 一个开关切换。

**为什么能这么干净？** 契约冻结（接口先行）+ 数据逻辑分离（真值集中）+ 单一职责（只做关节语义）。C 侧只要守住契约和真值来源，B 侧怎么写都不影响它——这是多人在同一项目并行开发的根基。

---

## 六、对"抓取应用"最实际的三个收益

1. **30Hz 周期预算富余**：下发亚毫秒 + 整臂反馈约 15ms，33ms 节拍内轻松；将来要提速，优化项也写好了注释（同步读 ≈10ms）。
2. **上层永不碰刻度**：抓取代码只写 `send_action(q5, 50)` 和读 `fb.angles_deg`——不出现任何 4096/0x38/方向符号，低级错误在结构上不可能发生。
3. **安全网自动生效**：软限位钳位、急停冻结都藏在每次调用里，上层无需自己实现任何"防呆"；急停线程利用总线锁的重试间隙，永远能挤进串口发"锁死"指令——**安全功能不被慢速故障拖累**。

> 在应用看来，这个文件 = **"指哪打哪、随时可问、该停就停"的关节伺服**：上层只说关节角和百分比，换算、限位、急停、等待——全是它的事。

## 附 A：命令行手册（真机验收 / 调试）

> 电机侧当前唯一的可运行入口（B 侧未落地）。**执行会让舵机运动/上电，人务必离开机械范围、手放物理急停上。**

### 0) 通用：指定串口（Linux 默认 /dev/ttyACM0）

```bash
# Windows 开发机
set QINGYUN_SERVO_PORT=COM5 && python -m qingyun.grabbing.motor_control
# Linux（香橙派，默认口可不设）
python -m qingyun.grabbing.motor_control
```

### 1) 实时回传显示（默认模式）：30Hz 打印 6 关节 角度/速度/电流

```bash
python -m qingyun.grabbing.motor_control                  # 持续显示
python -m qingyun.grabbing.motor_control --hz 30          # 指定刷新频率
python -m qingyun.grabbing.motor_control --no-torque      # 不使能力矩：手掰关节，
                                                          #   角度实时跟随 → 验证"实测回传"
python -m qingyun.grabbing.motor_control --once 100       # 只读 100 次后退出
```

| 参数 | 作用 |
|---|---|
| `--hz N` | 打印频率 Hz，默认 30 |
| `--no-torque` | 不使能力矩（可手掰验证回传；验证的是"实测"而非"目标回显"） |
| `--once N` | 只读 N 次退出（0 = 持续，默认） |

### 2) 单关节扫掠自检（运动链路验收，会真实运动）

```bash
python -m qingyun.grabbing.motor_control --sweep pan --amp 30 --rate 15 --dev-tol 8
```

命令内部自动按安全顺序执行：`connect → diagnose（6 台在不在）→ 使能力矩 → 打印警告并停 1 秒（撤手时间）→ 往返扫掠 → 打印 ✔ 通过 / ✘ 未通过 → close`。

**它在验证什么**：目标角 → 运动 → 实测回传 三层链路（指令收到没 → 舵机动没动 → 读回准不准）。任何一层断，表现为 `|实测 − 指令| > 容差` → 立即中止并提示排查方向（卡阻？换算方向/零点未标定？力矩未使能？）。

**通过标准**：全程偏差在容差内，且扫完**回到起点**偏差也在容差内。

| 参数 | 作用 |
|---|---|
| `--sweep 关节` | 被测关节：短名 pan/lift/elbow/wrF/wrR/grip 或长名（如 shoulder_pan） |
| `--amp DEG` | 单侧扫掠幅值°，默认 30（会被软限位自动截断） |
| `--rate DEG_S` | 目标角速度 °/s，默认 15（慢而稳） |
| `--dev-tol DEG` | \|实测−指令\| 中止容差°，默认 8 |

注意：`--sweep` 与 `--no-torque` 互斥（扫掠必须有力矩，会真实运动）；若当前姿态贴近限位导致扫掠范围被吃光，命令会直接报错要求减小 `--amp`。

### 3) 快速排障路径

```
舵机不上线  → 先跑 diagnose（全部离线会给出排查清单：供电→接线→端口→波特率→ID 烧录）
读数异常    → --no-torque 手掰看角度是否合理跟随（区分实测/回显、区分换算方向错）
运动不对    → --sweep 单关节往返，看偏差与中止原因（卡阻/方向/零点/力矩）
```
