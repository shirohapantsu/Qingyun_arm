## 2. 修改目标

保留现有“RGB ArUco PnP → 人工录入基座接触点 → SVD 刚体变换”的标定方式，以及已验证正确的 Kabsch/SVD 主公式。重点解决坏输入被接受、误差超标仍保存、单位猜测、数据不可追溯和拟合残差被当作整体验收的问题。

标定主程序独立完成检查，不导入视觉运行模块，不启动深度流或 RKNN，不控制机器人运动。相机检查只作用于本次标定采集会话，不更改视觉模块的设备选择和采集参数。

## 3. 实施顺序

### 第一步：记录基线

1. 记录工作区已有改动，对保护清单内的关键文件保存修改前哈希，不覆盖用户已有改动。
2. 执行现有标定单测，记录当前环境实际结果；不将报告中的其他平台结果充当本机结果。
3. 使用当前可用依赖。若缺少测试依赖，记录缺项，不升级或替换现有运行环境。
4. 保留标定程序主要入口；默认进入正式可视化界面，坐标单位固定 mm，不再询问。终端兼容入口可显式指定其他单位，禁止自动猜测。

完成条件：文件改动允许清单与基线明确，离线测试不打开设备或写正式配置。

### 第二步：优先修复输入与保存

1. 默认 mm，内部统一转为 m；正式页面仅填写黑框边长多少 mm 和各点 X/Y/Z 数值。终端兼容入口可显式 `--unit m`。拒绝 NaN/Inf、数量错误和无法解析的输入，合理范围检查须有明确来源。
2. 默认将候选与记录写入新的会话目录，例如 `calibration_assets/sessions/<session_id>/`，分别保存 `T_base_camera.candidate.json` 和 `session.json`。测试全部写临时目录；指定受保护文件作为输出时明确拒绝。
3. 非有限结果、非法变换或拟合残差超限时返回失败，可保留诊断记录，不能标为合格候选。暂沿用最大 4 mm 作为拟合质量筛选值，并明确它不等于 CAL-040。
4. 候选先写同目录临时文件，校验完整 JSON 后原子替换；已有会话结果不静默覆盖。保存失败返回错误并清理临时文件。
5. 取消、数据不足、求解失败、质量超限和写入失败映射为非零 CLI 退出码。

完成条件：E05 的超限结果不再被当作成功；E07 的小数值毫米输入按显式单位解析，NaN/Inf 被拒绝；成功和失败测试均不改动正式配置。

### 第三步：补齐采集、SVD 与 PnP 检查

1. 检查离线图片可解码，实际帧尺寸必须与读取的 RGB 内参一致。尺寸不匹配时明确报错，不自动缩放内参或改写配置。
2. 标定程序支持显式 RGB 设备参数，记录本次设备和实际成像尺寸；不改其他程序的设备设置。失败或退出时释放本程序打开的相机。
3. 用显式异常代替 assert，检查两组点形状为 `(N,3)`、数量一致、有限值及有效点数；保留当前交互流程至少四个有效对应点的要求。
4. 检查重复点、空间跨度和去中心化点集第二奇异值，拒绝共线/近共线，记录阈值和诊断值。共面非共线仍允许求解，不因第三奇异值为零就拒绝。
5. 检查 R/t 有限、旋转正交、det(R)≈1、齐次末行正确。
6. PnP 检查期望 ID、重复 ID、标记边长、可见像素尺寸、正深度、有限值和重投影误差；保留现有正方形物点顺序。必要时比较 IPPE 候选，歧义明显时要求重新采集。
7. live 可记录多帧角点/PnP 波动；离线单图明确标为单帧。质量阈值在标定参数中显式给出并记录，未实测前不声称毫米级硬件保证。

完成条件：E01/E02 保持正确求解，E03 共线拒绝，E06 尺寸失配拒绝；已知位姿 PnP、畸变/斜视、重复 ID、坏图和非有限值有独立回归测试。

### 第四步：补充记录与独立验证

1. 会话保存原图/标注图、设备/尺寸、内参哈希、标记实测边长、ID/角点/PnP 结果、原始输入、单位、转换后的对应点、拟合残差及候选哈希。
2. 记录接触点/TCP 定义及工具版本，说明录入值必须是基座系接触点坐标。只有法兰 XYZ 而没有姿态和工具转换依据时，拒绝将其当作接触点；本轮不扩展运动学模块。
3. 提供独立验证点记录与误差计算，验证点不参与拟合，覆盖新的位置和实际高度。验证缺失时显示“未独立验证”，不因拟合残差小而自动升级状态。
4. 保留 E04 共同偏差反例：拟合与真值使用同一 TCP 可能共享系统偏差，需记录参考不确定度，并用独立量具/已知尺寸目标交叉检查。
5. 修改标定程序内的说明与输出，明确“拟合残差”和“独立外参验证”，删除“绝对真实”“绝对收敛无 Bug”“拟合即 CAL-040”等承诺。

完成条件：会话数据可复算拟合结果，候选可追溯；明确区分未验证、验证失败和验证通过。任何状态均不自动将候选安装到正式运行配置。

### 第五步：标记生成的必要修正

1. PNG 增加正确 DPI 元数据和 100% 打印说明，明确黑色标记方形边长与卡片外框的区别，保留 100 mm 校验线。
2. 调整覆盖编码区的中心图案，保持触碰点与 PnP 原点一致，并验证检测结果。新图写独立目录；按后续用户要求，旧 40 mm 图纸已删除，改用 80 mm 版本。
3. 优先使用当前已有依赖；需要新增依赖的 PDF 输出不纳入本轮。打印后实测边长和校验线，不能用 DPI 声明替代尺量。

完成条件：临时生成图可检测、中心约定一致、DPI 正确；文件检查与实物打印验收分别记录。

## 6. 实施记录与使用方式

已完成两个标定程序及专项测试修改：显式单位、图像尺寸检查、点集退化检查、PnP 多解/重投影检查、多帧波动记录、接触点定义、独立验证点计算、候选原子创建、失败退出码、PNG DPI 及编码区保护。保留 Kabsch 主公式及候选 schema v1。

实测环境：Python 3.10.12、NumPy 2.2.6、OpenCV 5.0.0、pytest 6.2.5。未安装或升级依赖。修改前既有测试为 7 passed；修改后以下命令为 **63 passed**（60 项标定专项测试，3 项原有视觉测试）：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest tests/test_calibration_math.py tests/test_touch_calibrator.py tests/test_vision_pipeline.py -v -p no:cacheprovider
```

测试包含实际生成图 → ArUco 检测 → PnP → 输入已知接触点 → SVD → 保存候选的完整离线流程；故障与保存流程测试使用临时目录。未连接相机/机械臂执行实测，质量筛选默认值尚不代表现场测量精度。

运行标定（默认 RGB 索引 0，现场须确认对应设备；推荐用 `--rgb-device` 显式提供实际 `/dev/v4l/by-id/...` 路径）：

```bash
python3 qingyun/calibration/touch_calibrator.py
```

默认使用正式浏览器界面，流程见第 8 节；单位默认 mm，接触点默认“闭合夹爪两指尖中心”，均不再询问。可用 `--marker-length-mm 80` 指定界面初始边长，仍需在页面确认实际尺寸。`--tool-version` 和 `--tcp-description` 可显式覆盖记录。原终端流程通过 `--terminal` 启用；`--image` 离线图仍走兼容流程且必须匹配内参尺寸，该流程支持 `s` 跳点、`q` 取消。

默认输出到 `calibration_assets/sessions/<新会话>/`：原始/标注 PNG、`session.json` 和 `T_base_camera.candidate.json`。失败写 `failure.json`，不输出合格候选。单图重复性标为未评估，未提供独立验证时标为 `not_performed`。候选不会自动安装到 `configs/vision/T_base_camera.json`。

  "unit": "mm",
  "reference": "填写独立参考测量方法、工具及 TCP 定义",
  "reference_uncertainty_mm": 0.2,
  "points": [
    {"id": 1, "camera_xyz_m": [-0.10, -0.05, 0.60], "base_xyz": [100, 100, 100]},
    {"id": 2, "camera_xyz_m": [0.10, -0.05, 0.60], "base_xyz": [300, 100, 100]},
    {"id": 3, "camera_xyz_m": [-0.10, 0.05, 0.60], "base_xyz": [100, 200, 100]},
    {"id": 4, "camera_xyz_m": [0.10, 0.05, 0.63], "base_xyz": [300, 200, 130]}

生成新图纸：

```bash

```

## 7. 独立识别预览

补充 `--detect-only`：只观察 RGB 标记识别，不询问单位/TCP、不录入机器人坐标、不调用外参求解、不生成外参候选。仅修改标定主程序及专项测试，共用现有 ArUco 检测参数；未修改视觉运行模块或现有配置。

### 远程电脑查看实时画面

SSH/远程 VS Code 下，`DISPLAY=:0` 的 OpenCV 窗口通常显示在香橙派本地桌面，电脑上看不到。新增浏览器入口解决这个问题：

```bash
python3 qingyun/calibration/touch_calibrator.py --detect-only --browser
```

在 VS Code 的“端口”面板转发 **8765**，电脑浏览器打开转发地址（通常为 `http://127.0.0.1:8765/`）。若使用 SSH，可在电脑端运行 `ssh -N -L 8765:127.0.0.1:8765 orangepi@香橙派IP`。服务只绑定香橙派回环地址；端口冲突时用 `--preview-port` 更换，转发端口同步更换。

画面旁显示当前相机系 XYZ、帧计数、画面更新时间和最近窗口指标。浏览器按钮“保存结果并退出”或终端 Ctrl+C 会保存最后一个完成帧的图像和报告。窗口中途有帧但被 Ctrl+C 中断，不再一律记录为失败。浏览器模式不会调用 OpenCV 桌面窗口；单张离线图则保持展示至退出。

若黑色正方形实测为 80 mm，追加 `--marker-length-m 0.080`。页面会显示当前边长设置；XYZ 为 RGB 光学系，尚未转换为机器人基座系。不能将屏幕显示图案的名义大小当作实测物理尺寸。

标定工具的 RGB 采集补齐项目相机调试脚本已采用的 **MJPG** 请求格式；只影响本工具本次打开的取流会话，不修改视觉程序、驱动或系统配置。设备只读模式枚举确认 1280×720 支持 MJPG 30/15 fps，而 YUYV 为 10/5 fps；不以格式枚举代替实际成功取流验证。

### 静止场景的建议采集门槛

默认按最近约 3 秒统计，窗口左边界保留一帧。相机和标记必须固定；漏检、重复 ID 和 PnP 失败不会从分母里删掉。

| 指标 | 当前默认值 | 含义 |
|---|---|---|
| 观察时长 / 帧数 | ≥3 秒且 ≥30 帧 | 单张图无法通过时间稳定性判断 |
| 每个期望 ID 的检出率、PnP 通过率 | 均 ≥95% | 当前帧也必须有唯一、合格姿态 |
| 最短像素边长 | ≥60 px | 采集余量建议，比原 20 px 的小标记拒绝线更严格 |
| 最大单帧重投影 RMS | ≤1 px | 像素拟合检查，不是毫米误差 |
| 角点抖动 | ≤0.5 px | 各角点相对窗口均值的二维 RMS，取四角最大值 |
| 相机系三维中心波动 | RMS≤2 mm，最大偏离均值≤4 mm | 检查重复性，不是真值误差；也不是峰峰值 |
| 浏览器画面更新时间 | ≤1 秒 | 超时显示 STALE，并禁止沿用旧 READY |

`WARMUP`：时长或帧数不足；`CHECK`：存在未达标项，表格显示具体原因；`READY`：所有期望 ID 通过上述采集质量检查。默认期望 ID 为 1～6；只试一张 1 号标记时，可加 `--expected-ids 1`，否则其余缺失 ID 会阻止全局 READY。门槛可通过 `--preview-*` 参数调整，完整字段见 `--help`。这些数值是本工具初始工程筛选标准，未经现场验证，不是 OpenCV 官方标准，也不承诺实际测量误差。

仅 ID 正确、重投影小、XYZ 稳定仍不能证明实际坐标准确。回归已覆盖“80 mm 标记按 40 mm 求解，重投影近零而 XYZ 缩小一半”的反例。实体边长、内参、接触点/TCP 及外参都可能带来系统偏差；外参仍须独立位置交叉验证。项目整条视觉链 CAL-040 的逐样本三维误差 ≤4 mm 需另做实测，不因 READY 或拟合残差通过而自动成立。[OpenCV PnP 定义](https://docs.opencv.org/4.7.0/d5/d1f/calib3d_solvePnP.html)

## 8. 正式标定：网页采满 10 次自动停止，终端录入 mm 坐标

正式标定继续使用现有可视化 Preview 页面。默认接触点为闭合夹爪两指尖中心，单位固定 mm，不再询问单位或 TCP 备注。电脑端继续转发 8765，运行：

```bash
python3 qingyun/calibration/touch_calibrator.py
```

### 操作流程

1. **点击开始前持续检测**。页面显示实时画面和质量指标，只填写黑色正方形实测边长多少 mm（默认 80）；此阶段不累计正式批次。
2. 机械臂停在 Home，相机和标记固定。点击 **“开始采集 10 次”**，清空开始前的稳定性历史，从新帧重新检查。每次须所有期望 ID 均通过检出率、PnP、尺寸、重投影和稳定性门槛，才计入进度。
3. **恰好收集 10 个合格时间窗口即自动结束检测**，不再采第 11 批，不需要手动“采用最佳观测”。每批结束时间至少相隔一个窗口时长；默认窗口 3 秒，所以通常至少约 30 秒，质量不通过时需要更久。窗口边界可能共享一帧，不称为统计独立实验。
4. 自动选择质量最好的一批，先释放相机，再保存 `selection.json`、`selected_raw.png`、`selected_annotated.png`。页面提示保存完成及转入终端，随后预览服务自动关闭；无需点击停止，网页也不必保持打开。
5. 终端按 ID 逐点询问接触点 **X Y Z（mm）**，支持空格或逗号分隔；错误格式或 NaN/Inf 会要求重新输入当前点。输入 `q` 或 Ctrl+C 可取消，已保存的相机数据保留。此阶段相机和网页服务已关闭，不再要求回 Home 等待画面 READY。
6. 输入完成后立即计算外参；通过拟合检查后保存候选及会话记录。相机和标记在接触过程中仍须保持固定；停止取流后不再自动检查它们是否移动。

### 多次观测如何选择

每批先通过现有采集门槛，再比较各标记的重投影、角点抖动、三维中心 RMS 和最大偏离：分别除以各自门槛，优先选**最差一项归一化误差更小**的批次；平局时优先最低检出/PnP通过率更高者，再比较平均归一化误差。评分越低越好，不称为实际准确率百分比。

相机点采用最佳窗口内各标记合格 PnP 三维中心的**逐轴中位数**，不会被最后一帧替换。`selection.json` 在终端提问前保存全部 10 批比较记录、选定窗口原始观测、质量指标和中位数相机点；配套图像是该窗口末帧。机器人坐标尚未输入，不会按外参拟合残差反向挑批次。

采集期间发现布局移动，会清空旧批次重新计数，防止混用不同布局。需要改尺寸时，点击“清空本轮采集，返回 Preview”再填写边长并开始；开始和重置均丢弃旧尺寸的在途帧。重复点击开始不会重启已在进行的采集；采满后不再接受重置或追加数据。

`--comparison-windows` 现在表示**采满即停止的目标数量**，默认 10，不再表示允许无限比较的最低门槛。正常使用不需传此参数。原 `--detect-only --browser` 继续作为独立识别预览，不进入坐标录入；`--terminal` 保留旧兼容入口。`--marker-length-m` 与 `--marker-length-mm` 仍互斥；正式页面、纯预览、离线和旧终端入口未指定尺寸时均默认 80 mm。

### 保存与验证边界

相机数据写入失败不会进入终端坐标录入，也不会生成候选。坐标录入取消会保存 `cancelled.json`；拟合、独立验证或后续写入失败会保存 `failure.json`。已成功保存的 `selection.json` 和图像不会因取消或计算失败删除。

成功后保存 schema v1 的 `T_base_camera.candidate.json` 和 `session.json`，矩阵平移单位仍为 m，正式配置不自动覆盖。观测质量和多帧中位数不能代替真值测量；拟合残差、独立外参验证与整条视觉链 CAL-040 继续分别报告。
