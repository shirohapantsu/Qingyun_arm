# P3 视觉检测与目标选择技术文档

状态：2026-09-23 第三轮实施规格；D19 已确认采用 OBB 区域深度点测量，不增加分割模型。依赖 P0 公共类型与 P1 契约；本规格可编码，真机几何精度必须经 P4 实测，未通过不得宣布视觉可用于抓取。

## 1. 目标、范围与依赖

实现 `qingyun/grabbing/vision.py` 单体：相机接入、YOLO-OBB 推理、RGB-D→base_link 几何、五项可抓性过滤、确定性排名、ignore/valid_count 语义与逐项审计日志。前置 P0 的 `VisionInterface`/`VisionThresholds` 与 P1 冻结的模块桩（异常类名与签名不变，替换桩体）。

现状输入（D11）：

- **模型已有**：YOLO-OBB 草莓检测模型与数据集（含 ripe/unripe 类别）。本阶段**不含训练/数据集构建**，只做接入；类别名以实际模型输出为准写入配置。
- **相机**：奥比中光 **Astra Pro**。RGB 走 UVC、深度走 SDK，RGB-D 对齐（D2C）与时间戳一致性是本阶段显式接入任务；SDK 分支/固件在目标机实测后锁定，不预设任何 wheel 直接可用。
- OBB 只提供图像采样区域和成熟度；**不把图像框的角度/边长当真实 yaw/尺寸**。无实例分割模型，按 §6 的深度连通区域估计 base 系几何。

非目标：模型训练、目标身份跟踪/永久排除（D03）、多果品切换（D06）、子进程形态（依赖冲突逃生门暂不实现）、蓝莓适配。

## 3. 公开签名（P1 冻结，重述）

```python
class NoTarget(Exception): ...        # ROI 无物体 / 全部候选被过滤 / ignore 跳尽
class VisionHardError(Exception): ... # 相机断开 / 帧读取失败 / 检测管线崩溃 → terminate

def configure(thresholds: VisionThresholds, config_path: Path) -> None
#   main 冷启动段在 init 前调用一次；重复调用或 init 后调用 → VisionHardError（程序错误）

def init() -> None
#   YOLO 权重一次性加载（不懒加载、不放 import 时）；打开相机并验证可采集一帧
#   （replay 模式验证目录非空且首帧可读）；init 阶段故障抛 VisionHardError，
#   不得伪装成 NoTarget

def get_target(ignore: int = 0) -> VisionInterface
#   前置条件：机械臂在 home（plans/运动 RETURN 维持）
#   一次调用 = 一次完整采集-检测管线，无跨调用缓存；本体内部多帧融合不受限
#   返回确定性排名第 ignore+1 名；ignore ≥ valid_count 必为 NoTarget（跳尽）
```

`ignore` 必须为非负 int；负值/非整数是调用方程序错误，抛 VisionHardError（不静默取 0）。

## 4. 配置与标定包

`configs/vision.json`（提交的字段说明模板，D16；`configs/vision.local.json` 为实际运行文件，gitignore）：

```json
{
  "camera": {"type": "orbbec_astra_pro", "depth_mode": "640x480@30",
             "rgb_device": null, "rgb_size": null,
             "max_pair_delta_s": null, "acquire_timeout_s": null},
  "model": {
    "backend": "yolo",
    "path": "vision/yolo_obb_strawberry.pt",
    "detection_floor": 0.05,
    "conf_threshold": 0.5,
    "class_ripe": ["strawberry"],
    "class_unripe": ["strawberry_unripe"]
  },
  "calibration": {
    "intrinsics_path": "vision/camera_intrinsics.json",
    "extrinsic_base_camera_path": "vision/T_base_camera.json"
  },
  "geometry": {"min_points": 32, "inner_scale": 0.8,
               "depth_neighbor_jump_m": null, "footprint_padding_m": null},
  "source": {"mode": "live", "replay_dir": null}
}
```

- 检测适配层以detection_floor保留检出，不在模型调用时按conf_threshold或成熟度类别提前筛掉邻物。候选资格再按conf_threshold筛选；须满足0≤detection_floor≤conf_threshold≤1，二者是视觉参数，不进入公共目标类型。仅能对实际检出的物体计算邻距，不宣称覆盖未检出物体。
- `source.mode = "replay"` 时按 §4.1 manifest 顺序消费；每次 get_target 一组，耗尽后 NoTarget(`replay_exhausted`)。init 只验证不消费首帧。replay 帧序列与成功/失败及连续任务的关系按 P5 §2。
- **相对路径一律相对本配置文件所在目录解析**（D16：上图是 `configs/` 下配置文件的合法示例，`vision/` 为标定包子目录；不得再出现 `configs/vision/...` 的双重嵌套写法）。
- 标定包格式（P4 产出、P3 消费；**加载时严格校验，缺文件/缺键/非法值 → init 抛 VisionHardError**）：
  - `camera_intrinsics.json`：`{"schema_version":1,"rgb":{"width":W,"height":H,"fx":...,"fy":...,"cx":...,"cy":...,"dist":[k1,k2,p1,p2,k3]},"depth":{"width":Wd,"height":Hd,"fx":...,"fy":...,"cx":...,"cy":...,"dist":[k1,k2,p1,p2,k3]},"depth_to_rgb":[[...],[...],[...],[...]],"depth_unit_m":...}`。dist 固定5项 Brown-Conrady 顺序；设备若输出已去畸变深度，填零系数并记录 SDK 设置；不是任意相机模型都可直接套5项。
  - `T_base_camera.json`：`{"schema_version":1,"from_frame":"rgb_optical","to_frame":"base_link","matrix":[[...],[...],[...],[...]]}`。矩阵将 RGB 光学系转换到 base；平移单位 m，不能使用深度相机外参冒充。

JSON 示例中的 null 是未测模板值，不是运行默认。live 要求 rgb_device 为实际设备标识、rgb_size 为两个正整数且与内参匹配；时间参数为有限正数；depth_neighbor_jump_m 为有限正数、footprint_padding_m 为有限非负数。P4 采集验证并回填这些值；replay 使用显式名义值，不假冒实测。min_points 为≥3的整数且非bool、inner_scale 在(0,1]；类别集合非空且互斥，置信度在[0,1]。内参 fx/fy>0，所有数有限，分辨率正整数；旋转矩阵验证正交和det≈1、齐次末行为[0,0,0,1]。未知键拒绝，格式错误按 VisionHardError；不允许自动缩放内参以掩盖分辨率不匹配。

`model.backend` 只允许 yolo/fixture；live 必须 yolo。fixture 仅 replay，model.path=null，不加载任何权重；检出来自帧的 detections.json，后续几何完全共用。yolo 必须权重存在且类别可匹配；检测适配层撤销 letterbox/resize，将 OBB 统一成**原始 RGB 分辨率四角像素**及 class/conf。这是检测器唯一消费格式，不让下游猜角度单位、w/h 或模型预处理。

### 4.1 帧与回放契约

私有相机边界统一为 `Frame(color_u8, depth_raw, rgb_time_s, depth_time_s)`：RGB `(H,W,3)` uint8，深度 `(Hd,Wd)` 原始轴向Z数值，单位由 depth_unit_m 指定；两个时间在同一主机 monotonic 时基。raw 深度不是径向距离；SDK 若提供径向距离，适配层先转换并验证。D2C 软件只执行一次，禁止 SDK 已对齐后再当 raw 深度配准。

replay 目录提交 `manifest.json`：`{"schema_version":1,"frames":[{"id":"0001","color":"0001_color.npy","depth":"0001_depth.npy","rgb_time_s":1.0,"depth_time_s":1.0,"detections":"0001_detections.json"}]}`。路径相对 replay 目录；np.load 禁止 pickle；ID 唯一、时间非递减、形状与标定一致；颜色/深度缺失、格式错误是 HardError，不是 NoTarget。fixture detections 文件为列表，元素形如 `{"class":"strawberry","conf":0.9,"corners_px":[[u0,v0],[u1,v1],[u2,v2],[u3,v3]]}`，四角按周界排序；坏框拒绝而不填默认值。yolo backend 忽略此文件并推理 RGB。

### 4.2 坐标与配准公式

列向量约定 `P_rgb = R_rgb_depth P_depth + t_rgb_depth`，`P_base = R_base_rgb P_rgb + t_base_rgb`。RGB 光学系 X向右、Y向下、Z向前；base 轴与运动一致。原始 RGB **不重映射**，YOLO 在原图上检测；投影时使用 RGB 畸变，反投影需要像素射线时用 undistortPoints，避免同一像素去畸变两次。

每个有效深度像素去深度畸变得归一化射线 `(xn,yn,1)`，以 `Z_depth=raw*depth_unit_m` 构造三维点；转 RGB 后要求 Z_rgb>0，再投影到带畸变 RGB 像素。落点取最近整数像素（.5向上），同格多点保留最小正 Z_rgb（遮挡 z-buffer）；相同Z按深度像素行列序打破平局。保留完整 `xyz_rgb_m[H,W,3]` 及有效掩码，无数据格为NaN、不插值补洞；aligned_depth 只是其中Z分量，不能保存原 Z_depth。测量直接转换保留的三维点，避免重新用整数像素近似反投影。

上述坐标含义依 [OpenCV 相机模型](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)；投影/反投影实现使用同一标定模型，测试参考从独立三维场景生成。

## 5. Astra Pro 接入（显式任务清单）

1. 目标机（香橙派 arm64 + x86 开发机各一遍）验证 SDK 路线：官方 `pyorbbecsdk` 对 Astra 系列的支持以实测为准；不可用则退 OpenNI2/Astra SDK 绑定。选定后锁定版本写入 requirements.txt。
2. RGB走UVC、深度走SDK；按 §4.2 生成 xyz_rgb 网格，不再定义第二套 D2C 公式。
3. live 每次 get_target 开始记录 t0，只接受映射到主机时基后曝光时间≥t0的两帧，差值≤max_pair_delta_s；丢弃旧帧并在 acquire_timeout_s 内配对，超时 HardError。SDK/主机时钟偏移和不确定度需实测纳入配对验证；不能用队列出队时间冒充曝光时间。如果设备无可靠时间戳，适配层必须验证清空队列后新采集帧的上界，不能直接宣称已满足。replay 不与当前墙钟比较，但仍检查两帧时间差和序列顺序。
4. 深度单位按 `depth_unit_m` 换算；无效深度（0/NaN）标记并跳过。
5. 相机抽象成可注入接口（live/replay 同一接口），供测试与 mock 复用。

## 6. get_target 管线（顺序固定）

1. **取帧**：成对获取新 RGB + 对齐深度；配准/时间戳/深度尺度验证失败 → VisionHardError。
2. **检测**：yolo推理或fixture适配，输出class/conf/原RGB四角像素（§4格式），达到detection_floor的全部检出参与测量/邻距。推理崩溃 → VisionHardError。
3. **测量**（对每个检出，包括后续会被过滤的）：
   - 将框内全部有效 xyz_rgb 点变换为 P_base；无有效点记 no_depth；剔除 `z_base ≤ table_z_m + table_flatness_m` 的桌面点，余下为空记 below_table。Z_rgb、z_base、h 始终使用不同变量，不互换。
   - 在框内非桌面有效像素上建立8邻接图，仅当相邻两点的三维距离≤depth_neighbor_jump_m才连边。以框中心同比缩放 inner_scale 的内框作为种子区：只有**一个**点数≥min_points且与内框相交的连通分量时接受；0个记 insufficient_geometry，多个记 ambiguous_geometry。与另一检出框的有效分量共享像素/无法分离时拒绝受影响候选，不自动合并成一颗草莓。
   - 使用被选中的**完整分量**测量长宽，不只取内缩区域。投影其点到 base XY，取凸包和最小面积外接矩形；枚举凸包边方向求解，等面积时按 wrap180 后 yaw、中心x/y的字典序确定，保证点输入顺序无关。长边为 length_m、短边为 width_m；长边方向由 base XY 两端点 atan2 得 yaw 后 wrap180。共线/零面积/非有限点集拒绝 invalid_geometry。
   - position.xy 为该 base XY 外接矩形中心；`z_top` 为所选分量与内框交集点的 base Z 中值（空交集已被拒绝）；`h=z_top-table_z_m`；position.z=`table_z_m+h/2`。这是明确的表面/半高估计模型，不是完整三维重建；必须通过 CAL-040/041，未通过应调整安装/采样或回审算法，不能改变4mm/5°标准掩盖误差。
   - 所得尺寸是可见点集的几何估计，不能证明真实尺寸上界。运行包络的实物包含关系由 D18 样本前提保证；K 以同一算法测得的面积拟合。框角射线投到桌面的结果不得冒充实物长宽。
   - `ripe` = class ∈ class_ripe。
4. **邻距**：对**全体检出物体**（含低置信度、ROI 外、被过滤的；XY 平面）用矩形足迹近似计算，过滤与排名共用一份：

   ```text
   u_ij = (center_j.xy - center_i.xy) / distance_ij
   r_i(u) = (L_i*|dot(long_axis_i,u)| + W_i*|dot(short_axis_i,u)|) / 2
   d_ij = distance_ij - r_i(u_ij) - r_j(u_ij)
   d_i = min(d_ij for j≠i)；单目标 d_i = +∞，日志 isolated=true（不写 JSON Infinity）
   ```

   邻距计算用 `L=length_m+2*footprint_padding_m`、`W=width_m+2*footprint_padding_m` 的占用矩形，返回值和分级仍用原始测量长宽。padding由P4验证集测得的足迹低估与位置误差共同标定。中心重合/重叠按净距不足处理。存在任何无法建立三维几何的检出（含低置信度/no_depth/below_table/ambiguous_geometry），本次其余候选均拒绝 neighbor_unverifiable；不将桌面投影未经验证地称作保守足迹。此时是有效扫描全被过滤，不是设备HardError；日志保留源检出ID，方便辨别保守拒绝导致的任务完成。
5. **过滤**（逐项拒绝原因记日志）：

   | 项 | 规则 | 拒绝码 |
   |---|---|---|
   | 数据有效性 | position 有限、`length_m ≥ width_m > 0`、ripe 为 bool、yaw∈[-90,90) | `invalid_geometry` |
   | 候选类别/置信度 | class属于ripe/unripe映射且conf≥conf_threshold；不满足者仍作为邻物 | `unmapped_class` / `low_confidence` |
   | 位置 | 中心在 `target_bounds_m` 闭区间内 | `out_of_bounds` |
   | 尺寸（D10） | `length_m ≤ envelope[0]` 且 `width_m ≤ envelope[1]`（不设下限、不查高度；实物包络由D18保证） | `oversize` |
   | 方向 | 非过滤项（测量误差走 CAL-041 验收 ≤5°） | — |
   | 头顶净空 | 以候选中心/yaw构造envelope水平足迹，区间 `(z_top, z_top+approach_height_m+envelope[2]]` 中存在非桌面且不属于该候选分量的base点 → 拒绝；自身分量按像素归属排除 | `overhead_blocked` |
   | 邻距 | `d_i ≥ clearance_m` | `too_close` |

   **尺寸过滤的三条边界说明（R06 + 复审 §4 更正）**：
   1. **高度维不过滤，运动不兜底**：按 D18，用户保证本期 demo 所有草莓实物长/宽/高不超过 motion profile 对应 envelope；这是样本前提，不增加逐个量具登记流程。未来样本不满足时必须先回审，不能以运动 COLLISION 作为尺寸检查。
   2. 现有运动膨胀未单列尺寸低估误差，不宣称它吸收任意测量误差。尺寸、足迹padding的验证与 CAL-040 报告一起交付；头顶检查仅检查可见深度点，不证明遮挡后的体积无障碍，单层清场前提仍有效。
   3. 逐轴比较对任意 yaw_offset 都是"投影不超包络投影"的充分条件（复审 §4 对初审 L5 的更正）；P1 预检的 `yaw_offset ∈ {0,90}` 断言只是本期产品限制，修改 yaw_offset 必须回审本节。

6. **排名**：`(-d_i, dist_to_roi_xy_center, x, y, z)`；ROI 中心 = `target_bounds_m` 的 XY 几何中心。禁随机数、时间戳、置信度 tie-break。测试保证同组几何输入、不论检测器输出顺序，排序一致。
7. **返回**：`valid_count = len(ranked)`；`ignore ≥ valid_count` → NoTarget（原因 `skip_exhausted`）；否则返回第 `ignore` 索引目标（六字段构造，position 为 float64 `(3,)` 副本）。
8. **日志**：统一经 runlog.event("vision_scan", ...) 写入，沿用 P1 context 的 task_instance_id/scan_id；每次调用（含NoTarget/HardError）恰好一条扫描结论。含源帧ID/两时间戳/backend、检出数、valid_count、ignore、全部候选几何/拒绝码/选中分量与占用足迹、选中索引或NoTarget原因。不得因抛异常漏记；日志不含非法Infinity。

无检出 → NoTarget（`no_detection`）；全被过滤 → NoTarget（`all_filtered`）。单候选局部缺深度是拒绝不是硬错误；相机离线/整帧深度不可用/推理崩溃是 VisionHardError。

## 7. 测试场景（无相机、无权重亦可跑）

| 编号 | 场景 | 预期 |
|---|---|---|
| P3-T01 | 合成帧：已知内参/外参/桌面/单物体 | position/yaw/length/width 与独立参考一致（数值容差内） |

| P3-T12 | 相机断开、整帧深度无效、推理抛错 | VisionHardError |
| P3-T13 | 尺寸上限边界（length==envelope[0]） | 通过（闭区间）；过小不设下限 |
| P3-T14 | 头顶有遮挡物 | `overhead_blocked` |
| P3-T15 | configure 未调用即 init / 重复 configure / init 后 configure | VisionHardError |
| P3-T16 | replay 模式序列耗尽 | NoTarget(`replay_exhausted`) |
| P3-T17 | import 模块 | 不开设备、不加载权重 |
| P3-T18 | 同帧序列重复运行 | 首版每调用一对帧，不做多帧融合；同输入输出及排序一致 |
| P3-T19 | 独立正向投影：倾斜相机、外参平移、fx≠fy、画面边缘、不同物高 | 恢复base点及已知物体几何；不能把base高度当相机深度或把框投桌面当真尺寸 |
| P3-T20 | 非零RGB/深度畸变、D2C重叠像素与空洞 | 无重复去畸变；保留最近RGB Z；空洞不填伪深度；坐标结果符合独立真值 |
| P3-T21 | 桌面/邻物混入OBB，内外框和多个连通分量 | 桌面被剔除；尺寸使用完整分量；模糊归属拒绝，不把混合点当单目标 |
| P3-T22 | live+fixture、坏内参/外参、分辨率或时间不匹配 | HardError，绝不进入抓取；模板null不能运行live |
| P3-T23 | 两任务连续manifest、init验证与帧耗尽 | init不消耗首帧；两任务均有目标；显式空帧与耗尽原因可区分 |
| P3-T24 | footprint_padding、自身点与外来头顶点 | 邻距按膨胀足迹；自身不误报头顶遮挡，外来点触发拒绝 |

fixture：numpy合成原始深度+RGB，按§4.1格式；OBB由fixture检测器提供，不依赖真权重。纯函数单测可直接注入xyz_rgb网格，端到端几何测试必须覆盖raw深度→D2C全过程，不能只测已经正确对齐的数据。

## 8. 真机验收（P4 执行，此处定判据）

- CAL-040：base 系位置误差用**三维欧氏距离**，判据为**逐样本** ≤ **4mm**（D09：min(5mm, profile bound)）——它们作为运行期误差上界消费，**不验均值**；采样覆盖 ROI 中部/边缘、多朝向、多尺寸；独立验证集不复用拟合数据。
- CAL-041：无向长轴 yaw 误差用**模 180° 最小角差**，判据为**逐样本** ≤ 5°。
- **分母口径（R10）**：验证样本与视觉检出一一对应；未检出/被过滤的样本计入分母并按失败处理，不能只统计 `get_target(0)` 成功返回的样本。
- **近圆样本（L6 + R09）**：圆度剔除阈值由 P4 冻结（本文不指定数值）；近圆样本不参与 CAL-041 的 5° 验收。仅剔除验收**不等于**运行许可——safety 的物体膨胀按 profile 的 5° yaw 上界构造，近圆果的随意 yaw 会使该假设失效；因此**近圆果整体不纳入本期 demo 样本集合**（写入 P5 操作规范的样本准入条件）。
- 混绿果场景：ripe/unripe 混淆矩阵人工验收（可接受比例验收前由用户确认，不虚构通过值）。
- 几何中心"半高模型"的独立验证并入 CAL-040。
- **真值偏差控制（R10）**：TCP 同时用于拟合与真值测量时会共享系统偏差——须记录参考测量的不确定度，并用独立量具/已知尺寸目标交叉验证。
